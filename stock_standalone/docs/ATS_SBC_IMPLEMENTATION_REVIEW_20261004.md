## 必须优先处理的问题

### P1-1：后台 singleShot 回调未回到主线程，两个功能会停在忙碌状态

- 位置：核心源码 `1304`、`11362`、`11905`；三处均从普通 `threading.Thread` 内调用不带接收对象的 `QTimer.singleShot(0, callable)`。
- 当前 PyQt6 环境复现：工作台取数已返回，但 `_is_tick_fetching=True`；全量评估仍 `_is_evaluating=True` 且卡片数为 0，主线程的排队信号对照回调可以正常执行。
- 修复方向：复用已有 `pyqtSignal` 与 `QueuedConnection` 模式，将结果交给主线程槽函数；在成功、失败、取消时释放忙碌状态，并检查请求版本、标的、数据源与关闭状态。
- 验收：真实事件循环验证成功、异常、关闭窗口和切换标的后回包；既有测试没有覆盖新工作台或全量评估的完成回调。

### P1-2：后台取数方法实际包含 QWidget 读写

- 位置：新后台调用点 `11303`、`11825`，实际执行 `_get_stock_realtime_data_for_code` 的 `11069–11138` 等分支。
- 该方法调用复选框 `isChecked()`、SpinBox `value()/setValue()/blockSignals()` 和状态标签 `setText()/show()`；待上市分支的接口替身复现记录到 13 次调用，全部位于后台线程。
- 修复方向：主线程先捕获手动参数、数据源与代码，后台只返回纯数据；控件更新统一进入主线程槽函数，并明确共享策略状态的串行写入边界。
- 验收：已上市、待上市、手动估价三个分支均断言控件线程归属；全量评估不得逐个改写当前工作台的估价框。

### P1-3：数组解包改变日期回退规则，已有“零漂移”反例

- 位置：核心源码 `6735–6746`、`6761–6764`；存在 `date` 列时，只预取该列，空值再回退到索引，遗漏原来的逐行 `datetime` 回退。
- 复现：2400 Bar、`date=""`、`datetime` 含完整日期、索引只含时分；HEAD 方法生成 `buy/sell` 两个信号，当前方法只生成 `buy`，多日数据被归到 `day_0`，T+1 状态无法正常解锁。
- 修复方向：保留原逐行优先级 `date → datetime → index → day_0`，同时在循环前批量完成日期归一化。
- 验收：用 HEAD 方法或固定黄金结果对照不同日期格式、空日期、混合日期及跨日持仓；当前测试只比较新版冷算与新版缓存结果。

### P1-4：Alt 批量切周期后，调度器继续使用旧订阅

- 位置：核心源码 `8073–8102`；直接赋值 `_current_period_mode`，没有走会调用 `subscribe()` 的 `set_period_mode()`。
- 复现：两个窗口由 `1m` 切到 `day` 后，调度器订阅仍为 `1m`；随后投递日 K 批次，两窗口刷新计数均不增加，因为 `_deliver_batch:4680` 的周期检查拒收结果。
- 修复方向：统一经 `set_period_mode(..., reload=False)` 更新订阅；焦点窗口立即加载，其他窗口由集中调度器补齐，避免每窗独立启动取数线程。
- 验收：批量切换后检查所有订阅周期，验证后续至少两轮实时批次能继续更新；这是现有批量切周期路径的遗留问题。

### P1-5：只读 K 线缓存接口不存在，振幅补拉没有消费路径

- 位置：核心源码 `988`、`1298–1307`；`TDXRealtimeFetcher` 未实现 `get_cached_kline_bars`，两个 `hasattr` 分支始终得到 `None`。
- 振幅工作线程的 `d_df` 既未注入画布，也未传给主线程；即使单独修复回调，重新调用仍无法读取缓存，且没有补拉防重入或失败冷却。
- 修复方向：提供校验周期、所需 Bar 数量及 TTL 的只读缓存接口，或直接将返回数据作为信号载荷；按标的和周期合并请求，失败后短暂冷却。
- 验收：缓存已预热时不得再发请求；冷补拉完成后振幅必须显示；连续刷新与失败重试不能堆积线程。

### P1-6：工作台首开、切换与 IPC 刷新仍存在主线程网络调用

- 位置：核心源码 `10311`、`10596`、`10726`、`11206–11216`；这些路径仍同步执行 `_load_mock_or_live_data()`。
- 已上市标的的 TDX 分支会执行 `fetch_stock_snapshot()`、`fetch_intraday_bars()`；后台化仅覆盖 3 秒定时入口，不能支持“工作台主线程零网络阻塞”的结论。
- 修复方向：首开、换代码、换数据源、IPC 更新与定时刷新统一走合并后的异步入口，主线程仅装载结果。
- 验收：给快照与分钟数据接口注入延迟，分别验证上述入口的事件循环可响应；关闭时还应检查共享 fetcher 的 `disconnect()` 等待连接锁问题。

## 原方案对账与实施顺序

| 方案项 | 审核判定 |
| --- | --- |
| SBC 内发行价只读复用 | 核心文件的同步 `fetch_ipo_calendar()` 已移除；不能表述为全代码库零外部请求 |
| 2400 Bar 数组取值与热缓存 | 已落地且正常样本有提速；日期兼容回归、黄金验证及冷算 SLA 尚未闭环 |
| 时序哈希、K 线极值、标签布局缓存 | 已落地；失效规则不完整；`date+HH:MM` 反查 `751–757` 仍线性扫描，不能笼统声称全路径 O(1) |
| 成交量复用 | 单帧双调用已合并，常驻列预计算链路未接通 |
| 悬停节流、重复 wheelEvent | 严格时间窗与单一 wheelEvent 已落地；末次移动补画缺失；默认缩放仍右侧吸附，未完整兑现方案的光标锚点描述 |
| 常规窗口平铺 | 有本进程窗口时跳过 EnumWindows；仍调用 topLevelWidgets 并保留 Win32 兜底，15ms 未重新实测 |
| 工作台、全量评估后台化 | 后台入口已添加，但主线程回调与控件线程归属不正确；首开/切换路径仍同步取数 |
| 静态图层、图元复用、工作台统一调度、Alt 集中队列、引擎状态复用 | 尚未完整实施 |

- 第一批：先处理 P1-1/2/3/4，恢复完成回调、控件线程安全、跨日信号与切周期后持续更新；同时把相关回归测试纳入 Git。
- 第二批：处理 P1-5/6 与缓存失效、成交量前置，接通只读数据复用和统一异步入口。
- 第三批：实施静态图层与增量策略计算，复测首帧、切周期、鼠标、20 窗口、CPU 与内存指标，以 P50/P95 分别报告冷算和热命中。
- 验收前更新设计文档的 Drafting Only 状态，修正“100% 闭环”“绝对零漂移”及未实测的性能结论。
