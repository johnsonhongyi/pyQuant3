## 三、P0 阻断问题

### P0-1　悬空垫口径错误，导致「结构预判验证」形态 0 命中（正例全漏）

**位置**：`ats/fusion/anomaly.py:126`

```python
if (is_structure_prejudged or close_over_vwap10) and min_vwap_cushion >= 0.20:
```

`min_vwap_cushion` 由 `enrich.py:182-191` / `replay.py:860-869` 计算，口径是**自开盘 t≥1 起、截至当前时刻的累计最小值**：

```python
cushions = [(lows[k] - vwap[k]) / vwap[k] * 100 for k in range(1, n)]
min_vwap_cushion = min(cushions)
```

该值**单调不增**，一旦任一分钟的最低价触碰到分时均线，即永久为负，当日再也无法恢复。

**实测（全市场 5,576 只，2026-10-29）**：

| 指标 | 数值 |
|---|---|
| 全天最低价从不跌破 VWAP+0.20% | **16 只（0.3%）** |
| 全天最低价从不跌破 VWAP+0.25% | 11 只（0.2%） |
| 曾触及/跌破 VWAP | **99.3%** |
| min_cushion 分位 | p50 = −1.58%，p90 = −0.65%，max = +4.53% |

**回放插桩（72,732 次 detect_patterns 调用）**：

```
cushion >= 0.20           : 0 次
cushion >= 0.20 且结构成立 : 0 次
```

**点名正例被漏杀的直接证据**：

| 标的 | 昨日结构 | 今日 | 累计悬空垫 | 结构验证 |
|---|---|---|---|---|
| 钧达股份 002865 | is_struct=1, touch=7, disp=1.26% | **+11.43%** | t=1 时 **+0.000%** → 永久失效 | **未触发** |
| 中国卫星 600118 | is_struct=1, touch=10, disp=0.77% | **+10.17%** | t=1 +1.214%，t=3 起跌破 | **未触发** |

结论：操盘手要求的「今天盘中没感知到」，根因不是数据缺失，而是**该形态在开盘前 3 分钟内一次性判定且不可恢复**——任何一次正常回踩（哪怕 −0.03%）即永久取消当日资格。设计文档原文 `min_{t≥1}(low_t − vwap_t)/vwap_t ≥ 0.20%` 就是此口径，**属于设计本身与实战不符**，非单纯实现偏差。

### P0-2　`tier_floor` 后置，越过 `tier_cap` / `age_cap` / L4 门槛（风控被反噬 + 追高）

**位置**：`ats/fusion/engine.py:891-895`

```python
if tier_cap is not None: tier = max(0, min(tier, int(tier_cap)))   # 891
if tier_floor is not None: tier = max(tier, int(tier_floor))       # 895  ← 最后执行
```

`tier_floor` 在 `tier_cap`、`age_cap`、L4 门槛、`structure_clarity` 封顶**全部之后**才用 `max()` 抬高，等于把上述所有风控降档作废。

**实测（复现脚本）**：

| 场景 | 结果 | 期望 |
|---|---|---|
| 结构验证 + `tier_cap=1` | **tier = 4** | ≤ 1 |
| 结构验证 + 启动已 60 分钟（`age_cap=1`） | **tier = 4** | ≤ 1 |
| 无结构 + `tier_cap=1` | tier = 0 | 0（正常） |

这直接违反引擎自身设计约束（`engine.py` 文件头）：**「级别是时间的函数。同一个票，启动 40 分钟后即使分再高也不能给 L4。」** 实测 60 分钟仍给 L4，即**结构性追高**。

受影响调用方：`engine.py:1026`（`tier_cap=3` 限 L4 数量）、`engine.py:1029`（超预算逐级降档）、`replay.py:977`（无形态封顶 L2）。

### P0-3　`rebalance()` 对结构票死循环，会锁死融合链路

**位置**：`ats/fusion/engine.py:1028-1029`

```python
while ev is not None and decision.tier > 0 and total + decision.size_pct > budget:
    decision = self.engine.evaluate(ev, rg, now=base.ts, tier_cap=decision.tier - 1)
```

`evaluate` 内部 `has_box10_hover`（L834-841）会从 `event.extra["patterns"]` 读出「结构预判验证」并强制 `tier_floor = 4`；叠加 P0-2 的后置 `max()`，`tier_cap` 永远压不下去 → `decision.tier` 恒为 4 → **while 永不退出**。

**实测**：4 只结构票（各 30%，合计 120% > `max_total_pct=85%`），`rebalance()` 8 秒超时被 kill，退出码 124。

**影响面**：`shadow.py:577-582` 在 `with self._lock:` 内调用 `rebalance()`。一旦当日出现 ≥3 只结构验证票，**融合流水线在持锁状态下挂死，梯度监视器整体冻结**。当前 `max_l4=2`、`max_total_pct=85.0`，L4 单票 30%，3 只即触发。

> 讽刺之处：结构信号越成功（命中越多），越必然触发此死循环。

## 四、P1 设计偏差

### P1-4　结构池过宽，`vwap10_touch_count` 门禁无区分度
- `structure_pool(2026-10-29)` = **1,206 只（23.1%）**；`box10_pool` = 2,395 只（46.0%）。
- `touch_count` 分布：≥2 占 **5,227/5,228（≈100%）**（分布峰值在 9 次）。因 `vwap10` 是 10 日均价，10 日内最高价天然多次高于它，`touch_count >= 2` 几乎不筛任何票。
- `wash_quality`（要求 `touch_count >= 3`）= 1,203 只，与 `is_structure_prejudged` 的 1,206 只几乎重合 → **「洗盘充分」这一档位没有独立信息量**。
- 正向价值仍在：结构池涨停率 1.64% vs 池外 0.70%（**lift 2.34×**），均值 −2.12% vs −2.79%。**池子有 edge，问题在触发端（P0-1）把池子废掉了。**

### P1-5　结构验证用 `close_over_vwap10` 兜底，L4 保底面放大到 37%
`anomaly.py:126` 用 `is_structure_prejudged or close_over_vwap10`，而 `close_over_vwap10` 全市场 **1,944 只（37.2%）**。设计文档支柱 2 明确要求「当命中 `is_structure_prejudged` 的股票」。实际把「昨收在 10 日均线上方」这一极宽条件也纳入 `_floor=4`（`shadow.py:542-545`），与「结构机会」定义不符。

### P1-6　UI「🎯 只看结构机会」在真实数据上返回空表
用 `_row_is_structure_opportunity` 跑 1,368 条真实回放记录：**通过 0 条（0.0%）**，L4 中 0/255、L2+ 中 0/724。原因：回放记录既不写 `struct` 字典，也不写顶层 `is_structure_prejudged/prev_strong_vwap`，`chain` 字段在 records 中不存在。操盘手勾选后看到的是**空表**。

### P1-7　涨停/高开 >9.6% 的结构票不在发现漏斗内
`stock_live_strategy.py:3169`（全市场漏斗）`mask = (pct >= 2.2) & (pct <= 9.6)`；`:3212`（结构池快车道）`2.0 <= p_pct <= 9.6`。
设计文档的核心正例正是「今日早盘放量高开，**直接 10% 涨停**」。pct=10.0 > 9.6 → **结构池快车道直接跳过**，只有该票恰好落在静态监控池时才会被评估。

### P1-8　测试用例污染实盘落盘目录
`tests/test_structure_opportunity_model.py:342/381` 构造 `FusionShadow(config={"sample_interval_s":0.0,"session_gate":False})` 且 `force=True`，未覆盖 `log_dir`，而默认目录是生产路径 `logs/fusion_shadow`（`shadow.py:135`）。今日 55 条假记录即由此产生，会直接污染操盘手当晚的复盘视图。

## 六、梯度有效性实测（这是最需要正视的一条）

按入场价计算的前瞻表现（1,368 条记录，2026-10-29）：

| 档位 | 条数 | MFE 中位 | MAE 中位 | 收盘相对入场 | 该票全天涨幅中位 |
|---|---|---|---|---|---|
| L1 | 644 | +1.12% | −1.22% | −0.12% | +1.23% |
| L2 | 420 | +1.10% | −2.08% | −1.38% | −1.21% |
| L3 | 49 | +1.20% | −2.62% | −1.41% | +0.40% |
| **L4** | 255 | **+0.62%** | −1.37% | **−1.00%** | **+4.72%** |

**档位与前瞻收益完全无单调关系**，L4 的 MFE 反而最低。

L4 尤其值得警惕：该票全天涨幅中位 +4.72%，但**从 L4 入场点起算 MFE 仅 +0.62%、收盘 −1.00%** —— 说明 L4 是在涨幅已走完才给的，正是操盘手反复强调要杜绝的「追涨」。这与 P0-2（老化封顶被越过）互为印证。

补充：L4 共 255 条但仅涉及 **13 只票**，且「可下单 0 笔」；`lead_label` 全池无一条「总龙头」，说明 L4 主要来自 `tier_floor` 保底而非分数分档（全池 RAR p98=58.8 < L4 阈值 68.0）。
