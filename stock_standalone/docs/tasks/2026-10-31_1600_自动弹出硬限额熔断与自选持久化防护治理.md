# 自动弹出硬限额熔断与自选持久化防护治理

## 背景与问题陈述
1. **自动弹出远超限制、无数窗口被弹出刷屏**：
   - 用户反馈并附图显示：桌面上弹出了几十上百个监控小窗口（厦门信达、招商轮船、再升科技等层层叠叠）；
   - 后台报错：`ERROR: 自动创建监控窗口失败: not enough values to unpack (expected 4, got 3)`；
2. **关闭就会被持久化污染自选股列表**：
   - 用户指出：“关闭就会被持久化”，导致这些被刷出来的无数临时窗口在关闭时被写入 `monitor_list.json`，污染了用户的常驻自选股；
   - 强烈要求：“严格修复弹出功能,绝对不能超过限额”。

---

## 根因深度剖析
1. **致命死循环根因（解包异常击穿配额计数）**：
   - 在 `place_new_window` 中执行了 `left, top, right, bottom = monitors[0]`；由于 `monitors[0]` 带有 3 个字典键（'monitor', 'work', 'flags'），Python 解包抛出 `ValueError: not enough values to unpack (expected 4, got 3)`；
   - 此时 `create_monitor_window` 内部在抛出异常前已经执行了 `monitor_win = tk.Toplevel(root)`（窗口已经被创建在桌面上）；
   - 异常抛出后中断了后续代码，导致 `pop_win._auto_popup = True` 与 `alive_auto_popups.append(code_str)` **从来没有执行**；
   - 结果当前存活计数一直为 0，配额判断 `len(alive_auto_popups) >= auto_popup_limit` 永远不成立；
   - 外层对候选池里的几百只股票疯狂重复创建窗口，导致数十上百个窗口全部弹到屏幕上！
2. **自选股持久化缺乏盘中临时标记过滤**：
   - `save_monitor_list()` 遍历了 `monitor_windows.values()` 中的全部窗口，并未在盘中排除带有 `_auto_popup` 临时标记的窗口，导致关闭任何窗口触发写盘时，把这些临时弹窗也写进了 `monitor_list.json`。

---

## 解决方案与改动实施
1. **全场景 4 元组原生解包兼容类 `MonitorItem(tuple)`**：
   - 继承自原生 4 元组 `(left, top, right, bottom)`，无论是 `left, top, right, bottom = monitors[0]` 还是 `l, t, r, b = MONITORS[idx]` 均能 100% 正常解包，彻底根绝 `expected 4, got 3` 异常；
   - 同时支持 `.work` 属性和 `.get("work")` 字典方法，多屏工作区精准适配；
   - 在 `place_new_window` 和 `create_monitor_window` 增加 `try...except` 容错，坐标异常自动回退默认 geometry，绝不中断主流程；
2. **三重硬熔断与严格限额保护机制**：
   - **进入前硬熔断**：`remaining_slots = auto_popup_limit - len(alive_auto_popups)`，只要当前已达限额（10只），直接 `return` 退出，绝不执行候选扫描；
   - **预扣配额防击穿**：命中后在调用创建前直接预扣配额 `created_count += 1` 和 `alive_auto_popups.append(code_str)`；达到配额立刻 `break`；
   - **孤儿窗口异常自愈**：创建窗口时若发生任何异常，捕获后立即调用 `win.destroy()` 强制销毁半成品残留窗口，绝不留在桌面上；
3. **盘中持久化过滤保护**：
   - 在 `save_monitor_list()` 中加入盘中保护：在 15:00 收盘前，所有带有 `_auto_popup` 标记的临时窗口**绝对不被写入 `monitor_list.json`**；
   - 保护用户的常驻自选股列表纯净，关闭临时弹窗绝不产生自选股持久化污染。
