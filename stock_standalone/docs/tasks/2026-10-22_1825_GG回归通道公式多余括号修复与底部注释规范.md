# 2026-10-22 18:25 【GG回归通道公式多余括号修复与底部注释规范】

## 1. 问题背景与根因定位
用户在使用通达信指标公式系统编译“GG回归通道”时遭遇语法报错：
```
当前公式 : GG回归通道 (画线指标公式)  
错误句 :  
详细信息 : 多余的 "}" ! 
错误起始位置 : 11105 ; 长度: 9 没有严格按规则调整好
```

### 根因剖析
1. **通达信不支持嵌套注释**：
   通达信公式编译器的词法分析器遵循最简单字符扫描规则（ASCII `0x7D` 触发注释立即结束），不支持嵌套 `{ { } }`。
2. **说明文字内含有符号触发提前闭合**：
   在注释说明文字中写入了字符：
   `如后续需重新启用，只需删除首尾的 { 与 } 即可。`
   其中的字符 `}` 导致外部的注释块在说明文字处提前关闭，导致后续的 `========================================================}` 成为孤立、无前导匹配的 `}`，触发 `多余的 "}" ! 长度: 9` 报错。
3. **被注释块内部残留大括号**：
   原斐波那契段落中第 1 行包含 `{N1:=0;}`，若外部整体包裹大括号也会引发提早截断。

## 2. 改进措施（严格遵从 KISS / DRY / 健壮性原则）
1. **彻底清理注释说明文字**：注释标题中的说明文字严禁包含任何 `{` 或 `}` 字符；
2. **剔除内部残留注释**：将内部的 `{N1:=0;}` 彻底剥离，确保被注释段落纯净；
3. **整体单一大括号安全包裹**：
   将斐波那契黄金分割（高1/低1/H1-H5 7个黄色价格数字及绿线、红线水平彩线）完整移至公式最底部，并使用干净利落的单个 `{ ... }` 块进行整体注释；
4. **语法静态验证**：通过自动化测试脚本对通达信词法深度进行验证，保证全文本大括号深度始终在 0 与 1 之间切换，无任何未闭合或多余闭合。
