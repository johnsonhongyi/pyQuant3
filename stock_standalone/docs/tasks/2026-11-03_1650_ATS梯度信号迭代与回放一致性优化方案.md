## 0. 核心结论与三大结构性缺口

信号「粗糙、无法迭代、高档位命中率不单调」的根因不在单一阈值，而在**三处结构性缺口**与**四处代码级机制缺陷**：

1. **评分与档位脱钩，三层档位语义未分离**：
   - 生产实测 452 条 L4 中 442 条（98%）由结构或总龙头保底抬升，L4 的 RAR 中位数（63.2）反而低于 L3（65.4）；
   - [`engine.py`](../../ats/fusion/engine.py) 先调 `tier_of(rar)` 定档，随后才对 `rar` 做 `+12 / +8 / -6 / -12` 加减分，导致 `decision.rar != decision.axes.rar`，展示与排序用的 RAR 并非定档依据；
   - `FusionBus` 在 `shadow.observe()` 首次评估后无参二次重评（未传 `cuts` 与 `tier_floor`），且 `_force_downgrade()` 降档时仅修改 `tier` 和 `size_pct`，未同步重算 `entry / stop / targets / invalidate`。
2. **缺乏严谨的结果评估闭环与状态可复现快照**：
   - [`SignalEvent.to_dict()`](../../ats/fusion/contract.py) 遗漏 `vwap_10d`、`ma5/10/20`、`ret5d/10d/20d`、`rs5`、`extra` 等关键输入，[`StructureSnapshot.to_dict()`](../../ats/fusion/structure_timeline.py) 遗漏 `high_water`、`status_since` 与 `streak`，且 `cuts` 未落盘，事后无法精确复算；
   - [`trade_sim.py`](../../ats/fusion/trade_sim.py) 存在「整根 bar 最高价低于 `price_lo` 时捏造 `price_lo` 穿价成交」、「将全天不同时段先后触发止盈与止损误判为同日双触止损」、「次日开盘 VWAP 破位退出优先级排在盘中止盈止损之后」三处失真；
   - [`calibrate.py`](../../ats/fusion/calibrate.py) 在测试日上挑选排序口径，且未按标签数据实际可用时刻（`label_available_ts`）截断训练集。
3. **回放与实盘双轨分叉（DRY 失效）**：
   - `FusionShadow.observe` 与 `DayReplay.run` 各自维护约 600 行编排逻辑（形态识别、结构时间轴、板块时钟、总龙头、保底、评分），在温度公式、涨停阈值、量比语义（实盘日内累计量比 vs 回放单根 3m bar 量比）、龙头定义、板块共振、`cuts`、形态保底开关等十余处口径不一致。
4. **直接拉低命中率与污染状态机的代码级机制缺陷**：
   - **未验证行情穿透门禁**：[`adapter.py`](../../ats/fusion/adapter.py) 在缺失原始行情时间戳与 `trade_date` 时默认回填 `freshness_s=0.0` 与系统当前日期，且 [`shadow.py`](../../ats/fusion/shadow.py) 在执行数据过期/跨日否决前就更新了 `StructureTimeline` 与 `SectorClock`；
   - **缺失前高短路当突破 & `WAITING` 状态穿透**：[`structure_timeline.py`](../../ats/fusion/structure_timeline.py) 与 [`anomaly.py`](../../ats/fusion/anomaly.py) 中 `hi_pre1 <= 0` 或 `hi_10d <= 0` 时条件短路为 `True`，且 `WAITING` 状态可穿透生成 `PATTERN_BOX10_VWAP_HOVER`；
   - **结构保底越级豁免温度上限与共振门槛**：[`engine.py`](../../ats/fusion/engine.py) 中 `temp_cap = max(temp_cap, 4)` 将 `COLD_WEAK`（L3）、`ICE_COLD`（L2）、`OVERHEATED`（L2）及 `COOLING_EBB` 下的龙头（L1）直接抬至 L4，并豁免了 L4 的板块共振门槛。

## 2. 冻结的核心数据与业务契约（闭环定稿）

### 2.1 三层档位命名与向后兼容契约

| 字段名 | 定义与计算阶段 | 兼容与出口规则 |
| :--- | :--- | :--- |
| `score_tier` | 纯调整后风险分 `adj_rar` 经过当次 `cuts` 映射得到的分数档位（不含任何保底与封顶） | 新增只读字段，随 `FusionDecision` 与日志落盘 |
| `signal_tier` | 在 `score_tier` 基础上应用 `tier_floor` 保底，再经单票风控上限（`temp_cap`、`age_cap`、水下封顶、滞后封顶、清晰度封顶、结构失守/剔除降档）收敛后的**单票最终信号档位** | 新增只读字段；`engine.evaluate()` 刚返回时，`decision.tier == decision.signal_tier`，配套 `signal_size_pct` |
| `portfolio_tier` | 经 `FusionBus.rebalance()` 组合配额（`max_l4`、`max_total_pct`）收敛后的**组合授权档位** | 新增只读字段（未经过组合重平衡前等于 `signal_tier`）；经 `FusionBus.rebalance()` 写回后，`bus` 各出口（`top()`、`portfolio()`、`get()`、`actionable`）的 `decision.tier == decision.portfolio_tier` |

- **分数链路显式保存**：修复 `decision.rar` 与 `axes.rar` 不一致问题；显式记录 `base_rar`（五轴加权减惩罚基础分）、`adj_rar`（定档前完成跨日、排头兵、结构/总龙头先验加减分后的最终定档分，且 `decision.rar == decision.adj_rar == axes.rar`）、`floor_tier`、`floor_source`、`cap_tier`、`cap_reasons`。
- **组合降档同步重算**：当 `FusionBus.rebalance()` 或 `_force_downgrade()` 将档位降为 `nt` 时，**必须基于 `nt` 同步重算 `size_pct`、`entry`（`_entry_plan(nt, ev)`）、`stop`（`_stop_plan(nt, ev)`）、`targets` 与 `invalidate`**（当 `nt == 0` 时清空执行计划），严禁留下高档位旧计划。

### 2.2 前置数据卫生门禁（Data Hygiene Gate）与状态机保护

1. **时间戳与交易日来源验真**：
   - 在 `adapter.build_event()` 中记录 `extra["ts_source"]`（`quote_server_ts` / `snap_ts` / `replay_bar` / `unverified`）与 `extra["trade_date_source"]`（`quote_trade_date` / `replay_bar` / `unverified`）；
   - 当实盘输入缺失原始行情时间戳时，禁止默认赋 `freshness_s = 0.0`，必须标记 `freshness_unverified = True`（`freshness_s = float("inf")`）；缺失原始交易日时标记 `trade_date_unverified = True`，禁止把系统时钟回填值当作已验证的今日新鲜行情。
2. **状态更新前拦截**：
   - 在 `DecisionKernel` 入口（调用 `LaunchTracker`、`StructureTimeline`、`SectorClock`、`_prime_leader_by_sector`、`MarketRegimeTracker` **之前**）前置校验数据卫生：
     - `price > 0`、`vwap > 0` 且核心数值有限（非 `NaN/Inf`）；
     - `"pct" not in missing`；
     - 非 `freshness_unverified` 且 `freshness_s <= stale_seconds`；
     - 非 `trade_date_unverified` 且 `trade_date == expected_day`。
   - 凡未通过前置数据卫生门禁的事件，直接返回 `L0 (Hard Veto)`，**绝对禁止修改任何内部有状态组件**。
3. **双状态机职责边界**：
   - 全天结构确认以 `StructureTimeline.status == STATUS_CONFIRMED` 为唯一权威状态；
   - [`launch_signal.py`](../../ats/fusion/launch_signal.py) 仅作为早盘（`09:30~11:30`）A/B 型启动的独立增强证据，不作为午后或全天升档的必要条件。

### 2.3 Hard Veto、可选特征缺失降级与持仓状态隔离

1. **开仓硬否决（Hard Veto $\rightarrow$ `signal_tier = 0`）**：仅限**必需基础行情无效/未验证**（`price/vwap <= 0`、`pct` 缺失、`freshness` 超限或未验证、`trade_date` 跨日或未验证、停牌、成交额低于硬底线）及明确定义的开仓风控红线；此安全底线永不纳入软化范围。
2. **可选评分特征缺失（Soft Degradation）**：`taker_buy_ratio`、`bid_pressure`、`slope_score`、`intent_score`、`structure_clarity`、`rs5` 等可选派生特征缺失时，**严格保持既有 `missing` 剔除归一 + `coverage` 扣减 + `provisional` 标记契约**，绝不一刀切打成 L0。
3. **持仓与执行受阻状态隔离**：已建仓标的受 A 股 T+1 锁仓或一字跌停/停牌限制无法卖出，属于**持仓执行状态（`HOLDING_T1_LOCKED` / `HOLDING_LIMIT_DOWN_LOCKED`）**，必须保留持仓记录与止损预警，不得混同于开仓评分的 L0。

### 2.4 双层复算（L1a / L1b）与日志完整性契约

1. **L1a 单条无状态确定性复算（Stateless Single-Record Replay）**：
   - **输入**：落盘记录中保存未截断 float 精度的完整 `SignalEvent`（补齐 `to_dict/from_dict` 全字段）+ 进入 `engine.evaluate` 时的已求值状态快照（含 `StructureSnapshot` 全字段含 `high_water / status_since / streak`、`SectorClock` 输出、`launch_ts`、`vwap_slope_5m_pct`、`MarketRegime`、`cuts`、`tier_floor`、`config_fingerprint`）；
   - **验收范围**：同版本同配置下，单条重算的 `score_tier`、`signal_tier`、`signal_size_pct`、`entry`、`stop`、`targets`、`invalidate` **100% 精确相等**，`base_rar` 与 `adj_rar` 浮点误差 $\le 10^{-6}$。
2. **L1b 有状态序列与组合回放（Stateful Sequence & Portfolio Replay）**：
   - **节流不改行为原则**：在 `shadow.observe()` 中，**所有有效事件 100% 正常走完 `DecisionKernel` 计算与内部状态更新**；“L0 抽样”仅控制最终写盘步骤，且**凡引起任何内部状态（含结构状态、`high_water`、滚动窗口、计数器、龙头占位、温度阶段、组合配额）变化的事件 100% 强制写盘**；
   - **时序与检查点**：每条记录携带进程内严格递增 `seq_no`（消除同 `ts` 多来源排序歧义）与 `session_id`；进程启动/重启、每 15 分钟及正常关闭时写入包含 `FusionBus` 持仓上下文的完整 `STATE_CHECKPOINT` / `EOF_CHECKPOINT`；
   - **完整性检测**：记录 `dropped_write_count` 与 `max_records_truncated`；若回放检测到 `seq_no` 断号、写盘失败、达到日上限截断或缺失尾部 `EOF_CHECKPOINT`，显式标记 `log_incomplete = True`（或 `sequence_broken = True`）；
   - **验收范围**：在完整日志段上重放事件序列 + `FusionBus.rebalance()`，`portfolio_tier`、组合裁剪后的 `size_pct` 及组合降档后的执行计划 **100% 精确一致**。

### 2.5 撮合模型、T+1 退出时序、成本换算与评估统计契约

1. **成本与净收益精确换算公式**：
   - `0.15%` 固定定义为**整笔交易往返总成本（Round-Trip Total Cost = 15 bps）**：
     $$\text{net\_return\_pct} = \text{gross\_return\_pct} - 0.15\%$$
   - **净目标与净止损换算**：基准“净止盈 $+3.00\%$”对应毛涨幅 **$+3.15\%$**（$\text{target\_price} = \text{fill\_price} \times 1.0315$）；基准“净止损 $-2.00\%$”对应毛跌幅 **$-1.85\%$**（$\text{stop\_price} = \text{fill\_price} \times 0.9815$）。统一基准线与分档目标线均按此换算。
2. **入场撮合双轨模型与主周期隔离**：
   - 主周期指定为 **1m bar**，缺失时回退 **3m bar**，评估报表按 `1m` 与 `3m` **分表独立报告**，禁止混并；
   - **轨道 A（可执行限价买单，主口径）**：固定为上限 `price_hi` 的限价买单（`price_lo` 仅作回踩深度诊断，绝不用于下限抬价）。信号在 `signal_ts` 触发后，订单自严格满足 `bar_start_ts > signal_ts` 的**下一根 bar** 起生效；在 `expire_min` 窗口内，首根满足 `volume > 0`、非停牌、非一字涨停（`not (low == high and pct >= limit_up_pct)`）且 `low <= price_hi` 的 bar，按 `fill_price = min(price_hi, open)` 成交；
   - **轨道 B（研究代理价，辅助口径）**：信号后下一根可交易 bar 的 `open` 价。
3. **A 股 T+1 锁仓与后续逐 bar 退出严格优先级**：
   - **买入当日（T+0）**：受 T+1 制度约束不可卖出，仅记录日内 `day0_mae_pct`、`mfe_pct` 及收盘是否跌破分时均线 `close_below_vwap`（需校验当日最后一根 bar 时间 $\ge 14:57$）；
   - **T+1 及后续交易日（T+1, T+2, ...）逐根分钟 bar 统一检查顺序**：
     1. **待执行退出指令优先（Pending Exit Recovery）**：若前序 bar 已触发退出（如 `close_below_vwap`、止损、止盈、到期）但因一字跌停或停牌受阻（处于 `pending_exit` 状态），则无需重新检验原价格阈值，在**首个允许卖出的 bar**（`volume > 0` 且未封死跌停）立即执行退出（开盘未封死按 `open`，盘中开板按跌停价/开板价保守成交）；
     2. **当根 bar 开盘跳空检查（`bar.open`）**：首根 bar 若存在 `close_below_vwap`，或任意 bar 满足 `bar.open <= stop_price`（跳空破止损）或 `bar.open >= target_price`（跳空达止盈），立即激活退出；若该 bar 开盘未封死跌停则按 `bar.open` 成交，否则转入 `pending_exit`；
     3. **当根 bar 盘中高低点检查（`bar.low / bar.high`）**：若 `bar.low <= stop_price` 且 `bar.high >= target_price`（同根 bar 内双触），按保守规则以 `stop_price` 止损退出；若单触止损或止盈，按对应价格退出（若触及跌停锁死无法卖出则转入 `pending_exit`）；
     4. **持有期满收盘退出**：在到期日（基准 `hold_days=1` 即 T+1）最后一根 bar，**必须先验证日内数据完整性（最后一根 bar 时间 $\ge 14:57$）**；若完整则按 `close` 触发到期退出（跌停锁死则转入 `pending_exit` 顺延至后续可卖日）；若当日仅有残缺半日数据（如 `< 14:57`），严禁将残缺末根 `close` 当作收盘价结案，必须标记为 `IMMATURE_OPEN`（`status_reason="INCOMPLETE_INTRADAY_BARS"`）。
4. **标签实际可用时间（`label_available_ts`）与防泄漏截断**：
   - 区分 `label_end_ts`（业务事件/窗口结束时刻）与 `label_available_ts`（**计算该标签所需的最后一根 bar 闭合且数据落盘可读的时刻**，$\max(\text{required\_bar\_close\_ts}) + \text{ingestion\_lag\_s}$）；
   - 历史归档缺少真实落盘延迟时，取所需最后一根 bar 的闭合时刻（收盘/跨日指标取对应日 `15:05:00`）并标记 `availability_mode="bar_close_conservative"`；
   - 在任意决策/训练截止时刻 $t_{\text{cutoff}}$，仅允许使用满足 `label_available_ts < t_{\text{cutoff}}` 的样本；盘中资金配额模拟严格按信号时间戳流式顺序（Chronological Order）结合当时可用预算录取，剔除全天事后排序选 TopN 与 `focus_codes` 强塞逻辑。
5. **五类互斥分母状态与可计算的期望收益公式**：
   - 每个信号唯一归入五类顶层状态之一：`FILLED_MATURE`、`UNFILLED_EXPIRED`、`UNFILLED_LIMIT_LOCKED`、`IMMATURE_OPEN`、`DATA_INVALID`，并附带细粒度 `status_reason`（`ZERO_VOLUME`、`SUSPENDED`、`INCOMPLETE_INTRADAY_BARS`、`MISSING_NEXT_DAY_BARS`、`T1_LIMIT_DOWN_LOCKED`、`UNVERIFIED_TIME`）；
   - **主分组口径**：唯一主分组固定为**「每只票每日首次达到可行动门槛（L2+）时当刻的确定档位」**（分别按 `signal_tier` 与 `portfolio_tier` 输出 L2 vs L3 vs L4 互斥对照表）；“每日最高档位（Peak Tier）”仅作盘后诊断；
   - **已终结有效信号净期望收益（Resolved-Signal Net Expectancy）**：
     定义有效且已终结集合 $S_{\text{resolved}} = \text{FILLED\_MATURE} \cup \text{UNFILLED\_EXPIRED} \cup \text{UNFILLED\_LIMIT\_LOCKED}$，未成交已终结样本实现净收益计为 $0.0\%$：
     $$\mathbb{E}_{\text{resolved}}[R_{\text{net}}] = \frac{\sum_{i \in \text{FILLED\_MATURE}} r_i^{\text{net}}}{|S_{\text{resolved}}|} = \text{FillRate}_{\text{resolved}} \times \mathbb{E}[R_{\text{net}} \mid \text{FILLED\_MATURE}]$$
   - `IMMATURE_OPEN` 与 `DATA_INVALID` 独立披露数量与占比（`immature_rate`、`invalid_rate`）；凡 `immature_rate > 0` 的批次标记为 `BATCH_PENDING`，不进入已封账训练集。

### P3：达到统计准入门槛后的信号结构优化

## 4. 强制验收标准与上线回滚护栏（冻结条款）

| 门禁类别 | 冻结验收指标与触发条件 |
| :--- | :--- |
| **L1a / L1b 确定性门禁** | 同版本同配置高精度快照下，L1a 单票（`score_tier / signal_tier / signal_size_pct / entry / stop / targets`）与 L1b 组合（`portfolio_tier / size_pct` 及降档计划）一致率 **100%**，`rar` 误差 $\le 10^{-6}$；通过「重启检查点恢复、同 `ts` 按 `(ts, seq_no)` 合并、断号/缺尾检测、旧签名兼容」4 项专项单测。 |
| **样本外（OOS）上线通过标准** | 在满足准入门槛（$\ge 15$ 日、$\ge 3$ 温度阶段、每档 $\ge 50$ 笔且总计 $\ge 200$ 笔成熟样本）的 Walk-Forward 验证中：<br>1. 点估计单调：$\hat{\mu}_{\text{L4}} \ge \hat{\mu}_{\text{L3}} \ge \hat{\mu}_{\text{L2}}$（同时满足 `FILLED_MATURE` 条件净收益与 $\mathbb{E}_{\text{resolved}}[R_{\text{net}}]$）；<br>2. Day-Block Bootstrap（1000 次按日重采样）下，$\text{L4} - \text{L2}$ 净收益差值的 **90% 置信区间下界 $> 0$**，且新参数相对基线的净期望收益差值 **90% 置信区间下界 $\ge -0.10\%$**。 |
| **生产影子自动回滚门禁** | 所有策略参数变更通过配置开关（Feature Flag）与新旧双影子对照上线；若出现 **L1a 复算一致率 $< 100\%$**，或 **连续 3 个完整交易日高档位（L4/L3）净期望收益倒挂且低于基线版本超过 $0.50\%$**，立即触发告警并一键回滚至基线配置。 |
