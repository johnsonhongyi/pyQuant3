# 修复融合梯度监视器拖动崩溃(0x8001010d)与非交易日白板问题

## 1. 现象与根因诊断

### 现象
- 用户在非交易时段（2026-11-01 21:43 周日晚间）打开【🧬 融合梯度监视器】，界面呈现空表格，仅有一行说明文字（用户感知“没有任何效果”）。
- 用户使用鼠标拖拽移动窗口或在表头上拖动调整列宽时，程序直接闪退并抛出致命异常：
  `Windows fatal exception: code 0x8001010d` (主线程崩溃退出)。

### 深度根因对比（对比 DailyLimitUpDialog、DragonLeaderMonitor 等无异常窗口）
1. **全局 QApplication 事件过滤器污染（致命）**：
   - 只有 `FusionLadderDialog` 在 `__init__` 中执行了 `app.installEventFilter(self._tooltip_filter)`，向全局唯一的 `QApplication` 安装了过滤器；
   - 在 Windows 原生拖拽（无论是拖动窗口的 `WM_ENTERSIZEMOVE` 模态循环，还是拖动表头列宽）期间，线程处于 Windows 严格的 **Input-Synchronous Call** 状态；
   - 此时 `_tooltip_filter` 捕获到鼠标事件并调用 `_tip_card.hide()`。`_TipCard` 拥有独立的 OS 顶层 HWND（`Qt.WindowType.ToolTip | FramelessWindowHint`），在输入同步循环中调用其 Win32 `ShowWindow(SW_HIDE)` 跨 HWND 发送同步消息，违反 Windows COM 规则，直接抛出 `0x8001010D` (`RPC_E_CANTCALLOUT_ININPUTSYNCCALL`)！
2. **表头 HeaderToolTip 拖拽冲突**：
   - 全项目仅 `FusionLadderDialog` 给每个表格表头挂载了自定义 `HeaderToolTip`，内含 450ms 延迟弹窗；
   - 用户拖拽微调列宽停顿超过 450ms 时，定时器在拖拽中强行 `_show_pending()` 弹出并置顶 `_TipCard`，破坏了 Windows 鼠标 Capture 并引发 COM 冲突。
3. **moveEvent 极高频状态持久化**：
   - 在拖拽移动的每一像素都调用 `self._save_window_states(is_open=True)`，与 Windows 模态移动循环争抢 CPU 并造成大量对象分配。
4. **空数据占位行启用合并单元格排序**：
   - 在 `not rows` 分支中，设置了整行 `setSpan` 占位后却启用了 `setSortingEnabled(True)`，用户拖拽/点击表头极易触发视图越界。
5. **“没有任何效果”的根因**：
   - 周日或休市期间打开时，`_render_live` 写死了 `load_live_rows(day, allow_fallback=False)`，彻底禁用了向最近有效交易日回退，导致全表直接返回空列表；
   - `_init_days` 在休市时未优先选中有实际数据的有效交易日。

---

## 2. 核心实施改动

1. **拔除全局事件过滤器，收敛至本窗口体系**：
   - 移除 `app.installEventFilter(self._tooltip_filter)`，改为 `self.installEventFilter(self._tooltip_filter)`；
   - `UnifiedToolTipFilter.eventFilter` 增加前置短路：当鼠标左键处于按下状态（拖动中）时立即返回 `False`，且非本窗口 QWidget 绝不拦截；
   - `_hide_card` 在拖拽期间绝不强行调用 `_tip_card.hide()`。
2. **表头 HeaderToolTip 增加拖拽静默守卫**：
   - 在 `MouseMove` 和 `ToolTip` 事件中，若检测到 `QApplication.mouseButtons() & Qt.MouseButton.LeftButton`，立即停止定时器并静默隐藏，严禁在拖动列宽过程中弹出置顶窗口；
   - `_show_pending` 增加左键按压安全防守，杜绝在输入同步循环中调用 `_show`。
3. **moveEvent 彻底轻量化**：
   - 移除拖拽移动过程中每像素调用的 `_save_window_states(is_open=True)`，只保留 `snap_timer.start(400)`；
   - 严格对齐 `DailyLimitUpDialog` 规范，仅在拖拽完全停止后（`_detect_and_snap` 未贴边分支）或窗口关闭时持久化一次。
4. **占位说明行禁用排序**：
   - 在 `not rows` 占位行渲染时，严格保持 `tbl.setSortingEnabled(False)`，消除合并单元格排序崩溃隐患。
5. **非交易时段平滑回退，彻底解决“没有任何效果”**：
   - `_render_live` 中：盘中交易时段保持查看实时流，非交易时段（夜间/周末/盘前）无记录时自动启用 `allow_fallback=True`，平滑回退展示最近有效交易日数据；
   - 状态栏显式友好标注：`“状态：... ｜ ⚠ 今日暂无记录，展示 2026-10-30 数据”`；
   - `_init_days` 下拉框默认优选含有实际影子日志的有效交易日。
