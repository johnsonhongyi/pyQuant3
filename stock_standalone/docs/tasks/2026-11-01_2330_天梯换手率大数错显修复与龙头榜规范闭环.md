# 2026-11-01 23:30 天梯换手率大数错显修复与龙头榜规范闭环

## 任务背景与问题现象
- **现象**：在【每日涨停分析与强势股天梯 (Limit-Up & Multi-Day Momentum)】看板中，“换手%”一列错显为 `911678...`、`822522...`、`368020...` 等带省略号的超大数字；而在【Top 3 强势板块龙头突击跟单榜 (Hot Alpha Leaderboard)】中，同只股票（如万邦医药 301520）换手率显示为正常的 `43.54%`。
- **环境条件**：夜间非交易时段（或盘前/冷启动）、兜底数据回退时 100% 暴露；白天盘中有 TDX 五档分笔时会被流通股本重算值覆盖。

## 根本原因排查
1. **字段契约错配**：
   在 A 股新浪/东财及系统核心宽表规范中，字段 `turnover` 的含义是**成交金额 (元/万元)**（如万邦医药成交额 8.22 亿、中远海控 36.8 亿）；而换手率（百分比）对应字段为 `turnover_rate` / `hsl` / `turnoverratio` / `ratio`。
2. **天梯引擎映射错误与量比污染**：
   `ats/limit_up_engine.py` 在初始化记录时，误写了 `"turnover_rate": _safe_float(row.get('turnover', ...))`，直接把几亿成交额赋值给换手率；且误将换手率 `ratio` 作为量比 `vol_ratio` 的备用值。
3. **龙头榜正确原因**：
   `ats/hot_sector_engine.py` 严格规避了 `turnover`，明确注释并实现从 `('turnover_rate', 'hsl', 'turnover_ratio', 'ratio')` 提取，并设置了 `(0.0, 100.0]` 安全守卫。

## 修复实施细节
1. **标准提取器封装 (`extract_turnover_rate` & `extract_vol_ratio`)** (`ats/limit_up_engine.py`)：
   - 换手率按优先级遍历 `('turnover_rate', 'hsl', 'turnoverratio', 'turnover_ratio', 'ratio')`，坚决排除 `turnover`（成交额）；
   - 过滤 `NaN` 并严格限制在 `(0.0, 100.0]` 合法区间内，异常大数安全归零；
   - 量比严格提取 `('vol_ratio', 'volume_ratio', 'vr')`，杜绝将换手率 `ratio` 当量比。
2. **强势股天梯看板 UI 闭环** (`ats/ui/daily_limit_up_dialog.py`)：
   - 排序子键 `_make_column_subkey` 与表格渲染 `_render_table_rows` 统一复用标准提取逻辑；
   - 呈现规范：有效换手显示百分比（如 `43.54%`），无效或 0 换手安全显示 `"--"`。
3. **分时策略引擎同步对齐** (`ats/intraday_strategy_engine.py`)：
   - 分时快照与动态规则表达式提取换手率时同步对齐龙头榜标准。
