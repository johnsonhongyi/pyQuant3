# 2026-10-22 22:10 【ATS主窗口多日基准涨跌幅切换（1D/2D强/3D强至9D）纯视图层优化落地闭环】

## 1. 任务背景与核心痛点
- **用户发现与业务诉求**：
  在早盘盘前初始化因外部未完成而残留使用前天（T-2）收盘价时，用户意外发现：以 T-2（或更早）收盘价计算的涨幅能够极其敏锐、直接地观察出“2日强”（双日连板主升）梯队和连续突破标的；
  因此用户提出优化诉求：在 ATS 主窗口提供基准日选择选项，允许切换使用 `df_all` 中依据 `cct.compute_lastdays`（默认为 9）预留的 `lastp1d`（昨收）、`lastp2d`（前收）、`lastp3d` ... `lastp9d` 来计算并展示主窗口的涨跌幅。
- **全局强约束（Red Line）**：
  **“只是为了ats的主窗口的额所有tab的便于查看,不能变动底层其他的信号数据”**！
  严格保持底层策略引擎、信号账本（`SignalLedger`）、风控、T+1 计算和交易执行读取未被篡改的真实 1D 行情，实现 UI 纯视图层（View）与底层数据模型/信号决策的彻底解耦。

## 2. 核心架构设计与工程落地

### 2.1 高性能多日涨跌幅纯数值计算（`ats/ui/styles.py`）
- 新增 `compute_base_day_percent(row, base_day=1, current_price=None) -> float`：
  - `base_day <= 1` 时：优先返回行情行内既有 `dff` / `percent`，或 `(close - lastp1d)/lastp1d * 100.0`；
  - `base_day > 1` 时：从行内提取 `lastp{base_day}d`，计算 `round((p - lastp) / lastp * 100.0, 2)`；
  - 缺失或非法值时：平滑回退至当日真实涨跌幅，0 外部 I/O 阻塞，耗时 < 1 微秒，绝不上抛异常。

### 2.2 多 Tab 表头标签动态对齐与基准感知
- **重点关注面板**（`ats/ui/favorite_panel.py`）：
  - 扩展 `get_ats_table_headers(extra_cols, base_day=1)`：当 `base_day > 1` 时自适应生成 `DFF({base_day}D)`；
  - 增加 `FavoritePanel.set_pct_base_day(base_day)`，切换时就地更新表头标签并保留用户列宽；
- **大级别 MA20d 回调跟踪器**（`ats/ui/swing_table.py`）：
  - 接入 `set_pct_base_day(base_day)`，表头与 `favorite_panel` 严格对齐；
- **资金主线与龙头中枢**（`ats/capital_dragon_engine.py` & `ats/ui/capital_dragon_panel.py`）：
  - `get_dragon_table_headers(extra_cols, base_day=1)` 支持 `涨幅%` 自适应为 `涨幅%({base_day}D)`；
  - `CapitalDragonPanel` 增加 `self.pct_base_day` 与 `set_pct_base_day()`，渲染第 5 列（`涨幅%`）时若 `pct_base_day > 1` 自动通过 `compute_base_day_percent` 动态计算多日累计涨幅，并同步更新单元格 `raw_val`，保证数值升降序与高亮彻底对齐。

### 2.3 主窗口工具栏控制与数据管线闭环（`ats/ui/main_window.py`）
- **工具栏下拉选择与持久化**：
  - 工具栏增加 `self.combo_pct_base` 下拉框（选项根据 `cct.compute_lastdays` 自动生成 `1D(昨收)`、`2D(2日强)`、`3D(3日强)` 直至 `9D`）；
  - 启动时自动从 `window_config.json` 恢复 `ats_pct_base_day`（默认 1D），切换时异步持久化；
- **视图生成与底层信号隔离**：
  - `LedgerUpdateWorker` 构造函数接收 `pct_base_day`；
  - `LedgerUpdateWorker.run()` 中，`_ledger_update_service.update_snapshot` 传入的仍为原始 1D `pct`，而构建 UI `swing_rows` 时第 9 列填入计算后的 `display_dff`；
  - `refresh_realtime_ui` 中左侧三级池 `universe_widget` 显示的 `pct` 同样同步计算多日累计涨幅。

## 4. 架构设计原则总结
- **KISS (简单至上)**：无新库、无复杂中间件，仅复用已有 `df_all` 中的 `lastpNd` 字段，以极简纯函数在渲染前计算；
- **YAGNI (精益求精)**：只针对主窗口查看需求扩展，不修改底层撮合和信号管线；
- **SOLID (单一职责 & 开放封闭)**：展示层变化仅作用于视图组件，底层业务领域对象对视图修改封闭；
- **DRY (杜绝重复)**：统一收敛在 `compute_base_day_percent` 单一事实来源（SSOT），多 Tab 与左侧树统一复用。
