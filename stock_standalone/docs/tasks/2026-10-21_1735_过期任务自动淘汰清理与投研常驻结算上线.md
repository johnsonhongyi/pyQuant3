# 2026-10-21 17:35 自动AI投研过期任务自动淘汰清理与常驻一键结算功能部署上线

## 1. 任务背景与核心诉求

- **用户反馈痛点**：
  1. 页面没有看到之前添加的【结算并恢复】入口（因原条件为仅在状态包含 `unsettled` 时呈现，而后台自愈对账秒级恢复后按钮自动隐去，用户不易察觉与主动对账）；
  2. 桌面桥执行完毕回传后，Web 历史任务卡片中存在大量历史堆积的过期任务（`expired`），任务持续增加，界面卡顿刷屏；
  3. 明确要求：“**过期的任务需要可以自动清理,数据持续增加的需要有全自动清理功能**”。

---

## 2. 根因剖析与方案设计

### 2.1 数据库与任务状态膨胀分析
- 系统原逻辑中，无论是自动认领租约超时（600s）被标为 `expired` 的任务，还是手动取消的任务，均持久保存在 `automatic_research_jobs` 表中；
- 每次扫描或循环未对历史终态任务做滑动窗口淘汰，导致任务总数膨胀（线上达 103 条以上），前端渲染列表时被历史 `expired` 任务刷屏；
- 同时在 `automatic_research_runs` 表中累积了过多无用明细。

### 2.2 优雅滑动窗口与全自动数据瘦身设计
遵循 **KISS / YAGNI / DRY** 原则，不引入沉重外置定时任务，直接在 Go 后端与 Python 策略引擎的主循环与对账事务生命周期中内嵌轻量级原子级自动清理：
1. **过期/取消任务淘汰（Keep Top 3）**：
   - 保留最近 3 条 `expired` 或 `cancelled` 任务作为审计与排查凭据；
   - 超过 3 条的历史过期任务自动原子剔除（`DELETE FROM automatic_research_jobs WHERE status IN ('expired', 'cancelled') AND id NOT IN (SELECT id ... LIMIT 3)`）。
2. **已完成任务滑动窗口（7 天）**：
   - 自动清理 7 天前已完成的陈旧任务（`completed`），释放数据库存储空间。
3. **Token 用量明细记录滑动窗口（30 天）**：
   - 自动清理 30 天前陈旧的 `automatic_research_runs` 账本明细，保留近一个月历史统计分析能力。
4. **事务并发安全（SQLite 互锁防范）**：
   - 抽象 `dbExecer` 接口统一承载 `*sql.DB` 与 `*sql.Tx`，消除在已开启的写事务内调用直接 `db.Exec` 引发的 SQLite 30秒嵌套锁死风险。

### 2.3 UX 交互全面升级
1. **【结算并恢复】常驻呈现**：
   - 投研看板摘要区顶部操作栏（红圈位置）改为**常驻展示**，有未结算时呈现高亮琥珀色警示，正常时呈现标准对账恢复按钮，随时支持用户主动触发；
   - 抽屉面板设置中亦常驻提供该功能。
2. **“分析任务与回传”头部快捷操作与列表防抖**：
   - 卡片头部新增 **【清理过期记录】** 快捷按钮；
   - 前端在展示未决/过期任务时做限制，同一视图下最多渲染 3 条最近过期任务，彻底消除 10+ 条历史过期记录刷屏。
