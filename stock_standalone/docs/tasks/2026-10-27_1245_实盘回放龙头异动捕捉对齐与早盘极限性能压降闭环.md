# 2026-10-27 12:45 实盘回放龙头异动捕捉对齐与早盘极限性能压降闭环

## 一、背景与早盘卡顿根因穿透

### 1.1 早盘全系统严重卡顿四大根因
1. **`stock_live_strategy.py` 融合层抢占 TDX 网络连接**：
   - 昨日引入的 `_fusion_refresh_depth` 每 15 秒调用 `TDXRealtimeFetcher.fetch_batch_stock_snapshots`（内部还对每只股票循环调用 `get_finance_info` TCP 请求，且未返回 `bid_pressure`）；
   - 更致命的是，`_fusion_intraday_bars` 在 30 个并发工作线程中回退调用 `TDXRealtimeFetcher.fetch_intraday_bars(code)`，每轮多达 24 个线程排队争抢 `TDXRealtimeFetcher._conn_lock` 拉取 240 根分时 K 线，阻塞策略主循环长达数秒，并饿死 ATS `NextDayWatchProcess` 行情拉取。
2. **`ats/tdx_realtime_fetcher.py` 60 秒僵尸代码雪崩与逐票串行补拉**：
   - `_get_security_quotes_safe` 中 `_unlisted_or_dormant_codes` 采用固定 `cooldown_sec = 60.0`，且对批次漏回代码 `missing_in_chunk` 执行 `for c_m in missing_in_chunk: self.api.get_security_quotes([(mkt, c_m)])` 逐只串行 TCP 请求（单批最多 40 次串行 TCP 往返，耗时 1.5~3.5 秒）。
3. **`FusionLadderDialog` Qt UI 主线程阻塞 I/O**：
   - `_init_days()` 在 UI 主线程直接实例化 `DayReplay()`，触发 `load_minute_cache()` 反序列化 21MB 的 `minute_kline_cache.pkl`（实测阻塞 UI 主线程 **643.7ms**）；
   - `_auto_refresh_live()` 每 2 秒在文件未变化时仍调用 `_maybe_ensure_data()` -> `load_live_rows()`，在 UI 主线程反复读取并解析 5,000 行 `.jsonl`。
4. **`FusionShadow` 30 线程并发锁缺失与 HDF5 无锁读取**：
   - `FusionShadow.observe()` 被 30 个工作线程并发调用，但 `_last_sample`、`_rar_samples`、`bus`、`current_regime`（访问 SQLite `market_pulse_db`）未加锁；
   - `ats/fusion/premarket.py`、`sector.py`、`context.py` 中 `pd.read_hdf` 未接入 `_HDF_GLOBAL_LOCK`。

### 1.2 实盘梯度未能如回放捕捉龙头异动标的的核心断层
1. **五档买压与外盘占比断层**：实盘 `df_all_data` 内存已含新浪五档 `b1_v..b5_v`、`a1_v..a5_v` 及内外盘，但 `depth_fields` 未读取，导致承接轴长期缺失。
2. **龙头身份 (`is_leader`) 与板块共振 (`sector_resonance`) 断层**：回放按全市场 `pct >= p99` 或前三强势板块第一股设置 `is_leader=True` 并计算 `sector_resonance`；实盘从未注入这两个字段，导致龙头环境加分与一票否决豁免失效。
3. **异动形态 (`detect_patterns`)、板块时钟 (`SectorClock`) 与形态保底 (`tier_floor`) 断层**：回放识别「一阳穿三线 / 突破10日VWAP / 逆势带头 / 潜伏转突破 / 两阳加速」及「排头兵 / 夺旗」并賦予 `tier_floor=2/3`；实盘 `FusionShadow.observe()` 完全未调用。
4. **潜伏转突破 (`latent_break`) 先手时钟重置断层**：早盘微涨触发 `LaunchTracker` 后，午后放量突破因 `age_min > 70` 被 `age_coef = 0.0` 封杀为 L0。
5. **候选池漏斗断层**：实盘仅评估静态监控池 `fetch_list`，未对全市场 `df_all_data` 新冒头的异动先锋做轻量漏斗扫描。

## 二、核心修复与极限性能对齐实现

### 2.1 零网络开销盘口/分时派生与全市场龙头先锋漏斗
- **[`ats/fusion/enrich.py`](../../ats/fusion/enrich.py)**：
  - `depth_fields(snapshot, row=None)`：直接从内存行 `b1_v..b5_v` / `a1_v..a5_v`（或 `bid_vol1..5` / `ask_vol1..5`）计算五档买压 `bid_pressure`，从 `b_vol/s_vol` 计算 `taker_buy_ratio`，**0 网络请求**；
  - `intraday_fields(bars, ...)`：新增滚动 10 根阳线量能占比 `taker_buy_ratio` 代理（对齐 `DayReplay._slice_day`）与横盘蓄势放量突破 `latent_break` 识别。
- **[`stock_live_strategy.py`](../../stock_live_strategy.py)**：
  - **彻底切除融合层所有 TDX 网络调用**：删除 `_fusion_intraday_bars` 中的 `TDXRealtimeFetcher.fetch_intraday_bars` 回退，严格只读 `all_klines` 与同进程 `MinuteKlineCache`；
  - **全市场内存横截面引擎 `_fusion_update_cross_section(df_all_data, now)`**：每 10 秒在内存向量化计算全市场 `p99` 领涨龙头、前三强板块第一股龙头、板块共振分 `sector_resonance`、板块启动时钟 `SectorClock` 与真实市场涨跌宽度（耗时 `< 2.5ms`）；
  - **全市场新晋龙头先锋漏斗 `_fusion_scan_market_vanguards`**：每 15 秒从 `df_all_data` 内存筛选 Top 20 新晋领涨/强共振放量先锋送入 `FusionShadow.observe(source="vanguard_funnel")`，耗时 `< 2ms`，杜绝监控池外大龙漏网。

### 2.2 `FusionShadow` 与 `adapter` 全面对齐回放引擎
- **[`ats/fusion/adapter.py`](../../ats/fusion/adapter.py)**：
  - `LaunchTracker.note(..., reset_wave=False)` 与 `reset_code` 支持二波潜伏突破重置先手时钟；
  - `build_event` 补齐 `ma5/ma10/ma20/vwap_10d/ret5d/ret10d/ret20d/limit_up_streak` 及 `depth_fields` 零开销回退。
- **[`ats/fusion/shadow.py`](../../ats/fusion/shadow.py)**：
  - 全链路接入 `detect_patterns`、`pattern_score`、`SectorClock`（排头兵/夺旗）、`PATTERN_LATENT_BREAK` 先手重置、形态保底 `tier_floor`（2/3 档）与实时 `RaceTracker` 赛马跟踪；
  - `adaptive_cuts` 优先基于按股票代码去重的横截面最新分值计算分位（`self._latest_rar_by_code`），防止单只高频股污染分位阈值；
  - 全程 `self._lock` 与 `self._regime_lock` 双重检查锁定，消除 30 线程并发竞争与 SQLite 重复打开。

### 2.3 TDX 60 秒风暴根治、HDF5 全局锁与 UI 零阻塞
- **[`ats/tdx_realtime_fetcher.py`](../../ats/tdx_realtime_fetcher.py)**：
  - `_unlisted_or_dormant_codes` 引入指数退避冷却（60s -> 120s -> 240s -> 480s -> 最大 1800s）；
  - `missing_in_chunk` 由逐只串行 TCP 循环改为单次小批量（`retry_batch[:12]`）合并请求，消除 3.5 秒串行阻塞；
  - `_normalize_quote_to_snapshot` 补齐五档 `bid_pressure` 与 `taker_buy_ratio`。
- **[`ats/fusion/premarket.py`](../../ats/fusion/premarket.py)、[`ats/fusion/sector.py`](../../ats/fusion/sector.py)、[`ats/fusion/context.py`](../../ats/fusion/context.py)**：
  - 所有 `pd.read_hdf` 全部纳入 `JSONData.tdx_hdf5_api._HDF_GLOBAL_LOCK` 保护。
- **[`ats/ui/fusion_ladder_dialog.py`](../../ats/ui/fusion_ladder_dialog.py)**：
  - `_init_days()` 改为直接扫描影子目录与上下文目录文件名（耗时 `< 0.3ms`），彻底移除 UI 线程反序列化 21MB `minute_kline_cache.pkl`；
  - `load_live_rows` 与 `load_live_series` 增加 `(path, size, mtime)` 内存缓存，`_maybe_ensure_data` 优先复用内存最新时间戳，消除每 2 秒重读 JSONL；
  - 清理重复定义的 `changeEvent`，并在回放回补中完整保留 `track_entry`（MFE/MAE/收盘%/首异动/持续分）。
