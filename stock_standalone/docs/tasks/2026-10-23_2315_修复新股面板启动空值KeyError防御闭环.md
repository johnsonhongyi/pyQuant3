# 修复新股面板启动初期空值 KeyError: 'code' 防御闭环

## 背景与问题诊断
在 ATS 启动时（特别是夜间非交易时段或启动初期网络数据未就绪的几秒真空期内），日志频繁抛出以下警告：
```log
2026-10-23 22:41:15,872 [WARNING] IPO preparation failed: 'code'
2026-10-23 22:41:20,973 [WARNING] IPO preparation failed: 'code'
```

### 根本原因
1. **时序真空竞态**：
   - ATS 启动瞬间，主终端全市场 IPC 行情流率先到达；
   - 此时新股面板（`NewStockPanel`）的自身底层数据 `self.df_data` 还是刚初始化的空 DataFrame（`pd.DataFrame()`），后台线程 `NewStockFetchWorker` 仍在异步拉取中；
2. **缺少前置边界守卫**：
   - 界面切页渲染守护或 IPC 推送触发 `_request_table_prepare`，将空的 `self.df_data` 传入 `_merge_ipc_frame`；
   - 在 `_merge_ipc_frame` 第一行：`ipc_index_map = {str(c).zfill(6): str(c).zfill(6) for c in data['code'] ...}`；
   - 因 `data` 为空 DataFrame（缺少 `'code'` 列），Python 直接抛出 `KeyError: 'code'`；
   - 准备线程捕获并记录：`IPO preparation failed: 'code'`，形成每 5 秒一次的报错警告。

## 修复与加固实施
1. **`_merge_ipc_frame` 前置边界守卫与安全访问**（`ats/ui/new_stock_panel.py`）：
   - 增加前置判空：`if data is None or getattr(data, 'empty', True) or 'code' not in data.columns: return data`；
   - 行遍历由 `row["code"]` 升级为 `row.get("code")` 安全访问。
2. **`_prepare_stock_table` 前置判空**（`ats/ui/new_stock_panel.py`）：
   - 增加 `if data is None or getattr(data, 'empty', True) or 'code' not in data.columns: return [], ...` 优雅降级返回。
3. **`_request_table_prepare` 准备线程安全过滤**（`ats/ui/new_stock_panel.py`）：
   - `selected` 选中行提取增加 `'code' in data.columns` 守卫，杜绝空值访问抛错。
4. **自动化单元测试验证**（`tests/test_multiday_pct_base_view.py`）：
   - 新增 `test_new_stock_panel_empty_dataframe_guard` 专项用例（7/7 PASS）。
