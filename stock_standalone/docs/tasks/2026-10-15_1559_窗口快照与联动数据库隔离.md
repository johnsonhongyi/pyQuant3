# 窗口快照、磁吸恢复与联动数据库迁移

## 一、交付范围

本次提交包含本会话实现的窗口位置修复、联动数据库迁移保护改进、开发与打包环境数据库隔离及隔离测试。不包含工作区其他既有改动，不提交运行数据库、备份、行情数据或全局配置。

## 二、窗口快照与磁吸恢复

- TK 顶部工具栏的保存、恢复快照继续使用既有三个槽位，补充收集 `_signal_dashboard_win`，持久化名称固定为 `signal_dashboard_panel`。
- 面板显示时参与保存；磁吸收缩条仍属于显示中的窗口，因此也会纳入快照。已销毁的 Qt 面板跳过，普通显式隐藏的面板不新增到快照。
- 对具有 `anchor_edge` 和 `normal_geometry` 的 Qt 磁吸窗口，保存展开矩形和磁吸边缘，避免把屏幕外收缩坐标保存为正常位置。
- 恢复时停止旧滑动动画和磁吸、悬停定时器，清除收缩状态，更新展开矩形，恢复正常透明度，再恢复必要的悬停轮询。
- 停止动画不会触发其 finished 回调，因此恢复逻辑显式释放 `_in_snap_action`，并清除 `_is_dragging`，避免后续 moveEvent 永久无法触发吸附。
- 程序设置恢复坐标期间临时抑制拖拽检测，设置结束后允许用户再次拖动贴边；原先运行中的悬停轮询不会因恢复非贴边位置而永久停止。
- 保留既有 DPI 换算和屏幕边界约束；Tk 坐标通过 winfo 方法读取，修复负坐标无法按加号拆分的问题。
- 恢复只调整当前打开且能匹配快照的窗口，不负责创建已关闭的信号面板。旧快照缺少磁吸边缘字段时沿用当前窗口边缘状态。

## 三、旧数据库与 WAL 迁移保护

- 原逻辑只要发现 WAL 或 SHM 文件就拒绝迁移，无法区分异常退出残留与活动旧进程。
- 新逻辑在 Windows 上使用 CreateFileW，以只允许共享读取的方式持有数据库及存在的 WAL、SHM 文件句柄。旧 SQLite 可写连接占用时安全失败；迁移读取期间也阻止其他进程新开可写连接。
- 对共享冲突返回明确的 `linkage_legacy_writer_active`，不终止旧进程、不删除文件、不修改旧库。
- 无活动写入占用时，以 SQLite 只读连接和读事务读取一致性快照，正常合并读取 WAL 中已提交的数据；未提交事务不作为有效数据迁移。
- 迁移前使用 SQLite backup 生成完整恢复备份，执行 quick_check 后原子发布为 `原库名.migration-backup-时间戳.sqlite3`，路径记录在日志中。
- 运行库仍遵循原有容量策略：历史快照和事件按既有范围选取并清理。完整历史保存在完整恢复备份中，不能把运行库理解为全部历史的逐字节副本。
- 原数据库和 WAL 不被手工删除或强制 checkpoint；残留日志无需先删除即可被安全读取并迁移。
- 非 Windows 环境不能使用本次活动检测，会明确拒绝旧库迁移；不会用不可靠的文件存在检查代替活动检测。

## 四、开发与打包环境隔离

- 复用 sys_utils.is_packaged_env，按现有规则识别 PyInstaller、Nuitka 等打包环境。
- 打包环境维持应用根目录原数据库位置；开发环境使用同目录下的 `.development/system_linkage.sqlite3`。
- RAMDisk 路径继续按本地数据库绝对路径生成哈希身份，因此同目录开发版和打包版会自动使用不同运行库和归档目标。
- 日志输出 environment、runtime 和 archive，便于确认实际使用位置。
- 开发环境首次切换后使用独立新库，不自动复制原目录中的打包数据库或之前共用的开发数据；原数据仍保留。
- 显式传给客户端或网关构造函数的 database_path 继续遵循原调用行为，不经 runtime_database 自动重定向。
- 本次仅隔离联动 SQLite 数据库；网络监听端口、节点身份、配置、JSON 状态文件和其他业务数据未统一隔离。

## 五、验证

针对性测试文件：

- tests/test_magnetic_window_snapshot.py：左右顶边、普通位置、负坐标、两种 DPI、两种悬停轮询状态，共 16 个用例。通过提取真实方法执行隔离测试，不启动生产 UI。
- tests/test_linkage_legacy_migration.py：子进程异常退出 WAL 数据恢复、WAL/DELETE 模式活动连接阻止迁移且旧连接仍可写、开发与打包路径选择，共 5 个用例。
- tests/test_runtime_shutdown_archive.py：现有关闭归档及只读查看器回归，共 8 个用例。

验证命令：`python -m pytest tests/test_magnetic_window_snapshot.py tests/test_linkage_legacy_migration.py tests/test_runtime_shutdown_archive.py -q`。

另执行修改模块的 py_compile 和 git diff --check。测试使用临时目录、模拟窗口及隔离数据库，不连接真实下单环境。真实 Tk/Qt 桌面操作和实际打包产物未验收。

## 六、后续工作与验收

1. 在真实桌面依次验证左、右、顶边：收缩时保存，移动后恢复，鼠标离开自动收缩，再拖动重新吸附；覆盖多个快照槽位、多屏和 DPI 变化。
2. 分别运行源码版和实际 PyInstaller/Nuitka 产物，确认日志中的运行库和归档路径不同，并确认打包检测及目录写入权限。
3. 若开发、打包版本需要同时启动联动网关，先配置不同监听端口并检查节点身份、工作区及对端地址；本次数据库隔离不能解决端口占用。
4. 若需要继承之前共用的开发历史，先停相关进程并核对源库，再明确执行一次数据迁移；当前不会自动导入可能属于生产环境的数据。
5. 原有归档发布仍保留 WAL/SHM 存在即拒绝替换的保护；本次仅改进初始化迁移，后续若归档也受残留影响，需要单独设计 Windows 原子替换与占用检测，不能直接删除日志或绕过保护。
6. 完整迁移备份目前不自动清理；验证迁移与后续归档后再制定保留和清理策略，避免反复初始化产生备份占用。
7. 大数据库备份仍在初始化调用线程执行，未新增后台迁移调度或进度 UI；如有明显启动卡顿，后续单独设计异步初始化和明确就绪状态。
