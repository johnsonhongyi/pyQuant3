配置入口仍为 `config/llm_config.yaml` 的 `llm_settings.active_backend` 与 `backends`；本轮保留原默认选择及所有运行授权。切换路由后须重启对应旁路宿主，使 Worker 工厂与固定模型 ID 一致。Ollama 本机选择必须关闭远端回退；正式 Worker 继续读取既有 Stage/Provider/隔离授权，探针不签发授权。

Ollama 新路线还要求 `config/ollama_provider_acceptance.json` 绑定当前模型、规范化本机 URL 和三类 Agent Schema。人工验收记录须含 `status=ACCEPTED`、与既有运行授权相同的 `acceptance_id`、`binding_hash`、`reviewer`、`accepted_at`、相对项目根目录的 `evidence_path` 和探针文件实际 `evidence_sha256`；工具只输出探针及绑定哈希，不代写 ACCEPTED。证据必须为已通过且有完成时间的本机结构化探针；配置变化、证据被改或只有通用布尔授权时继续关闭。

## 本轮改动

- `ats/llm/ollama_backend.py`：通过 `/api/generate` 的 `format` 发送原生 JSON Schema；严格解析并复核结果，限定本机 HTTP origin、固定模型及 30 秒截止，禁用代理与重定向，不下载模型或执行工具。
- `ats/llm/backend_factory.py`、`provider_preflight.py`：Ollama 不再落入“不支持 Provider”；本机资源/结构化输出独立验收记录齐全后，沿用现有 Worker 启动门禁。预检轮询不访问网络。
- `ats/llm/request_producer.py`：兼容 Ollama 的 `model` 配置键；幂等 request_id 纳入模型和提示版本，避免切换模型后复用旧日志记录。
- `ats/llm/agent_contracts.py`：无证据请求原来生成 `enum: []`，被本机原生语法编译器拒绝；现以催化/风险列表 `maxItems: 0` 表达约束，不给无证据输出留引用空间。基础 Schema 哈希保持不变。
- `ats/llm/shadow_evaluation.py`：只消费已验链、已持久化交互结果和完整已验证输入；按 provider/model/prompt 分组，绑定原始快照哈希、证券、cutoff、成熟证据及人工复核。
- `ats/llm/interaction_journal.py`：新增批量只读接口，在一个一致的数据库读取事务中校验整条审计链一次，再取最近 100 个完整信封；消除逐个读取结果时重复全链校验的放大。
- `ats/ui/ipo_learning_console.py`：采集后台周期结束和人工标签审核保存后自动重算；展示影子状态、可评估分组数和报告时间。网络调用/指标重算不进入 UI 主线程。
- `tools/run_ipo_shadow_evaluation.py`：统一提供只读盘点、报告刷新、本机合成接口探针、独立预载；`learning_progress.py` 已按影子评估口径展示，正式权重训练/晋级/实盘明确在范围外。

## 评价契约

1. 评价窗口为最近 100 条已验链 Agent 交互，报告明确记录窗口限制与实际条数；不是“8 月至今全样本回放验收”。
2. 效果评价只接受 MARKET_REGIME 信封及完整 41 字段快照；证券、cutoff、配置/契约和输入哈希必须一致，输入证据只能引用该快照，不能带未来结果证据。
3. 模型响应必须在版本化信号时效内产生，早于 D1 收盘；成熟标签要有合法 D1-D3 交易日、真实可用时间及匹配人工 ACCEPTED 记录。旧响应、未来时间、错配、冲突证据与损坏审计均明确拒收/降级。
4. 同 provider/model/prompt 下，同一证券上市事件仅保留最早有效预测，防止重复预测增加样本权重。
5. 按决策 cutoff 排序做 70/30 前向分组；先前标签的实际可用与人工审核必须严格早于前向切点。至少 8 个事件、5 个切点前已审核先验、2 个前向事件才输出比较结果。
6. `ipo.shadow-direction.v1` 将 sentiment_score≥50 定义为研究方向提示，目标是 D1 收盘是否高于发行价；基线来自切点前已审核样本的多数方向。此定义不映射 ENTRY、买卖或仓位指令，也不代表收益评价。
7. 输出方向准确率、先验基线准确率、误报率/漏报率及各自分母；零分母返回空值。报告区分日志总数、窗口条数与省略数；写盘失败返回 persisted=false 并重算内容哈希。缺少请求开始时间时，P95 推理延迟明确 NOT_EVALUABLE，不以行情 cutoff 到响应时间冒充推理延迟。
8. 报告始终 `order_submitted=false`、`entry_authorized=false`、`model_promoted=false`、`training_performed=false`；比较结果不自动晋级或解锁交易。

## 可直接使用的入口

python tools/run_ipo_shadow_evaluation.py --read-only

# 刷新 data/ipo_learning/shadow_evaluation.latest.json，控制台自动读取
python tools/run_ipo_shadow_evaluation.py

# 合成输入验证现有本机服务；冷启动时先独立预载，不扩展 Worker 的30秒截止
python tools/run_ipo_shadow_evaluation.py --probe-ollama --start-local-service --warm-up

接口探针只发送明确标记的合成上下文。它不向生产交互审计库添加效果样本、不写 Stage/Provider 授权、不把 probe 的成功作为真实模型效果；模型自然卸载后需要重新预载。
