# 双桥重启后自动跟单降级与投研中断根治部署

## 1. 故障现象与复现背景
- **用户反馈**：早上出现双桥离线后，重启双桥后，前端页面（“自动跟单 · 模拟盘”控制台）状态依旧显示 `数据异常，已降级`，点击“刷新状态”或自动刷新依旧无法自动恢复。
- **现场实测**：
  - 远端 Docker 服务中，后台双桌面桥 `codex-411ad92cc5ef25a8efbc8e82` 与 `agv-59333f82b2a74c0363cd3ede` 均已恢复 `ready` 状态，心跳新鲜；
  - 但自动跟单后台 worker 日志中全天高频抛出 `CYCLE_ERROR: source unavailable or stale`，将 `cycle_status` 锁定为 `degraded`；
  - 自动投研策略准入函数抛出 `ValueError: Invalid isoformat string: '...216038+00:00'`，策略准入状态永久为 `policy_unavailable`，导致即便双桥重启也无法恢复派发自动投研任务。

---

## 2. 深度根因穿透

### 根因一：`candidates()` 强校验题材概览导致连板候选全盘被毙与死锁降级
1. **开盘啦轮动数据时滞**：开盘啦板块轮动接口（`/api/getPlateRotatData`）为日频/盘后计算，交易日盘中天然沿用上一交易日数据（`trade_date: 2026-10-20`），雷达融合引擎据此打上 `carry_forward: true` 与 `stale: true`；
2. **候选池全量级联崩溃**：`auto_follow.py` 中的 `candidates()` 在读取梯队之后，无保护调用 `fresh(overview["meta"], now, 1800)`。因 `stale: true` 和 `carry_forward: true`，`fresh()` 无条件抛出 `ValueError("source unavailable or stale")`；
3. **连板候选被殃及与周期死锁**：即便当日连板池（`ztpool.json` 44 只涨停，13 只连板股）100% 真实新鲜，也因题材异常而被全部丢弃，主循环捕获异常后将 `result = "degraded"` 写入 SQLite，前端映射为“数据异常，已降级”；
4. **下游链路全面阻断**：`follow_research.py` 检查 `state["cycle_status"] in ("market_gate", "degraded")` 直接静默返回；`follow_ai.py` 因无任何候选股而放弃派发任务。

### 根因二：Python 3.9 对 Go RFC3339Nano 纳秒时间戳解析异常导致投研策略瘫痪
1. **纳秒解析超界**：Go 语言 `time.RFC3339Nano` 输出 9 位小数纳秒时间戳（如 `2026-10-21T03:53:57.128216038Z`）；
2. **Python 3.9 兼容性陷阱**：在宿主机 Ubuntu Python 3.9 环境下，`datetime.fromisoformat()` 仅支持最多 6 位微秒小数，直接传入 9 位纳秒报错 `ValueError: Invalid isoformat string`；
3. **策略误判不可用**：`auto_research_policy.py` 原代码 `datetime.fromisoformat(row[1].replace('Z', '+00:00'))` 触发异常，被 `except` 捕获后返回 `(None, 'policy_unavailable')`，使得双桥即便重启且状态为 `ready`，自动投研也始终处于停摆状态。

## 3. 架构与工程加固方案

### 3.1 题材时滞容错与路线解耦（遵循 SOLID 单一职责与 KISS 原则）
- 在 `auto_follow.py` 的 `candidates()` 中，将 `overview` 题材新鲜度校验由“硬阻塞致命异常”调整为“优雅降级判定”：
  - 若 `overview` 处于跨日衰减或时滞状态（`overview_ok = False`），则本轮安全略过基于衰减题材的领涨股推荐，严格杜绝旧题材伪装新机会；
  - 但**绝对不打断基于当日真实涨停梯队的连板候选股生成**；
  - 成功保障了当日 13 只高标连板（吉大正元、海洋王、长春一东等）正常进入观察和执行队列。
- 在主循环执行完 `cycle()` 后，立即同步 `state["cycle_status"] = result`，消除时序滞后导致的下游组件误判。

### 3.2 纳秒时间戳微秒安全截断（DRY 原则）
- 在 `auto_research_policy.py` 中引入对 Go RFC3339Nano 纳秒级小数的正则平滑截断，统一兼容 Python 3.9 及以上版本的 `datetime.fromisoformat()`，使 `selection()` 正确识别在线桌面双桥节点。

### 3.3 RAMDisk 路径解析加固
- 在 `package-auto-follow.py` 中对 `resolve()` 异常增加 `absolute()` 保底，根除 Windows 内存盘（RAMDisk）环境下的 `WinError 1` 打包异常。
