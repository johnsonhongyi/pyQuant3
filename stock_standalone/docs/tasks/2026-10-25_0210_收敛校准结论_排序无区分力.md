# 收敛校准的结论：排序没有区分力（必须承认）

> 日期：2026-10-25 02:10
> 分支：`feature/signal-fusion-ladder`
> 目的：用盈利榜反向校准收敛规则，验证"能不能把答案排进前 20"

---

## 一、跑了什么

1. 训练日（10/19、10/21）给每个 L2+ 事件打标签：是否进当日盈利榜前 20；统计（阶段 × 赛道强弱 × 是否缩量）命中率；
2. 测试日（10/23）用六种排序口径取 Top20，量召回：`rar / profit_proxy / pct / ignition / pct_x_sector / calibrated`；
3. 追加实验：不用"首次触发"，改成**固定决策时点**（09:45 / 13:06）做横截面排序。

## 二、结果

| 口径 | 召回（Top20） |
|---|---|
| rar | 0% |
| profit_proxy | **5%**（最好） |
| pct | 0% |
| ignition | 0% |
| pct_x_sector | 0% |
| calibrated | 0% |

固定时点横截面（09:45 池 493 只 / 13:06 池 1202 只）：

| 时点 | 口径 | 命中 |
|---|---|---|
| 09:45 | rar | 0/20 |
| 09:45 | pct | 1/20 |
| 13:06 | rar | 0/20 |
| 13:06 | pct | 0/20 |

## 三、结论：问题不是"覆盖"，是"排序"

- 信号层**覆盖**了盈利榜 15/20（75%）——答案确实出现在事件池里；
- 但任何排序口径取 Top20 都只能命中 0~1 个——**排序与答案几乎无关**。

也就是说：系统"看见了"，但"认不出哪个是答案"。这才是"没有命中能力、没有下单判断力"的真正原因。

## 四、为什么认不出

RAR 的设计目标是"低风险可参与"：位置要近止损、承接要好、不要追高。
而当日涨幅榜前 20 的特征恰恰相反——**已经很强、还在变强**。

两者是**反向目标**：

| | RAR 偏好 | 涨幅榜特征 |
|---|---|---|
| 位置 | 贴近均价/止损近 | 远离均价、不断新高 |
| 追高 | 惩罚 | 奖励（强者恒强） |
| 时间 | 越早越好（先手） | 越晚越强（尾段加速） |

所以用 RAR 去排涨幅榜，必然是负相关。这不是调参能修的，是**目标函数选错了**。

## 五、两条可选路线（必须选一条，不能混）

**路线 A：继续做"低风险可参与"**
- 目标不是涨幅榜前 20，而是"正收益 + 低回撤"；
- 评价指标改成：胜率、盈亏比、最大回撤，而不是召回涨幅榜；
- 这条路我们已经有一定基础（缩量转放量 93.2% 胜率）。

**路线 B：做"强势延续"**
- 目标就是涨幅榜，特征要用：当日强度分位、连涨天数、板块龙头地位、尾段加速；
- 必须放弃"低风险"叙事，接受更高回撤；
- 需要新的打分器（`strength_rank`），与现有 RAR 并行，不能混用一个分数。

当前代码把两者混在一个 RAR 里，所以两边都做不好。

## 六、下一步（建议）

1. 先定路线。若选 B，新增 `strength_rank`（纯强度排序：当日涨幅分位 × 赛道强度 × 尾段加速度），与 RAR 并列输出两套清单；
2. 用盈利榜评估 `strength_rank` 的召回，目标是 Top20 命中 ≥8；
3. 两套清单在 UI 上分开呈现（低风险 / 强势），由使用者按 T+1 风险偏好选择。
