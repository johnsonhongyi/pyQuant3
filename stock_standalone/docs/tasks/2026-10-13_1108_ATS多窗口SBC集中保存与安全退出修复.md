# ATS 多窗口 SBC 集中保存与安全退出

- 现场日志：10:52:47 SBC 保存入口探测到 0 个窗口，随后行情线程仍有输出；父进程 10 秒后强制终止，返回码 1，PyInstaller 主进程报临时目录清理失败。
- 原链路逐窗发送 WM_CLOSE，窗口在集中保存前已注销；SBC 入口没有主程序已有的打包解释器退出 watchdog。父进程也未验证后台关闭任务结果。
- 新链路：父进程通过独立 request 文件发出集中退出请求，SBC 主线程心跳接收后先保存全部仍登记窗口，再关闭窗口停止轮询，检查行情/策略缓存保存结果，排空配置写入与归档，写入 fsync 确认回执，最后退出。
- 新协议不再由父进程扫描并抢写布局，也不逐窗 WM_CLOSE；旧进程保留兼容路径。等待预算 20 秒，超时仍有强制回收，但不能被报告为安全保存成功。
- 只有保存确认后才启动打包退出 watchdog，防止非 daemon 线程或 executor atexit 挂住解释器并占用共享解包目录。
- 原业务语义保留：单独关闭窗口不触发整组布局保存；Alt＋关闭触发集中保存；ATS 退出保存全部仍打开窗口。已单独关闭的窗口不会重新进入布局。
- 父进程要求正常退出码、后代进程退出和保存回执；关闭线程失败向 ATS 收尾门禁传递，主窗口保留失败提示，不再打印虚假的整体成功。
- NextDayWatch 仅在已请求退出时降低错误日志级别，运行期间的 worker 错误仍保留告警。
- 验证：19 项针对性测试通过，包括实际 Qt 单独关闭/Alt 关闭语义、13 个窗口完整落盘、缺失回执拒绝成功、缓存失败阻止回执、失败传递、独立子进程模拟阻塞非 daemon 线程后有界退出。
- 更新一项旧测试：生产已采用独立 watchdog，该测试仍期待已弃用的 150ms Qt 定时器，现改为验证实际 watchdog 调用。
- 语法及差异检查通过；未改动线上文件、未重新打包。需用新版本同时启动 ATS 和 SBC，运行一段时间后验收整组布局、日志回执、进程树及 PyInstaller 原生临时目录清理。
- 保留此前整窗重绘修复；不改交易规则，不删除现场临时目录，也不覆盖用户其他配置改动。

## 11:15 开发环境失败补查

- 用户复测为开发环境，SBC 被强制终止且无保存回执；现场仍存在以已回收 SBC PID 为父进程的 multiprocessing 子进程。未强杀该现场遗留进程。
- 上轮遗漏：解释器 watchdog 只覆盖打包环境，开发子进程可能被非 daemon 线程拖住；开发 run_sbc 入口未启用行缓冲，强制终止前的输出可能未落盘。
- 补齐：受 ATS 管理的开发 SBC 与打包 SBC 均在保存确认后启用 watchdog；保存配置与归档后、写回执前回收自身 multiprocessing 子进程。
- 开发启动设置 PYTHONUNBUFFERED 并复用 ensure_sbc_stdio。布局、关窗、行情缓存、策略缓存、配置、归档、multiprocessing 清理各阶段立即输出日志。
- 独立后台探针不操作 UI，只观察父进程请求；等待超过 8 秒且仍未完成时，记录当前阶段及全部 Python 线程栈，区分 GUI 不消费请求、锁等待、持久化或收尾阻塞。
- 针对性测试累计 20 项通过；模拟开发/打包两种入口，真实创建等待中的 multiprocessing 子进程与阻塞非 daemon 线程，验证回收、保存回执及有界解释器退出。
- 现场 saved=False 的确切阻塞位置仍需新日志确认；这些隔离验证不能表述为用户长时间运行场景已复现并完全解决。

## 11:22 线程栈定位与缓存写入竞争修复

- 新日志确认布局已经保存 6 个窗口，随后停在 market-cache；主线程等待 Windows RamDisk 字节锁，同进程 TDXHistoryCheckpoint 正持锁执行历史校验，dispatcher 仍在旧订阅快照上取数。
- Windows 文件字节锁也会让同进程不同文件句柄互相竞争并在等待后失败。增加实例级 writer RLock，让后台 checkpoint、周期归档、退出落盘进入同一串行入口；获取串行锁后才检查 dirty，前一 writer 已保存时退出不再重复写入。
- VWAP 快照仍在 writer/file 锁之外导出，避免引入工厂锁与写锁的反向等待；跨进程文件锁、远端数据合并、generation 语义不变。
- dispatcher 在行情批次前、每只股票历史取数前复查订阅，关闭窗口退订后不再继续处理剩余旧订阅。
- 22 项针对性测试通过，覆盖并发后台 writer 与退出 checkpoint、退订停止取数、选择性缓存合并、未加载股票 generation 和 VWAP 状态保留。另补锁序回归测试。
- 本次不是放宽 saved 判定，也未删除 dirty 检查或直接让 ATS 忽略子进程失败；仍需用户现场复测保存回执与安全退出。

## 11:31 盘中归档门禁遗漏修正

- 新线程栈显示后台缓存 writer 已完成写入，退出线程依次越过 strategy-cache、config-drain，最终停在 archive-drain 后返回 1。相较上一轮，文件锁竞争已不再是本次最终失败点。
- 确认实现错误：新增 SBC 收尾直接要求 `evaluation_store.flush(force=True)` 成功；该模块明确规定盘中 `force` 不能绕过正式归档门禁，因此正常盘中退出也会被误判失败。
- 修正为正式归档或恢复日志二选一持久化成功，保持原归档时窗规则。持仓组与单股使用独立 SBC recovery journal，不与 ATS 主程序 journal 共用，防止跨进程互相覆盖。
- SBC 启动时恢复其独立 journal，后续按既有归档时窗写入正式数据；只有 journal 也失败才拒绝回执及 watchdog。
- 26 项针对性测试通过，新增真实 EvaluationStore 盘中门禁、无 dirty 数据退出、有 dirty 数据安全写入及重启恢复、journal 失败不确认退出。旧测试 mock 正式归档恒成功未覆盖这项门禁，已补足。
- 尚需用户开发环境复测这次修正；未启动或关闭用户进程，未更新线上二进制。
