# 自动投研统一模型、设置与预算修复

## 结果与边界

- 自动投研默认关闭；旧 `ai_settings.enabled=true` 不会自动获得新版调度授权。保留原模拟提案采纳模式，不修改实盘交易、风控、行情证据或历史提案。
- 生产前端为 `stock-strategy/source/easy-stock-web`。入口统一为“系统设置 → 自动 AI 投研”，原“自动跟随 → Codex / AI策略”复用同一组件与后端设置；移除原入口的独立模型/强度选择。
- 模型来源只读取系统统一运行时，包括 provider、node/workspace、model、reasoning_effort。新任务冻结配置；执行前再次核对当前配置、策略能力、目录与 90 秒心跳。不可用时暂停，不选择其他桥、模型或档位。
- 移除后端自动换桥指令生成；前端后台刷新不能再持久改写全局模型，只有显式用户保存可修改系统设置。

## 设置、用量与安全控制

- 独立自动调度设置：开关、最短间隔、每日最多调用次数、每日 Token 预算。默认关闭、900 秒、3 次/日、300000 Token/日；间隔允许 300～86400 秒。
- 普通调度、成交复盘、AI 证据失效事件均遵守最短间隔，不再通过 force 绕过。保留交易日及 08:30～17:30 调度窗口。
- 两种领取入口（next 和 claim）使用同一事务门禁，先获得 SQLite 写锁再读取配置、次数与用量，确保并发不能透支次数；每日按 UTC+8 归属。
- 每次领取登记唯一尝试。失败也计次；未知/未结算用量阻止当日后续任务。过期租约不再静默重跑模型；原结果重放仍保持幂等。
- 增加今日已报告用量、未结算数、最近 30 项运行记录，展示模型/强度、时间、任务短 ID、状态和安全错误码，不返回完整证据、账号或密钥。
- Codex 策略补充 token_usage；收到 Token 上报达到剩余预算时中断当前 turn。AGV 沿用已有结果用量上报；缺失真实总用量则保持未确认，不能补 0。
- Token 预算依据提供方上报（含缓存输入），在途调用可能超额，不承诺它是账单硬上限。每日次数是领取次数上限；新版启用前的历史用量未自动补录，界面明确提示。
- 当前自动研究只支持具有 strategy_research 能力的 Codex/AGV 桌面桥；系统选 Hermes 时显示“不支持自动投研”并暂停，不静默改用桌面模型。
