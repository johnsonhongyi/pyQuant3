# 按日回放 + 验收：用"走出来的答案"检验信号系统

> 日期：2026-10-24 16:00
> 分支：`feature/signal-fusion-ladder`
> 验收标的：688787 海天瑞声、300296 利亚德（10/19 ~ 10/23）
> 目标：不等 10 个交易日，盘后当天就能看到"系统抓到没有、几点抓、几级、之后涨了多少"

## 一、结论

**系统在这 5 天里，10 个"票-日"中 8 个触发 L2 及以上，2 个只到 L1。**

最关键的 10/19 海天瑞声尾盘连续拉升，系统在 **13:54 以 L3 参与（RAR 66.8）触发**，当时涨幅仅 +3.2%，之后 MFE 8.16%、收盘 +7.92%——即在尾盘主升段之前就给出了可执行结论，而不是等涨幅榜。

10/23 利亚德更典型：**09:30 开盘即以 L2 触发（当时 -0.66%）**，之后 MFE 20.79%、收盘 +20.79%，等于抓在"一柱擎天"之前。

同时暴露了两个真实缺口（见第五节），这两个缺口比"抓到几只"更重要。

## 二、新增能力

### 1. 按日回放引擎 `ats/fusion/replay.py`

数据全部离线，不联网、不下单：

| 来源 | 内容 | 实测 |
|---|---|---|
| `G:/minute_kline_cache.pkl` | 3 分钟线，v2 压缩格式 | 5576 只 × 5 个交易日 × 每日约 77 根 |
| `logs/signal_snapshots/signal_ledger_latest.json.gz` | 当日信号账本 | 1141 条 entries |

单日 300 只标的回放约 4~8 秒（含两遍：先采样 RAR 分布，再按分位出结论）。

### 2. 自适应分档（这是让梯度"活过来"的关键）

固定阈值 82/72/62/50 是按理想输入定的。真实数据上，全池 RAR 的 p98 只有 64 左右——**L2 以上永远不触发，梯度退化成"只有 L1"**。

改为"**时点横截面分位 + 绝对下限**"：

- L4 = 同时刻前 2%，L3 = 前 8%，L2 = 前 20%，L1 = 前 40%
- 再与绝对下限取较严者：L4≥68 / L3≥60 / L2≥52 / L1≥45

按时点算而不是按全样本算，是因为全样本会被"强票被评估更多次"污染，阈值会随参与标的数漂移（实测 200 只与 300 只的 p60 能差 10 分以上）。

### 3. ATS UI 监视器 `ats/ui/fusion_ladder_dialog.py`

主界面工具栏新增 **「梯度🧬」** 按钮，打开非模态独立窗口，三个页签：

| 页签 | 看什么 | 数据来源 |
|---|---|---|
| 实时梯度（影子流） | L4/L3/L2/L1 排行、四轴分、仓位、进场区间、止损、先手分钟 | `logs/fusion_shadow/<今日>.jsonl` 尾部（与实盘信号同一条流） |
| 按日回放 | 选日期 → 跑 → 当日决策表（时间/级别/RAR/仓位/涨幅/MFE/MAE/收盘/温度） | 3 分钟线缓存 |
| 验收与复盘 | 填代码跑验收，直接出"哪一天几点几级抓到" + 未达标原因诊断 | 回放结果 + 影子日志 |

## 四、界面与用法

**界面**：ATS 主界面工具栏 → 「梯度🧬」→ 选日期 → 「▶ 跑回放」。进度条走完即出表；「验收与复盘」页填 `688787,300296` 点「跑验收」。

**命令行**：

```bash
# 单日回放（带验收标的）
python -m ats.fusion.replay --day 2026-10-23 --top 300 --focus 688787,300296

# 输出落在 logs/fusion_replay/<day>.jsonl 与 <day>.md
```

改完权重/阈值后重跑一次即可对比，不再需要等下一个交易日。

## 五、暴露的两个真实缺口（比命中率更重要）

### 缺口 1：冷市 + 先手过期，好票只给 L1

10/23 海天瑞声：09:42 触发 L1（RAR 46.5），之后 MFE 17.99%。当日 09:42 温度仅 35.9℃（冰点），温度上限把级别压到 L2，再叠加"启动 90 分钟后先手衰减归零"，11:19 出现当日最高 RAR 69.5 时反而只能给 L0。

这说明当前"温度上限 × 先手衰减"的双重压制在**冷启动日过严**：低温期用 0.5 系数、上限 L2 是对的，但"先手"应该按**启动**算，而不是按"首次满足涨幅 1%"算——它开盘就高开 1.7%，先手点被过早打掉。

### 缺口 2：追高惩罚不足以拦下"高位接力"

10/22 利亚德 +11.01% 时给到 L2，当日收 -2.4%。当时偏离均价仍在 7% 否决线以内，惩罚只有约 20 分，不足以把它压到 L1。**7% 的硬否决线对 20cm 标的偏宽**（创业板/科创板应单独设阈值）。

## 六、必须说清的局限

1. **同日分位 = 轻微前视**。回放用当日全池分布定分位，实盘只能用"过去 20 日滚动分布"。下一步应改为滚动，回放结果会比现在保守。
2. **盘口是代理**：外盘占比 = 收阳 bar 成交量占比；买盘压 = 收盘在 bar 区间的位置；结构清晰度 = 近 10 根站上均价比例。真实盘口数据回放里没有。
3. **VWAP 是近似**：(H+L+C)/3 按量加权，不是真实成交额/成交量。
4. **3 分钟粒度**：抓不到 1 分钟级的瞬时插针，先手时间精度约 ±3 分钟。
5. **底台是代理**：`max(当日最低, 均价×0.985)`，不是真实 SBC 底台。

因此：**回放用于判断"方向对不对、阈值该往哪调"，不用于估算收益曲线。**
