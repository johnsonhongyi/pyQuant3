## 0. 审核结论先行

前一份审计的根本缺陷，用一句话说：

> **它把"异动"当成一个瞬时属性在算，而"异动"本质是一个过程。**

因此它只能回答"这一帧谁涨得多"，无法回答：
- 谁**正在**走强（进退方向）
- 谁在**抬高**低点（上下结构）
- 谁**已经**进场、持了多久、浮盈多少（持仓时序）
- 谁该在**此时**退场、谁该被换掉（去弱留强跨时比较）

本文的替换方案是**三轴模型**：时间轴（Bar Clock）× 价格结构轴（HH/HL/LH/LL）× 状态轴（有限状态机 + 事件账本）。盘前用 DFall 数百个策略基数定"身份"，盘中只用时间轴定"时机"。

**核心不变式（贯穿全文）**：

1. 任何判断都必须挂在**bar 索引**上，不挂在"调用次数"或"当前帧"上。
2. 任何状态迁移都必须有**事件记录**（bar、价、因），否则不可复盘 = 不可信。
3. 状态**单调前进**，除退场外不得回退。
4. 盘前定身份，盘中定时机，**两者不互相覆盖**。

## 1. 事实基线（已代码核实）

### 1.1 频率不是高频，且由 CCT 统一定义

| 数据通路 | 实际节拍 | 定义位置 | 核实结论 |

| DFall 宽表 | **默认 300 秒** | 应新增 `ats_df_sync_interval`（当前缺失） | ⚠️ 现为硬编码：`main_window.py:4021` 保活 `stale_after=600`，`ipc_sync_manager.py:60` `stale_sync_interval=600.0` |
| TK → ATS IPC | 全量 `UPDATE_DF_ALL` + 增量 `UPDATE_DF_DIFF` | `ats/ipc_bridge.py:264/351`，端口 26670 | ✅ 增量合并已实现，含日期翻转与冷启动基线自愈 |

### 1.2 盘前基数：DFall 的数百列就是"身份"

`display_cols.json` 实测可展示列 70+，全量数百。按语义归四类，这正是"提前判断个股状态"的原料：

| 类别 | 列（实测存在） | 用途 |
|---|---|---|
| 结构 | `ch_slope_deg`, `ch_slope`, `ch_supp_slope`, `ch_supp_pos`, `TrendS`, `bull_s`, `bullbreak`, `boll`, `structure_base_score` | 定结构类型：突破底座/上升通道/反转/弱势下行 |
| 位置 | `support_today`, `support_next`, `resist_today`, `resist_next`, `ptop`, `pbottom`, `pbreak`, `MainU`, `nhigh`, `nlow` | 定触发线、防守线、空间上限 |
| 动能 | `dff`, `dff2`, `dff3`, `slope`, `power_idx`, `win`, `red`, `gren`, `sum_perc`, `per1d~per4d`, `signal_strength` | 定先验强度与历史惯性 |
| 风险 | `obs_d`, `pdays`, `ch_nod`, `lastdu4`, `vol_ratio`, `couts`, `td_sell` | 定波动预算、连板高度、出货风险 |

**关键**：这些列**盘前就已算好**，盘中不会变（或只微调）。所以它们是**先验**，绝不能和盘中瞬时涨幅混在一个排序函数里——现有引擎正是把 `vol_ratio_1d`/`alpha_1d`（先验）和 `curr_pct`（瞬时）加在同一个 `raw_score` 里，导致"身份"被"瞬时"淹没。

## 2. 病根：五个"无时序"的具体证据

不是抽象批评，逐条对应代码。

### 2.1 状态每帧无状态重算 → 没有"进退"

`ultra_short_anomaly_engine.py:1405-1485`：`race_state` 由 `if broken_stage_low / elif is_stagnant_in_overheat / elif severe_high_drop / elif is_now_accelerated / elif is_emerging_now / else` 单帧判定。

`is_accelerated` 在 1339 行被置 `True` 且是粘性的，但**分支里用的是 `is_now_accelerated`**（瞬时）。所以加速事实被记录却从不参与判决——这就是实测中"+9.6% 判留强 → 回踩 +3.8% 判出局 → 回升 +6% 退回蓄势"的根因。

**没有 `from_state`，就没有"进"和"退"，只有"是"和"否"。**

### 2.2 温度环按调用次数而非时间 → 15m 斜率失真

`MarketTemperatureCycleTracker.__init__:194` `deque(maxlen=180)`，`update_from_arrays` 每次调用 `append` 一次。180 点是**次数**不是**秒数**：
- 若 UI + 引擎 + 面板各调一次 → 1 秒 3 点 → 180 点 = 60 秒，`slope_15m` 实际是 1 分钟变化；
- 若只在 TDX 节拍调 → 180×5s = 900s，恰好 15 分钟（巧合成立）；
- 若 DFall 300s 节拍主导 → 180×300s = 15 小时，跨日。

同一个字段在不同调用拓扑下语义完全不同——**时间轴缺失的典型症状**。

### 2.3 只记 entry_price，不记轨迹 → 没有"上下"

`UltraShortHorseItem` 有 `entry_price / entry_ts / high_pct / low_pct`，但 `high_pct` 是**当日**最高，不是**进场后**最高。因此：
- 无法算进场后 MFE/MAE；
- 无法判断"高点是否在抬高"（HH/HL）；
- 无法算"站稳某线多少根 bar"。

`drawdown_from_high` 用的是日内高点，进场前的高点会污染进场后的回撤判断。

### 2.4 无事件日志 → 无法复盘

全模块没有任何"状态迁移事件"结构。`_cached_report` 只存最新快照。事后无法回答：这只股票几点几分因为什么进的场、中途有没有被误杀、出场价与最优价差多少。

**没有事件流，就无法做 T+0 回填，就无法把评分变成概率。**

### 2.5 无持仓账本 → "去弱留强"只是帧内排序

`sort_priority`（534 行）是帧内排序权重。真正的"去弱留强"必须是**跨时间比较**：A 已持 40 根 bar 浮盈 3% 且高点不再抬高，B 刚触发且量能结构更好 → 换掉 A。现有结构里 A 和 B 根本不在同一个可比空间（A 没有"持有多少 bar""进场后 MFE 曲线"）。

## 3. 目标模型：三轴

```
                     ┌──────────────── 状态轴（何时进/何时退）────────────────┐
                     │  DORMANT → ARMED → TRIGGERED → HOLDING → TRAILING → ACCEL │
                     │                     ↓            ↓         ↓        ↓    │
                     │                  EXITING ←───────┴─────────┴────────┘    │
                     │                     ↓                                    │
                     │                  EXITED ──(冷却 N bar)──→ DORMANT         │
                     └──────────────────────────────────────────────────────────┘
                                          ↑ 由时间轴 + 结构轴驱动
        ┌───────────────┐        ┌────────────────────┐        ┌──────────────────┐
        │ 时间轴 BarClock│  ───→  │ 结构轴 HH/HL/LH/LL │  ───→  │ 事件 + 持仓账本   │
        │ bar_id, 15s    │        │ 进退 / 上下         │        │ 可复盘 / 可校准   │
        └───────────────┘        └────────────────────┘        └──────────────────┘
                ↑
        ┌───────────────┐
        │ 盘前身份层     │   DFall 数百列 → 结构类型 / 波动预算 / 触发线 / 先验分
        └───────────────┘
```

三轴各自回答一个问题，互不越界：

| 轴 | 回答 | 数据源 | 节拍 |
|---|---|---|---|
| 盘前身份 | **这只股票值不值得盯** | DFall 数百列 | 盘前一次 + 盘中 300s 微调 |
| 时间/结构 | **现在是不是时机** | TDX 5~10s → 15s bar | 15s |
| 状态/账本 | **该进还是该退，持了多久** | 事件流 | 每 bar |

## 4. 架构：四层

### L0 盘前身份层 `ats/premarket_profile.py`

输入：`df_all` 一行（数百列）+ 昨日/多日 K。
输出：`PreMarketProfile`

```python
structure_class : BREAKOUT_BASE | CHANNEL_UP | REVERSAL | RANGE | WEAK_DOWN
vol_budget_pct  : 该股日内正常波动幅度（由 lasth/lastl/lastp 多日振幅中位数估）
trigger_line    : 触发线（优先 resist_today，其次 neck，再次 nhigh）
defend_line     : 防守线（support_today > support_next > nlow）
space_pct       : 到空间上限的距离（resist_next / ptop）
prior_score     : 0~100 先验分（结构 40 + 动能 35 + 位置 25）
gate            : PASS | WATCH | REJECT
trigger_params  : 该股自适应阈值（按 vol_budget 缩放，见 §7.2）
```

`gate=REJECT` 的股票**不进盘中时间轴**（省算力，也避免污染）。这就是"类似现在使用的策略过滤"。

### L1 时钟与轨迹层 `ats/signal_timeline.py`

- `BarClock`：wall clock → `bar_id`（排除午休），幂等写入同一 bar。
- `TrackSeries`：每股定长环形缓冲，按 `bar_id` 对齐，缺失 bar 显式记 `gap`。
- 派生量：`slope(n)`、`structure(n)`、`above_ratio(line, n)`、`mfe/mae`、`time_above`。

### L2 状态机与账本层 `ats/signal_state_machine.py`

- `SignalStateMachine`：状态 + 迁移守卫（确认 bar / 最短驻留 / 单调前进）。
- `TransitionEvent`：每次迁移落一条事件。
- `PositionLedger`：进场/加仓/减仓/退场，含 MFE/MAE、持有 bar 数、出场原因。
- `WeakStrongRanker`：跨持仓比较，输出"该换谁"。

### L3 消费层

- UI：时间轴视图（每只股票的 bar 轨迹 + 状态色带）、持仓账本、事件流。
- 告警：只推**状态迁移事件**，不推快照重复。
- 复盘：事件流 → T+0/T+1 回填 MFE/MAE → 概率化。

## 5. 数据结构（代码级定义）

### 5.1 Bar 对齐

```python
# 交易时段：09:30-11:30 (7200s) + 13:00-15:00 (7200s) = 14400s
# bar_seconds = 15 → 960 bar/日
def bar_id(ts: float, bar_seconds: int) -> int:
    """返回当日交易 bar 索引；非交易时段返回 -1。"""
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `bar_id` | int | 0~959，跨午休连续 |
| `close/high/low/open` | float | 该 bar 内聚合 |
| `vol` | float | 该 bar 内成交量（末值-首值，或直接取快照 volume 差分） |
| `vwap` | float | 末值 |
| `pct` | float | 末值涨幅 |
| `temp` | float | 该 bar 末市场温度 |
| `n_samples` | int | 该 bar 收到几次推送（用于质量诊断） |
| `gap` | bool | 该 bar 无推送 |

**幂等规则**：同一 `bar_id` 多次写入 → `open` 取首次、`high/low` 取极值、其余取末次。多消费方重复调用不会污染时间轴。

### 5.2 结构轴量化（"上下"）

```python
class Structure(Enum):
    HH_HL = "HH_HL"   # 高点抬高 + 低点抬高 = 上升结构（进）
    LH_LL = "LH_LL"   # 高点降低 + 低点降低 = 下降结构（退）
    HH_LL = "HH_LL"   # 扩张（波动放大，方向未定）
    LH_HL = "LH_HL"   # 收敛（压缩待变盘）
    RANGE = "RANGE"   # 无明显枢轴
```

枢轴检测：在最近 `n` 根 bar 上找局部极值（左右各 `k` 根确认），取最近两个高点、两个低点比较。
默认 `n=12`（3 分钟）、`k=2`。

### 5.3 进退量化

```python
slope_pct_per_min = linreg(close[-n:]) / close[-1] * 100 * (60 / (bar_seconds * n))
```

配三个派生：
- `slope_3`（3 bar，45s）：瞬时方向，用于触发确认
- `slope_12`（12 bar，3min）：短趋势
- `slope_48`（48 bar，12min）：日内趋势

`进退 = sign(slope_12)`，`加速 = slope_3 > slope_12 > 0`。

### 5.4 事件

```python
@dataclass(frozen=True)
class TransitionEvent:
    code: str
    from_state: str
    to_state: str
    bar_id: int
    ts: float
    price: float
    pct: float
    market_temp: float
    reason_code: str      # 机器可读，用于统计
    reason_text: str      # 人可读
    evidence: dict        # 触发时的关键量（slope/above_ratio/mfe...）
```

### 5.5 持仓

```python
@dataclass
class Position:
    code: str
    entry_bar: int
    entry_ts: float
    entry_price: float
    entry_pct: float
    entry_temp: float
    entry_reason: str
    stop_price: float
    target_price: float
    mfe_pct: float = 0.0      # 进场后最大浮盈（用进场后 high 算）
    mae_pct: float = 0.0      # 进场后最大浮亏
    max_bar: int = -1         # MFE 发生的 bar
    adds: list = []           # 加仓事件
    trims: list = []          # 减仓事件
    exit_bar: int = -1
    exit_price: float = 0.0
    exit_reason: str = ""
    realized_pct: float = 0.0
```

**关键**：`mfe_pct` 用**进场后**的 high，不是当日 high。这一条就修掉了 2.3 的污染问题。

## 6. 状态机完整定义

### 6.1 状态与层级

| 状态 | level | 含义 | 可持有 |
|---|---|---|---|
| `DORMANT` | 0 | 盘前合格，盘中未动 | 否 |
| `ARMED` | 1 | 逼近触发线，结构未坏 | 否 |
| `TRIGGERED` | 2 | 触发进场（事件产生当 bar） | 是（开仓） |
| `HOLDING` | 3 | 持仓跟单 | 是 |
| `TRAILING` | 4 | 浮盈达标，移动止盈 | 是 |
| `ACCEL` | 5 | 加速锁定 | 是 |
| `EXITING` | 6 | 退场待确认（软退场） | 是（减半） |
| `EXITED` | 7 | 已退场 | 否 |

### 6.2 迁移表

| From | To | 条件（全部满足） | 确认 bar | 原因码 |
|---|---|---|---|---|
| DORMANT | ARMED | `dist_to_trigger ≤ arm_dist_pct` 且 `structure != LH_LL` 且 `close ≥ defend_line` | 2 | `ARM_APPROACH` |
| ARMED | TRIGGERED | `close > trigger_line` 且 `vol_confirm ≥ 1.2` 且 `above_ratio(trigger_line,2) ≥ 0.5` 且 `alpha_today > 0` 且 `tradable` | 2 | `BREAK_TRIGGER` |
| ARMED | DORMANT | `structure == LH_LL` 或 `close < defend_line` | 2 | `ARM_INVALID` |
| TRIGGERED | HOLDING | 自动（同 bar 下一拍） | 0 | `POSITION_OPEN` |
| HOLDING | TRAILING | `mfe_pct ≥ trail_start_pct` | 1 | `TRAIL_ARM` |
| HOLDING/TRAILING | ACCEL | `slope_3 > 0` 且 `slope_3 > slope_12 > 0` 且 `close ≥ vwap` 且 `pct ≥ accel_thresh`（按 vol_budget 自适应） | 2 | `ACCEL_LOCK` |
| HOLDING/TRAILING | EXITING | `close < stop_price` 或 `structure == LH_LL` 且 `close < vwap` 或 `holding_bars > max_hold_bars` 且 `mfe_pct < min_progress_pct` 或 `market_temp 退潮` | 1~2 | `STOP_LOSS` / `STRUCT_BREAK` / `TIME_STOP` / `TEMP_EBB` |
| ACCEL | EXITING | `close < stop_price`（加速后止损位=vwap*0.992 与 trigger_line*0.99 取高） | 1 | `ACCEL_STOP` |
| TRAILING | EXITING | `close < max(high_since_entry * (1 - trail_gap_pct/100), stop_price)` | 1 | `TRAIL_STOP` |
| EXITING | EXITED | 确认 1 bar（硬止损则 0 bar 立即） | 0~1 | 继承 |
| EXITED | DORMANT | `cooldown_bars` 已过 且 结构重新合格 | 1 | `REARM` |

### 6.3 三个守卫

**(a) 单调前进守卫**
`level` 只允许沿上表前进。任何计算出的目标 level < 当前 level 且当前 ∈ {ACCEL, TRAILING}，**拒绝迁移并记 `MONOTONIC_BLOCK` 诊断事件**（不改变状态）。这条直接修掉 2.1 的"加速事实被抹掉"。

**(b) 确认 bar 守卫**
条件必须连续 `confirm_bars` 根 bar 成立。单 bar 假突破被过滤。实现用 `_streak` 计数器，条件不成立即清零。

**(c) 最短驻留守卫**
除硬止损外，状态至少驻留 `min_dwell_bars` 才允许离开。防抖动。

### 6.4 退场即"进退"的体现

退场不是"跌了就出"，而是四条互斥路径，各有原因码，可分别统计胜率：

1. `STOP_LOSS` / `ACCEL_STOP` / `TRAIL_STOP` —— 价格纪律
2. `STRUCT_BREAK` —— 结构纪律（LH_LL 确认）
3. `TIME_STOP` —— 时间纪律（持有超预算且无进展）
4. `TEMP_EBB` —— 环境纪律（市场退潮）

**这四条就是"进退"的量化定义**，也是后续概率化评分要分组统计的维度。

### 7.2 自适应阈值（按个股波动预算）

全局 `emerging_min_pct=1.6` 对不同波动率的股票不公平。改为：

```
pct_thresh   = max(0.8, k_pct * vol_budget_pct)      # k_pct 默认 0.55
vol_thresh   = 1.15 + 0.25 * (1 - vol_budget_pct/中位)  # 低波股放宽量能要求
accel_thresh = board_limit * 0.55                     # 10cm→5.5%, 20cm→11%（原为固定 5.5/7.5）
```

`vol_budget_pct` 由多日振幅中位数估（`lasth/lastl/lastp` 已有）。

## 8. 可交易性守卫（Tradability）

在 `TRIGGERED` 之前必须过：

| 检查 | 判定 | 处理 |
|---|---|---|
| 一字板 | `high == low == close` 且 `pct ≥ limit*0.98` | `tradable=False`，状态停在 `ARMED`，标"不可执行" |
| 停牌 | `vol == 0` 或价格不变超 `k` bar | `tradable=False` |
| 流动性 | 该 bar 成交额 < 阈值 | `tradable=False` |
| 涨跌停封板 | 封单/流通比过高 | 标"排队风险" |

**原则**：不可交易 ≠ 不记录。仍进时间轴、仍出状态，但**不产生可执行信号**，账本不记开仓。这样复盘能区分"信号错"和"执行不了"。

## 10. 验收标准

| 项 | 标准 |
|---|---|
| 时间轴正确性 | 960 bar/日；午休不产生 bar；同 bar 幂等 |
| 单调性 | 构造"加速后回踩"序列，状态必须停 `ACCEL` 或进 `EXITING`，**不得回 `DORMANT`** |
| 确认过滤 | 构造 1 bar 假突破，不得产生 `TRIGGERED` |
| 时间纪律 | 持有超 `max_hold_bars` 且浮盈 < `min_progress_pct`，必须 `TIME_STOP` |
| MFE 正确性 | 进场前的高点不得计入 `mfe_pct` |
| 不可交易 | 一字板不得产生开仓 |
| 性能（实测口径） | 见下表，**按跟踪池而非全市场验收** |
| 回归 | 现有 `tests/test_ultra_short_anomaly_horse_loop` 全绿 |

### 10.1 性能实测（本机 anaconda Python 3.9，单 bar = ingest + derive）

| 规模 | 单 bar 中位 | P90 | 15s 节拍占用 |
|---|---|---|---|
| 600 只（典型跟踪池） | **20.5 ms** | 22.5 ms | 0.14% |
| 800 只 | **27.9 ms** | 34.9 ms | 0.19% |
| 1200 只 | 41.7 ms | 46.2 ms | 0.28% |
| 5500 只（全市场） | 215.6 ms | 236.8 ms | 1.44% |

**必须澄清的一点**：本方案早期草案曾写"全市场 5500 只单 bar < 3ms"，该指标**不成立，已废弃**。
原因是逐股 Python 对象的每次方法调用固定开销约 0.3~1µs，5500 只 × 20+ 次调用不可能压到 3ms。
3ms 级别只能靠"跨股票 2D 数组整体向量化"实现，而 P0 不需要：
- 15s 节拍下 215ms 仅占 1.44% CPU，全市场也不构成瓶颈；
- 生产上只对 `gate != REJECT` 的跟踪池（约 600~1200 只）算派生量，实测 20~42ms；
- 向量化会牺牲"每股独立状态机 + 事件流"的表达力，得不偿失。

优化过程留痕（同一台机器，5500 只，单 bar）：1278ms → 355ms → 215ms。
关键改动：`structure` 的 `any(生成器)` 改 `None in seg`（C 层比较）、
三次提窗合并为 `_window3` 一次循环、环缓冲由 numpy float32 改 `array('f')`、
日期翻转检查从"每股每次"降为"60 秒一次"。
