# 2026-10-30 22:25 【TK彻底移除鼠标Button-4/Button-5侧键滚轮绑定治理】

## 一、问题背景
用户反馈：
使用鼠标的前进和后退（第 4、5 侧键，即 XButton1 / XButton2），映射为通达信的 F5（分时/日K切换）、Esc 或 Enter 键。但是在与 TK（Tkinter 主控）配合使用中，鼠标自定义功能会突然失效，必须退出并重启 ATNSOFT Key Manager 才能恢复。

## 二、根本原因定位
1. **Linux vs Windows 鼠标事件定义历史遗留陷阱**：
   - 在 Linux/X11 下，鼠标滚轮上滚和下滚对应 `<Button-4>` 与 `<Button-5>`。
   - 但是在 **Windows 系统** 下，鼠标滚轮唯一且标准的消息是 `<MouseWheel>`（包含 `event.delta`），而 **`<Button-4>` 和 `<Button-5>` 在 Tkinter (Windows) 下对应的是物理鼠标的第 4 键（后退）和第 5 键（前进）**（即 Win32 的 `WM_XBUTTONDOWN / XBUTTONUP`）。
2. **`bind_all` 全局劫持与未解绑**：
   - 在 `instock_MonitorTK.py`、`column_manager.py`、`popularity_resonance_gui.py` 等模块中，为了实现鼠标悬停滚动，在 `<Enter>` 事件中调用了：
     ```python
     tree.bind_all("<Button-4>", lambda e: tree.yview_scroll(-1,"units"))
     tree.bind_all("<Button-5>", lambda e: tree.yview_scroll(1,"units"))
     ```
   - 这导致当光标经过或悬停于小窗口上方时，Tkinter 全局捕获并吞掉了所有鼠标第 4、5 侧键消息，把前进/后退当做滚轮上下滚动。
   - 尤其当 `<Leave>` 事件因窗口失焦、弹窗、快速移动或层叠未触发时，该绑定持续残留，与 Key Manager 的低级鼠标钩子（`WH_MOUSE_LL`）发生按键状态争夺与冲突，导致 Key Manager 的虚拟按键注入失败或钩子超时被 Windows 系统静默注销。

## 三、治理方案（KISS / YAGNI 原则）
本系统专用于 Windows 生产环境，不再需要 Linux 的 Button-4/5 兼容：
1. **彻底移除所有 `<Button-4>` 与 `<Button-5>` 的 `bind_all` 和 `unbind_all`**；
2. **仅保留标准 `<MouseWheel>` 滚轮事件**，由 Windows 原生 `event.delta` 负责垂直平滑滚动；
3. **编写自动化测试**，确保 Treeview / Canvas 在 `<Enter>` 激活时绝对不注册 `<Button-4>` 和 `<Button-5>`，完全放行硬件侧键。
