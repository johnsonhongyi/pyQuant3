## 本轮发现及处理

- [P1，已修复] Docker 新容器启动失败时可能尚未运行，stop 返回 304 原先被当作错误，导致异常清理中断，旧容器未必恢复。现在仅对 stop 的 304 作幂等处理；清理动作即使失败也继续尝试恢复旧名称、重启策略、启动及健康检查，最终明确报告回退不完整，不伪报成功。补修只在本地验证，没有在生产重跑迁移。
- [工程问题，已处理] Windows 检出的 install.sh 是 CRLF。增加范围明确的 .gitattributes，使 Docker Shell、AC86U 工具及归档候选保持 LF；不对全仓执行换行迁移。
- [归档边界] scratch/ac86u-clash-20261018 包含私有原始配置、临时结果和二进制安装包，留本机并精确忽略；源码工具仍需自备对应私有基线。两个正式只读 inspect 脚本添加精确忽略例外后入库。
