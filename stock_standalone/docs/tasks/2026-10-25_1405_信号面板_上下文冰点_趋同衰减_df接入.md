## 二、信号面板：从"Top10"到"全部信号"

以前报告只给前几名，看不到"今天到底多少信号"。现在给完整分布：

```
标的 5573 只｜评估 41 万次｜L1+ 信号 11,353 条｜入局 390 笔｜可下单 5 笔
```

| 视角 | 内容 |
|---|---|
| **漏斗** | 评估 → L1+ → L2+ → L3+ → 入局 → 可下单，每层保留率 |
| 级别 | L1/L2/L3/L4 各多少条 |
| 结构 | 主升浪 / 通道内 / 超跌突发 / 杀跌反弹 / 其他 |
| 形态 | 突破VWAP、逆势带头、潜伏转突破、缩量转放量、两阳加速… |
| 陷阱 | 冲高回落、高开回落、前日大涨今日杀跌、放量滞涨、跌破均价放量 |
| 时段 | 上午/下午 + 按小时 |
| 温度 | <35℃ / 35~45 / 45~55 / ≥55 各多少条 |

**信号总量本身就是情绪指标**：一天 1000 条和 4000 条，是完全不同的盘面。

## 三、带头价值：不是固定加分，而是随环境衰减

```
温度 25℃ 趋同 10% → ×0.95   （没人反应，出现才有价值）
温度 40℃ 趋同 50% → ×0.60
温度 58℃ 趋同 85% → ×0.42   （人尽皆知的诱多）
```

公式：`0.35 + 0.65 × temp_f × cons_f`，下限 0.35（带头永远不是负分，只是很便宜）。

**趋同度**（0~1）= 0.5×全市场上涨占比 + 0.3×本赛道上涨占比 + 0.2×已涨超1%占比。

## 四、上下文：饿了几天，第一个包子最香

`market_ctx.py` 维护每日摘要（开盘/收盘/最低温度、阶段、宽度），落盘 `logs/fusion_state/market_history.json`。

- **冰点** = 上涨占比 ≤20%；低温 ≤35%；高温 ≥70%
- `ice_days` / `cold_days` 只数**此前**的天数（无未来函数）
- **饥饿度** = `1 + 0.10×min(冰点天数,3) + 0.03×min(低温天数,5)`，上限 1.5
- 饥饿度进 RAR 修正：`+min(6, (hunger-1)×12)`

用 36 天日线回填宽度（`seed_from_daily`），所以不需要等系统自己攒：

| 交易日 | 前一日宽度 | 上下文 | 饥饿度 |
|---|---|---|---|
| 10/20 | 0.446 | 常温 | ×1.00 |
| 10/21 | 0.622 | 常温 | ×1.00 |
| 10/22 | 0.392 | 常温 | ×1.00 |
| **10/23** | **0.093**（90 家跌停） | **冰点后第 1 天** | **×1.13** |

10/23 正是"惊天逆转"那天，也是利亚德 +20.79% 那天。

## 五、IPC 接的是 df 全量行情

你指出得对：`ipc_bridge` 推的是 `UPDATE_DF_ALL` / `UPDATE_DF_DIFF` 的全量行情，异动信号来自交易中心。已改成：

```python
bridge = FusionLiveBridge()
ipc.start_realtime_listener(
    port=26670,
    data_callback=bridge.make_df_callback(),      # ← 全量行情（主入口）
    signal_callback=bridge.make_callback(),       # ← 交易中心信号（可选）
)
```

`on_df(df)` 每帧做：读列（trade/price、percent/pct、open/high/low、pre_close、vol_ratio、vwap，字段名容错）→ 查日线上下文 → 算形态/陷阱/跨日风险 → 喂跟踪器。
首异动触发：`放量上行（涨幅≥1% 且量比≥1.5）` 或命中形态。

## 六、实测（10/19–10/23 全市场闭卷）

### 1. 趋同度是最强的单一过滤器

| 趋同度 | 入局笔数 | T+1 | 答案组 T+1 |
|---|---|---|---|
| 0.00~0.30 | 199 | **+2.37%** | **+22.96%** |
| 0.30~0.45 | 90 | +0.65% | +14.34% |
| 0.45~0.60 | 44 | +0.03% | +11.73% |
| **0.60~1.00** | 382 | **−0.33%** | +11.92% |

**趋同 60% 以上，T+1 直接转负。** 这就是"大家都异口同声了，出现的就是诱多"。

### 2. 温度 × 趋同交叉

| 组合 | 笔数 | T+1 | 胜率 |
|---|---|---|---|
| 温<40 + 趋同<0.45 | 189 | +1.82% | 43% |
| 温40~52 + 趋同<0.45 | 67 | +1.00% | 67% |
| **温≥52 + 趋同0.45~0.60** | 26 | **−1.78%** | **24%** |
| 温≥52 + 趋同≥0.60 | 382 | −0.33% | 44% |

### 3. 带头价值分档

|---|---|---|---|

| 口径 | 笔数 | 当日收盘 | T+1 | T+1胜率 |

| 加趋同闸门前·入局 | 715 | +0.99% | −0.03% | 46% |

## 七、必须承认的三件事

1. **可下单只剩 5 笔（5 天）**。趋同闸门（≥0.65 且温度≥55）很严，10/20 全天只入局 3 笔——因为那天是普涨日，没有分歧就没有超额。这是"宁可不做"的代价，不是 bug。
2. **答案覆盖掉到 22/48（46%）**。拦掉的很多后来也涨了（因为普涨），但它们的 T+1 期望是负的——**"涨了"不等于"能赚"**。
3. **饥饿度在这 5 天里几乎没有发挥作用**：只有 10/22 一天冰点，10/23 的 hunger 只有 1.13，对 RAR 的影响约 +1.6 分，不足以改变排序。机制已经就位（36 天宽度历史），但**要验证它必须跑更长的样本**，比如 8-10 月那 36 天。

## 八、下一步

1. 用 36 天日线 + 已有的分钟缓存跑"冰点后 1/2/3 天"的对比，验证"第一个包子最香"到底是第几天最香（可能是第 2 天，不是第 1 天）。
2. 趋同闸门目前是硬阈值（0.65/55℃），应改成连续惩罚：`persist -= 25 × max(0, consensus-0.5)`，避免边界跳变。
3. 面板接入 ATS 实时刷新（现在只有回放完成后刷新一次），让它成为盘中常驻视图。
4. `on_df` 的 vwap 现在依赖行情里自带字段，若上游没有，应改为用累计额/累计量现算。
