# 多显示器自动识别与均匀分布重排治理

## 背景与问题陈述
- **痛点场景**：
  - 用户日常使用 3 屏环境看盘监控异动；
  - 远程使用 Windows 远程桌面（RDP）查看异动时，Windows 将所有监控小窗口压缩挤压在同一个屏幕上；
  - 当切回本地 3 屏环境后，点击【重排】功能，小窗口仍然全部堆在同一个屏幕，用户不得不手动把窗口逐个拖到另外两个屏幕，体验极不友好；
- **目标要求**：
  - 优化重排功能，自动实时识别系统的多个屏幕；
  - 可以自动将小窗口均匀平分分布到各个屏幕上，彻底解决 RDP 导致全部挤在一屏的痛点。

---

## 根因定位与分析
1. **缺陷 1: 显示器列表未动态刷新检测**：
   - 原代码 `if not MONITORS: init_monitors()` 只有在 `MONITORS` 为空时才初始化；
   - 若系统在 RDP 下启动或运行过（此时显示器为 1 个），切回本地 3 屏后没有重新枚举显示器，导致程序依然误认为只有 1 个屏幕；
2. **缺陷 2: 按当前坐标归属分配导致单屏死锁**：
   - 原分配逻辑是读取每个小窗口当前的坐标 `(x, y)`，判断它目前在哪个屏幕上，就塞入哪个屏幕的列表；
   - 经历 RDP 缩屏后，所有小窗口的坐标都已经变成了主屏（Screen 0）内的坐标；
   - 结果重排算法认为所有窗口都“应该在 Screen 0”，把全部几十个窗口重新堆在 Screen 0，后排屏幕永远分不到窗口。

---

## 解决方案与改动实施
1. **显示器实时热检测与独立工作区精准适配 (`init_monitors`, `get_all_monitors`)**：
   - 每次重排前无条件调用 `init_monitors()` 重新调用 Windows API `EnumDisplayMonitors`，动态感知显示器插拔与 RDP 切换；
   - 获取每台显示器各自的 `Monitor` 物理区域和 `Work` 工作区区域，避开每个屏幕上各自的任务栏；
   - 按照物理 `left` 坐标升序排列（从左到右：Screen 0, Screen 1, Screen 2），保证屏幕顺序清晰稳定；
2. **多屏幕均匀切片分配算法 (Chunk Slicing) (`rearrange_monitors_per_screen`)**：
   - 当检测到有多屏（如 3 屏）且启用 `balanced` 模式时，将常规监控与策略报警小窗口均匀切分平分到每个屏幕（例如 10 个窗口平分到 3 屏为 4, 3, 3 个）；
   - 排在最前面的核心个股优先集中在第一屏/主屏，中排与后排分别在第二屏与第三屏，符合交易员看盘逻辑；
3. **RDP 缩屏自动自愈与配置交互**：
   - 自动检测：若检测到多屏环境但所有窗口当前都挤在单屏（典型 RDP 现象），系统自动触发均匀分布，一键铺满 3 屏；
   - 重排完成后自动写盘更新 `window_config.json`，方便持久化恢复；
   - 配置弹窗中增加 `[✔] 自动识别多显示器并均匀分布 (当前识别到 N 屏，解决RDP单屏问题)` 开关；
   - 右键菜单动态显示 `🚀 立即执行重排 (F6) [已识别 N 屏均匀分布]`。
