## 二、七大业务功能闭环逐项审核

### 1. ATS 时序可交易信号引擎闭环（Signal Timeline & State Machine & Premarket Profile）
- **业务闭环路径**：
  $$\text{宽表先验特征} \xrightarrow{\text{L0 盘前画像}} \text{门控分流 (PASS/WATCH/REJECT)} \xrightarrow{\text{L1 时间轴切片}} \text{L2 状态机确认 (2 bar 假突破过滤 + 2 bar 最短驻留)} \xrightarrow{\text{出场决策与分段加权}} \text{持仓账本对账}$$
- **核心实现与缺陷消除**：
  - **D1 跳空高开零信号**：新增 `GAP_BREAK_TRIGGER` 直通分支，抬高 `trigger_line`，根除高开时不进场静默停摆；
  - **D2 持仓泄漏**：规范 `open(code, ...)` 键匹配，引入 `PositionLedger.reconcile()` 孤儿仓位对账清理；
  - **D3 账本必选依赖**：强制内置账本，消灭不传账本时卡死在 HOLDING 的隐患；
  - **D4 逼近触发僵死**：增加 `ARM_STALE` 距离超时淘汰机制；
  - **D5 减仓收益失真**：实现分段加权盈亏核算 `realized_pct_weighted`；
  - **H1 bar 长度热改隐患**：落地 `TimelineHub.apply_bar_seconds()`，热改时强制清空重构；
- **测试验证**：`tests/test_signal_timeline.py` (16项)、`tests/test_signal_state_machine.py` (18项)、`tests/test_premarket_profile.py` (22项)、`tests/test_signal_integration.py` (4项)、`tests/test_signal_regressions.py` (16项) **全部 100% 纯绿秒级通过**。

## 三、审核中发现的潜在隐患与加固建议

在全量测试排查过程中，发现 1 项真实存在的环境残留隐患和 4 项测试层面的边界问题：

1. **【P1·真实潜在隐患】`_is_ats_shutting_down()` 对陈旧 `.ats_closing` 标志文件的自愈判定**：
   - **机理**：若 ATS 进程曾被操作系统意外终止，`G:\.ats_closing` 标志文件可能残留（写入了历史死进程 PID）。由于当前代码只做 `os.path.exists(closing_flag_file)` 判真，导致系统在后续启动时可能一直被误判为“正在退出中”，阻断单窗口正常除名；
   - **建议改进**：在 `_is_ats_shutting_down()` 读取到文件时，检查文件内记录的 PID 是否真实存活，或文件最后修改时间是否超过 60 秒；若属于陈旧死文件，则自动清理并返回 `False`，实现完全自愈。
2. **【P2·单测 AST 注入环境命名空间】`tests/test_tk_runtime_performance.py`**：
   - 测试通过 AST 单函数提取执行时，向命名空间注入了 `module datetime`，而源码使用 `from datetime import datetime` 期望的是类对象，导致测试运行 `datetime.now()` 报错。建议测试更新传入 `datetime=datetime.datetime`。
3. **【P2·测试函数收集命名冲突】`tests/test_concept_ranking_and_hits_fix.py`**：
   - 引用了业务函数 `from stock_logic_utils import test_code_against_queries`，因函数名包含 `test_` 被 pytest 误收集为用例导致 fixture 缺失。建议改为别名导入。
4. **【P2·测试 Mock 结构缺失属性】`test_ats_snapshot_ipo_memory.py` 与 `test_system_linkage_gateway.py`**：
   - 测试内部构造的 mock harness/owner 缺失了 `_closing` 与 `_ipc_sync_state_lock` 属性，建议在 mock 对象中初始化默认值。
5. **【P3·Windows 内存盘虚拟驱动兼容】`webTools/window_manager/bridge_token_usage.py`**：
   - 在内存盘路径下，`path.resolve()` 调用的 Windows 底层 API 可能会因驱动限制抛 WinError 1。建议用 `path.absolute()` 代替 `path.resolve()`。
