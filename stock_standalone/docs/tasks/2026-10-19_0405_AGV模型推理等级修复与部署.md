# AGV 模型、推理等级自适应修复与部署

## 原因及实机证据

- AGY 1.4.2 当前账号目录包含 Gemini Flash High/Medium/Low，以及没有独立等级的 Claude Sonnet/Opus Thinking；GPT-OSS 继续排除。
- 旧桥对不带等级后缀的模型静态赋予 low/medium/high/xhigh/max，导致 Claude 收到不支持的 `--effort high`。
- 同账号短标记对照：Claude Sonnet 不带 effort 返回 SUCCESS 和正确标记；带 high 返回 ERROR：`--effort is not supported for model "claude-sonnet-4-6"`。

## 修复及审核

- 根据实时 `agy models` 的 ID/显示标签解析可用档位；未声明独立档位的模型公布 `auto`，调用时省略 `--effort`。沿用现网 API 的 efforts 数组契约，无 API 运行代码或数据库变更。
- Web 模型列表继续合并为模型家族；Gemini 显示目录实际存在的等级，Claude 显示模型默认。恢复偏好、切换 provider、目录刷新、提交研究均在入队前解析真实模型变体与等级。
- 已移除的等级优先在同一家族中选择仍可用档位；整家族消失才回退目录中的可用模型。不会向 CLI 注入未公布等级。
- 任务入队后模型/等级已冻结，桥禁止暗中改变，避免触发结果回传配置不一致的 HTTP 400；旧的不合法任务明确失败并提示刷新。
- 实际发布目标是 easy-stock-web；easy-stock-analysis/frontend 仅同步相关兼容修复，不能代替前者部署。
- AGV 三处 CLI 入口统一启用已有隐藏控制台机制；审核中发现 stdout/stderr 读取线程退出未关闭管道，已补充关闭及句柄回归断言。
- 审核结论：上述发现均已修复，当前无未解决的阻断级代码问题。生产状态与完整发布验收以本文后续记录为准。
