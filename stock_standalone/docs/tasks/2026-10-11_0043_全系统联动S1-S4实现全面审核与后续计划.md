- 位置：[service.go:601](D:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/stock-strategy/source/easy-stock-analysis/backend/internal/linkage/service.go:601)、[单请求超时:270](D:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/stock-strategy/source/easy-stock-analysis/backend/internal/linkage/service.go:270)。
- 问题：一个 worker 顺序处理最多八条，每条网络超时可达四秒；多个离线目标会阻塞后面的在线目标，单机回环约四秒的记录不足以证明混合节点 p95≤5秒。
- 修复要求：使用小规模有界并发和节点公平调度，保留同操作/节点幂等与独立结果，不引入大型消息中间件。
- 验收：至少两个离线节点、两个在线节点与持续新增混合压测，分别记录排队、保存、UI 消费和行情等待时间。

### R13. 消费版本仍混用内存 version，缺行情/来源级版本定义【静态确认】

- 位置：[instock_MonitorTK.py:7739](D:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/instock_MonitorTK.py:7739)、[轮询发布:11728](D:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/instock_MonitorTK.py:11728)、[ATS sidecar 合并:main_window.py:4584](D:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/ats/ui/main_window.py:4584)。
- 问题：发给采集/sidecar 的 `linkage_favorites_revision` 使用 manager.version，回执又使用 persistent_revision；进程重启和不同消费者的数值没有同一语义，无法据此证明同一关注版本已被完整消费。
- 修复要求：明确持久化关注版本、行情批次版本、源时间和消费者游标；缓存失效与 ACK 比较分别使用对应字段，避免同名不同义。
- 验收：TK/ATS/采集进程分别重启、重复通知、迟到批次和关注删除后旧行情到达，均不回退投影或误报就绪。

## 7. 必须新增的验收矩阵

| 场景 | 应验证的不变量 |
|---|---|
| GET 后远端 remove_all，POST 返回 409，再同步两轮 | 不复活删除，不提前推进已消费游标 |
| 同来源离线增删、人工固定与自动来源退出 | 更新版本的人工意图受保护，remove_source 不扩大为 remove_all |
| TK/ATS 同时 ACK、heartbeat 与 ACK 交错 | 两端成功都保留，旧 pending 不覆盖新 ACK |
| 持久化后立即崩溃、ACK 丢失、Go/网关/ATS 独立重启 | 保存标记可恢复，旧新增不重加用户后来删除的股票 |
| 两端 synced 但 pending_fetch，之后补到行情 | Go/Web 都能收敛到真实行情结果 |
| ATS 停止超过五分钟后启动 | 不重新执行过期新增，允许已提交操作补消费状态 |
| UI dispatcher 阻塞/刷新异常/采集端未应用 | synced 不能由关注文件存在推断 |
| 两 workspace × 两节点 × 同 source_id | 不串工作区，不覆盖同类证据，来源冲突可见 |
| 同日过期、跨日、future/unknown 时间、Web 断线 | 原始 freshness 不被汇总或缓存刷新洗新 |
| ETF/指数/未知/错交易所/目录缺失 | 所有新增入口一致拒绝；合法历史项仍可删除 |
| context 慢、events 失败、证据积压 | 关注状态链独立工作，不依赖行情成功 |
| 旧 UI 入口批量关注、文件锁竞争/磁盘错误 | 主线程不做耗时写入，失败可见且文件保持可恢复 |
| 多离线与在线目标混合 | 在线节点不被离线目标长期阻塞，部分成功互不撤销 |
| 事件产生一天后回放、超过快照数量上限 | 事件对应原始证据仍可查，回放不读取未来数据 |
| 干净 checkout 构建与测试 | 所有必要用例、源码、配置模板和构建 SHA 一致 |
