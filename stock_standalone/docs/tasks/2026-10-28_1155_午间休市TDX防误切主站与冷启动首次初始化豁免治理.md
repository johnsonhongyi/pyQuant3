## 2. 根因剖析与穿透破案

### 根因一：午间休市 TDX 停盘口被误判为“主站假死”并引发连锁二分拆包轰炸
- **交易所与 TDX 行为**：交易所 11:30~13:00 为法定午休时段，通达信主站暂停向客户端推送实时盘口快照，`get_security_quotes` 接口返回空列表 `[]`；
- **原有工程漏洞**：`ats/tdx_realtime_fetcher.py` 的 `_get_security_quotes_safe` 当收到空批次时，未检查 `is_trading`（在午间休市或非交易时段）：
  1. 累加空批次计数 `self._consecutive_empty_batches += 1`；
  2. 触发健康探针（向 TDX 请求 000001 盘口，因休市同样拿不到盘口）；
  3. 系统错误判定主站假死，调用 `auto_failover()` 切换节点；
  4. 切换新主站后因休市依然返回空，于是启动递归二分拆包探针，将 40 只股票拆成 20、10、1 只向服务器反复发请求；
  5. 每次请求失败后，还将正常的股票代码全部加进 `_unlisted_or_dormant_codes` 僵尸代码黑名单！

### 根因二：跨日旧增量在非交易时段未被物理淘汰，导致冷启动展示昨日旧数据
- **原有逻辑**：`TDXGlobalCachePool.get_incremental_intraday` 将淘汰旧增量的逻辑误包在 `if is_trading_active and entry_date < self._current_date_str:` 中；
- 当在非交易时段（如午间休市、早盘 9:00 前、周末）冷启动时，`is_trading_active` 为 False，旧缓存（日期为昨日 `entry_date < self._current_date_str`）未被淘汰，反而被判定为 `is_after_close` 命中，直接 frozen 返回，导致冷启动看到昨天的旧数据。

### 根因三：SBC 集中调度器缺少全系统标准的“冷启动首次加载豁免”
- 全系统其他核心模块（如 CapitalDragonEngine 等）均具备 `cold_start` 机制：在首次启动时，无论是否处于休市或非交易时段，必须豁免拦截强制穿透拉取一次最新数据；
- `SBCGlobalDispatcher._run_loop` 原先在非交易时段只要 `revision == last_served_revision` 就直接休眠 30 秒，导致冷启动打开窗口时没有进行首帧穿透加载。

### 根因四：走势图各周期模式数据提取缺失现价兜底，导致副标题显示“现价 0.00”
- `_do_fetch_chart_data` 中，在 3d/5d/10d 以及 K 线模式中，代码只对 `op/vw/hi/lo` 做了缺省提取，漏掉了 `p = float(df_multi.iloc[-1].get("close", op))`；
- 且多日分时和 K 线把开盘价写成了 `iloc[-1].get("open")`（误取最后一分钟的分钟开盘价，而非全天开盘价 `iloc[0]`）；
- 最终导致休市时 snapshot 盘口为空时，`p` 恒等于 `0.0`，副标题展示 `现价: 0.00元 (+0.00%)`。

## 3. 治理与重构实施细节

### 3.1 彻底建立非交易时段/午间休市保护机制
修改 `ats/tdx_realtime_fetcher.py`：
- 在 `_get_security_quotes_safe` 的空批次分支增加 `if not is_trading:` 保护守卫：
  1. 重置 `_consecutive_empty_batches = 0`；
  2. 坚决禁止触发 `auto_failover()` 切换节点；
  3. 坚决禁止启动深度二分隔离探针与高频网络请求；
  4. 坚决禁止将正常标的误加进 `_unlisted_or_dormant_codes` 黑名单；
  5. 优先从 `_off_hours_cached_quotes` 复用有效定盘数据。

### 3.2 跨日旧增量严密物理淘汰
修改 `TDXGlobalCachePool.get_incremental_intraday`：
- 只要已跨入新交易日（`entry_date < self._current_date_str`），无论是否在交易时段，昨日旧增量坚决物理淘汰，绝不误判为 `is_frozen`；
- 若今天属于交易日且时间已过 09:30，增量分时若未包含今日数据，坚决物理淘汰并放行重新拉取今日数据。

### 3.3 权威自愈快照构建与冷启动无缝衔接
修改 `ats/tdx_realtime_fetcher.py`：
- 新增 `_build_fallback_snapshot(code, circ_wan)`：当盘口接口因休市或冷启动未返回报价时，自动从日线或分时权威数据提取当日收盘价格与指标；
- `fetch_stock_snapshot` 与 `fetch_batch_stock_snapshots` 全面接入该自愈机制，即使盘口暂停，仍能秒级获得真实收盘快照。

### 3.4 SBC 全局集中调度器冷启动首次加载豁免
修改 `ats/ui/intraday_strategy_dialog.py`：
- `SBCGlobalDispatcher._run_loop` 引入 `initial_loaded_codes` 集合；
- 凡存在未完成首次加载的标的（`has_pending_cold_start = any(c not in initial_loaded_codes for c in codes)`），100% 豁免非交易时段休眠，强力穿透执行首次初始化装载；
- 装载完成后记录至 `initial_loaded_codes`，再进入正常休眠。

### 3.5 走势图全周期模式现价与开盘价绝对兜底
修改 `ats/ui/intraday_strategy_dialog.py`：
- 多日分时（3d/5d/10d）与 K 线模式正确从 `iloc[0]` 提取开盘价 `op`，并补齐从 `iloc[-1]` 提取现价 `p`；
- 在 `_do_fetch_chart_data` 结束前加入全模式终极兜底：
  `if (p <= 0.001 or op <= 0.001) and df_target is not None and not df_target.empty:`
  确保从 `df_target` 最后一根 Bar 提取真实 `p`，彻底消灭标题栏与副标题 `现价 0.00`。
