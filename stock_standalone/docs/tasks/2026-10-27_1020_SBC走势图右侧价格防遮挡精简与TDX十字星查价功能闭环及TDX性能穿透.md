# 任务记录：SBC 走势图右侧价格防遮挡精简、TDX 十字星查价闭环及 TDX 性能瓶颈根因穿透

## 1. 任务背景与核心诉求
1. **SBC 右侧价格被遮挡**：SBC 走势图右侧的价格与基准线标签（如 `目标:12.`、`VWAP:12.`、`开盘:12.`）因右边距过窄且字符过长被右边缘截断；
2. **通达信同款十字星查价**：未点击时（鼠标在图表上悬停/移动），显示十字星光标与虚线，并在右侧价格轴实时显示当前选择位置的价格（对齐 TDX 灰白底黑字框），移出自动隐去；
3. **TDX API 严重性能问题根因穿透**：排查实盘日志中 `[NextDayWatch][ATS_TDX]` 频繁出现 `elapsed=1500~3500ms` 以及 `quote_gaps` 暴增（`quotes` 骤降至 30~50）是 Clash 问题还是代码问题。

## 2. 深入排查与实施改动

### 2.1 SBC 右侧价格标签精简与防遮挡优化
- **右边距扩展与安全呼吸区**：`MARGIN_RIGHT` 由 `52px` 调整为 `58px`，现价高亮标签框宽度 `p_box_w` 由 `52px` 优化为 `54px`；
- **分时走势图基准线标签精简**：
  - `开盘:12.31` -> `开:12.31`
  - `目标:12.68` -> `目:12.68`
  - `VWAP:12.45` -> `均:12.45`
  - 多日 VWAP 保持 `1D:12.44`、`5D:12.20`、`10D:12.20`；
- **K 线模式基准线与通道标签精简**：
  - `上轨/中轨/下轨` -> `上:/中:/下:`
  - `支撑/反转/开盘/目标` -> `撑:/转:/开:/目:`
- **效果**：所有右侧标签字符宽度压降 30%~45%，在 58px 区域内留有充足呼吸边距，彻底告别文字被右边缘裁剪遮挡。

### 2.2 通达信同款十字星查价功能对齐
- **免点击实时悬停激活**：
  - 在 `mouseMoveEvent` 与 `paintEvent` 中，当鼠标指针落在主图或副图有效区域（`_hover_pos`）时，自动激活十字星光标与双向虚线；
  - 移出画布（`leaveEvent`）自动恢复 `ArrowCursor` 并清除十字星与价格浮动，保持图表清爽无残留；
- **右侧价格轴精准对齐 TDX 选择价格**：
  - 水平虚线跟随鼠标当前 Y 坐标 `my`；
  - 精确反算光标物理高度对应价格：`p_selected = max_p - ((hy - mt) / mh) * (max_p - min_p)`；
  - 右侧价格刻度轴绘制 TDX 同款明亮灰白底色（`#E2E8F0`）+ 黑色加粗字体胶囊框，实时显示光标选择位置的绝对价格；
- **保留完整键盘锁定与当时数据 HUD**：
  - 无论分时还是 K 线，光标下方对齐 X 轴时间标签，左/右半区自适应悬浮展示开高低收、涨跌幅、成交量等当时数据 HUD；
  - 双击锁定/解锁与键盘左右方向键漫游功能 100% 向下兼容。

## 3. TDX API 严重性能问题根因穿透分析

根据实盘日志穿透排查，发现了四大核心诱因：

### 诱因一：60 秒冷却周期与单票重试的雪崩放大效应（最直接的波动源）
- **现象**：日志中 `quotes=31~60`（即丢失 60~85 只股票）、耗时飙到 2000~3500ms 的现象，**严格每隔 60~64 秒出现一次**（如 09:48:52、09:49:52、09:50:56、09:52:00、09:53:04、09:54:08...）；
- **根因**：
  1. `ats/tdx_realtime_fetcher.py` 中 `cooldown_sec = 60.0`；
  2. 当某些标的由于停牌/退市/代码异常在批次中未能返回时，代码会将其加入 `_unlisted_or_dormant_codes` 并冷却 60 秒；
  3. **整整 60 秒一到，冷却过期**，这批异常代码重新混入批次，导致整个 40 只标的的批次被通达信服务端拒绝返回或超时；
  4. 代码在 `missing_in_chunk` 中触发了**循环逐一单票重试**（`for c_m in missing_in_chunk: api.get_security_quotes([(mkt, c_m)])`）；
  5. 几十个标的连续单票网络请求，每次 50~100ms，直接导致当轮耗时被拉长至 3 秒以上；重试 4 次失败后再次进入 60 秒冷却，于是接下来的 60 秒内正常，60 秒后再次雪崩！

### 诱因二：昨天（10-26 20:51）引入的 `stock_live_strategy.py` 全量五档快照与分时 K 线抓取
- **根因**：
  1. `_fusion_refresh_depth(fetch_list)`：每 15 秒向 TDX 抛出几百只股票的快照请求；
  2. `_fusion_intraday`：若同进程内存未命中，退回 `fetch_intraday_bars`（单次拉 240 根 1 分钟 K 线），每轮预算最多抓 24 只股票；
  3. 导致 TK 进程在抓分时与五档，ATS 进程在抓 NextDayWatch 116 只行情，两端高频向同一个通达信主站发送大量请求，极易触发服务端的连接级防爬限流。

### 诱因三：Clash 规则中缺少通达信专用端口直连
- **根因**：
  1. 当前 Clash 规则主要是针对特定 IP-CIDR（如 `223.112.100.0/24`）和域名；
  2. 但通达信券商主站有数十个动态 IP，一旦主站自动切换到未包含在 CIDR 里的新 IP，若 Clash 开着 TUN 或规则模式，7709 端口的 TCP 数据包会被当作未命中规则而走代理节点；
  3. **解决建议**：在 Clash 规则中前置增加通达信专用端口绝对直连：
     ```yaml
     - DST-PORT,7709,DIRECT
     - DST-PORT,7711,DIRECT
     ```
