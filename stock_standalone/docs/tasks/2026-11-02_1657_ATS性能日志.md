# ATS 性能日志

## 开启

从项目目录启动主程序：

```powershell
python .\run_ats.py --perf-log
```

打包后的 ATS 程序也可追加 `--perf-log`。该参数只作用于 ATS 主界面，不修改 `global.ini` 或全局日志级别；正常启动不带参数时不记录性能日志。兼容环境变量 `FUSION_PERF_TRACE=1`。

## 路径与保留

日志写入运行根目录的 `logs/performance/ats_perf_<PID>.log`。运行根目录由 `sys_utils.get_app_root()` 决定：优先采用有效的 `INSTOCK_APP_ROOT`，否则按打包或开发环境定位；权限不足时无法创建日志。

每个 PID 的日志使用 2 MiB 轮转、保留 3 个备份（约 8 MiB）；同一 PID 的较早数据会被轮换覆盖。不同进程产生独立文件，程序不会自动清理旧 PID 的文件，长期使用时应按磁盘空间手动归档或清理。

记录通过有界队列异步写入；队列满时丢弃新记录，正常退出时尝试写入丢弃数。退出时最多等待 2 秒，强制终止或写入超时可能丢失尾部记录。

## 字段和适用范围

- `shadow_read_ms`：影子日志读取及快照；`aggregate_sort_ms`：行聚合与排序。
- `worker_wait_ms`、`worker_ms`：后台任务等待和执行时间。
- `prepare_ms`、`qt_ms`、`sort_ms`、`wall_ms`：表格准备、Qt 更新、排序和总墙钟时间；`qt_ms` 包含排序。
- `data_age_ms`：最新影子记录的年龄，依赖源记录时间和系统时钟。
- `ui_event_lag_ms`：约 10 秒一组的 Qt 定时器延迟采样；窗口隐藏、最小化或贴边休眠时不采样。采样值不等同鼠标点击或滚动延迟。

事件循环采样只有在打开融合梯度看板且窗口可见时产生；部分阶段仅在发生对应刷新时记录。性能日志不是完整测试报告，也不记录 TK/ATS 进程的 CPU 与内存；可配合 `tools/measure_strategy_ui.ps1` 采样。
