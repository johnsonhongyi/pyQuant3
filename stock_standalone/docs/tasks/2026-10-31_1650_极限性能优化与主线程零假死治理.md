# 异动扫描极限性能优化与主线程零假死工程治理

**日期**: 2026-10-31 16:50  
**模块**: `stock/testpy/tdxgui/异动联动.py`, `tests/test_rearrange_policy_customization.py`  
**分支**: `feature/signal-fusion-ladder`

---

## 1. 现象与底层根因剖析

### 1.1 现象
用户反馈在点击【▶ 测试弹出/报警】时，整个异动主窗口及所有小窗口出现长达数秒的“假死”无响应状态，并关切实盘中是否也会因扫描而导致卡顿。

### 1.2 根因分析
1. **慢速 `df.iterrows()` 阻塞主线程**：
   - 全天异动表长达 4600+ 行，原逻辑使用 `df.iterrows()` 逐行转为 `pd.Series`，在 UI 主线程耗时高达 1.5 ~ 2 秒；
2. **`get_stock_eval_dict` 缺乏批量上下文与重复 I/O**：
   - 扫描循环对数百只候选股票逐一调用 `get_stock_eval_dict`；若全局变量未预载，单只股票就会尝试调用网络快照 `_get_sina_data_realtime` 或磁盘 `_get_tdx_data_df`，在主线程同步累计耗时数千毫秒；
3. **测试扫描与 UI 强耦合**：
   - 测试按钮的回调直接在 Tkinter 主事件循环线程内同步执行全量大表扫描与评估，导致 Windows 消息泵（绘制、点击、定时器）全面停摆，产生假死。

---

## 2. 极限性能优化落地方案

1. **彻底废除 `iterrows()`，向量化提取 `df_by_code`（耗时从 1800ms 降至 2ms，提速 900x）**：
   - 使用 Pandas 向量化筛选与 `.to_dict(orient='index')`，一次性提取所有未监控标的的最新异动事件。
2. **构建批量评估上下文快照 (`get_bulk_eval_context`) 与单批次哈希缓存**：
   - 预先单次提取全市场数据源引用，扫描循环中单次获取开销仅 0.001ms，彻底杜绝循环内重复网络/磁盘 I/O。
3. **盘中实盘候选池切片保护与快速短路**：
   - 存活自动弹出窗口达上限时 0ms 快速短路返回；实盘非强制测试时，候选池优先检查最新 100 只活跃异动，杜绝整日 4000+ 历史记录循环。
4. **后台 Worker 线程异步扫描架构 (`is_async=True`)**：
   - 【▶ 测试弹出/报警】与繁重计算 100% 移入后台守护线程并发执行；
   - 按钮显示 `⏳ 扫描中...` 并暂时禁用防堆叠；
   - 主界面、异动流、小窗口全程 100% 丝滑响应，0 卡顿 0 假死；
   - 扫描完成后通过 `root.after(0, ...)` 异步回调主线程创建窗口。
5. **事件循环空闲帧分帧重排 (`after_idle`)**：
   - 窗口创建后通过 `root.after_idle(rearrange_monitors_per_screen)` 分帧排布，绝不在当前计算帧同步阻塞渲染。
