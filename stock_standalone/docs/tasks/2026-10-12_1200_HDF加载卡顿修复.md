# HDF 轨迹加载慢调用修复

## 定位
- `load_h5_all_30` 对应 Sina._load_hdf_hist_unified 调用 load_hdf_db，对 sina_MultiIndex_data.h5 的 all_30 整表加载；不是每只股票的单独读取。
- 本机只读文件属性显示轨迹库为 136,666,826 字节，约 130 MiB。原 5198.85 ms 仅为总耗时，不能据此认定全是磁盘读取或文件锁等待。
- 原冷缓存加载在调用线程同步执行，其他冷缓存请求等待同一个 Event 最长 60 秒；主线程调用时会阻塞界面。
- safe_load_table 和 load_hdf_db 在索引已经唯一时仍执行布尔筛选，产生不必要的整表复制；缓存深复制还占用共享缓存锁。

## 修改
- UI 主线程冷缓存请求启动单次后台加载并返回带 freshness=loading 的空结果；正在加载时 UI 不等待 Event，后台恢复和聚合调用者继续保留同步等待行为。
- 异步线程启动失败清理加载标记并唤醒等待者，返回错误状态；get_real_time_tick 保留空结果的状态元数据。
- 索引唯一时跳过两次不必要的全表布尔筛选，重复索引仍沿用原有 first/last 处理规则。
- 缓存深复制移至缓存锁外，减少其他缓存访问者等待；不取消 HDF 文件锁或改变历史数据范围。
- 增加 hdf_open_lock_all_30、hdf_read_table_all_30、hdf_index_dedup_all_30、hdf_cache_copy_all_30 的阈值日志，以及全局锁等待日志。

- 两个修改文件 AST 解析和 git diff --check 通过；未读取生产 HDF 内容、未运行测试或打包程序。
- 新包确认首次打开轨迹时界面可操作，后续刷新显示后台加载结果。
- 收集新增分段 SLOW 日志，区分打开/锁等待、整表读入、索引去重和缓存复制；当前未量化实际性能提升。
- 既有旧缓存返回策略保持兼容，首次冷加载会短暂为空；界面需要后续刷新才能获取完整数据。
