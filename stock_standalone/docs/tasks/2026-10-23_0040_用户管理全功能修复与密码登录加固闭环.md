# 2026-10-23 00:40 用户管理全功能修复(CRUD)+密码可见性与登录容错加固闭环

## 1. 任务背景与核心痛点
- **用户反馈**：
  > “修复用户管理,添加了用户无法登陆提示密码不对,而且无法添加的用户密码,及修改删除,
  > johnson · 管理员
  > lili · 普通用户,新加的用户无法登陆,无法增改删”
- **根因穿透**：
  1. **CRUD 接口严重残缺**：
     - 后端 `web_auth.go` 仅支持 `GET`（读取列表）和 `POST`（新增用户），**完全缺少 `DELETE /api/auth/users`**（导致前端根本无法删除用户），**完全缺少角色修改接口（`PUT /api/auth/users`）**；
     - 之前重置密码接口逻辑受限，重置密码后未清理失败登录锁定计数，且前端缺少行内操作入口；
  2. **新加用户登录提示密码不对**：
     - 密码输入框为盲盒 `type="password"`，缺少密码明文显示/隐藏切换（Eye/EyeOff）与确认密码校验机制，用户极易因大小写锁（CapsLock）、空格或输入法误输而不自知；
     - 后端在登录防暴破 key 中转了小写 `strings.ToLower(...)`，但在数据库查询时使用了原始大小写精确匹配 `WHERE username=?`，导致用户名大小写差异时直接查空，进而报 401“用户名或密码错误”；
     - 频繁试错触发防暴破 5 次阈值后，账号/IP 遭锁定 15 分钟，即使输入正确密码也报错误。
  3. **前端缺少操作入口**：
     - 用户列表仅以纯文本静态展示 `<li>{u.username} · {u.admin ? '管理员' : '普通用户'}</li>`，完全没有角色调整、行内重置密码、删除用户的按钮。

## 2. 改进实现与设计原则

### 2.1 后端加固 (`source/easy-stock-analysis/backend/internal/httpapi/web_auth.go`)
- **放行方法与统一接口**：
  - `/api/auth/users` 放行 `GET`（列表）、`POST`（新增）、`PUT`（修改角色）、`DELETE`（删除用户）；
  - 支持从 JSON body 或 Query 参数（`?id=X` 或 `?username=xxx`）提取目标用户；
- **大小写容错与防暴破自愈机制**：
  - 用户名查询统一采用大小写不敏感匹配：`WHERE LOWER(username)=LOWER(?)`，彻底根除因大小写不一致导致的登录失败；
  - 引入 `clearUserFailures(username)`：在用户新增、修改或重置密码成功后，立即清理该用户可能存在的失败重试计数，解除 15 分钟锁定，使用户能立即用新密码登录；
- **核心安全防线**：
  - **默认主管理员保护**：用户名是 `johnson` 或 ID==1 的系统主管理员**绝对禁止删除**，且**管理员权限绝对禁止被取消**；
  - **防自删与防误操作**：管理员不可删除自身登录账号，不可取消自身的管理员角色；
  - **级联清理**：删除用户时开启数据库事务，同时注销其所有历史会话（`DELETE FROM web_sessions WHERE user_id=?`）。

### 2.2 前端全面交互升级 (`source/easy-stock-web/src/components/AuthGate.tsx`)
- **密码可见性切换组件（`PasswordInput`）**：
  - 登录表单、添加用户表单、重置密码、修改本人密码所有密码输入框均配备眼睛图标按钮（`Eye` / `EyeOff`），随时一键查看明文，100% 杜绝因不可见盲盒输入导致的密码错误；
- **现代化表格与完整 CRUD 闭环**：
  - **用户列表表格**：清晰呈现用户名、身份角色标识与操作区；
  - **角色一键调整**：非主管理账号可点击一键在【管理员】与【普通用户】之间切换；
  - **行内快捷重置密码**：点击行内【重置密码】直接展开带眼睛图标的新密码输入框，输入后一键提交；
  - **安全删除确认**：对非 `johnson` 且非本人的用户提供红框删除按钮，点击前二次确认（`window.confirm`），确认后即时删除并刷新用户列表；
  - **添加新用户卡片**：提供用户名、初始密码、确认初始密码（实时比对两次一致性）、管理员角色勾选框；
  - **修改本人密码**：原密码、新密码、确认新密码。

## 4. 普通用户移动端 (iPhone Safari) 刷屏闪烁与登录占位符安全加固
1. **普通用户刷屏闪烁根因**：
   - 普通用户登录后，页面组件拉取只读联动信息 `GET /api/v1/linkage/targets`；
   - 原后端 `authorizedLinkage` 误将非 peer 浏览器的读操作也强加了 `authorizedLinkageAdmin` 校验（要求 `u.Admin == true`），对普通用户直接返回 `401 Unauthorized`；
   - 前端网络拦截器侦听到 401 即 dispatch `stock-auth-required`，而旧代码直接暴力 `setStatus(undefined)` 销毁整棵 React 渲染树；紧接着 `refresh()` 成功又重新挂载，挂载后又发起 targets 请求再次 401，形成每秒数十次的卸载/挂载死循环，在 iPhone Safari 表现为疯狂白屏闪烁；
2. **彻底解决与双保险**：
   - **后端放行与语义规范**：`auth.go` 放行所有已登录 Web 用户读取联动 targets/context/events 等只读信息；`server.go` 约束权限不足时返回 `403 Forbidden`，绝不返回 401；
   - **前端防闪烁与防抖**：收到 `stock-auth-required` 时绝不粗暴清空 `status`，而是静默核验 `/api/auth/status`，仅在确认会话真正失效时才切换视图，并设置 3 秒防抖门限；
3. **消除用户名信息泄露**：
   - 彻底移除了登录输入框和添加用户输入框中临时写入的示例提示 `（如 johnson / lili）`，保持 `placeholder="请输入用户名"` 纯净，杜绝用户名枚举与信息泄露风险。
