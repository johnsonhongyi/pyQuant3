# 全系统重点关注与数据联动闭环实施

## 范围与版本边界

本记录覆盖 pyQuant3 仓库中的 `stock_standalone` Python/TK/ATS 代码；该子目录当前没有独立 `.git`，版本边界沿用上层 pyQuant3 仓库。Go/Web 代码与版本状态记录在 stock-strategy 独立仓库的同名任务文档。本次不创建或迁移 Git 历史，也不跨仓库复制源码。

为使来源一致性回归随 Python 项目版本管理，仅在上层 `.gitignore` 为 `tests/test_global_favorites_linkage.py` 添加例外；其他测试忽略规则不变。

实施范围为审核方案 S1–S4：SBC 关注命令桌面落地、共享上下文、证据事件和双向来源化关注状态。策略采纳（审核方案 S5）不在本次范围内，不改变交易准入、风控或执行行为。

## 已实施

- `global_favorites.py`：跨进程互斥、重读后合并增量、原子持久化、来源和操作标记、revision 与删除 tombstone，保留本机旧调用接口。
- 旧整集合兼容保存按持久 revision 做乐观并发检查，拒绝过期进程快照，防止跨桌面撤销后被旧值复活；退市自愈删除来源并记录全局 tombstone。
- `system_linkage_gateway.py`：内网 JSON 网关、签名校验、SQLite 收件账本、操作幂等/重试和分项桌面回执；进程重启后可恢复已落盘关注，避免重复写入。
- `system_linkage_context.py`：只读共享上下文缓存和证据 outbox；提供 TK 竞价/异动、ATS 龙头/新股、Instock 候选证据的日期、新鲜度和覆盖范围。
- TK：在已有收盘筛选完成后发布 Instock 配置候选样本；重点关注的行情状态使用当前内存行情和采集时间判断，缺失、过期、休市与就绪分开展示；回执工作限制为单个后台线程。
- TK 行情采集：受限市场列表之外的关注股经原有 Sina Python 客户端只读补采，单批最多 128 只并轮转；最多缓存 512 条关注行情，状态与行情进入独立队列字段。
- ATS 行情显示：新增本机 26670 `UPDATE_LINKAGE_QUOTES` 旁路，发送时最多 128 行、周期重送供重连恢复；ATS 在 Qt 线程合并展示缓存，不并入 `current_df`，也不发送给策略/新股消费者。关注表按主行情与旁路各自的新鲜度选价，缓存状态缺失时重新判定；没有报价的已有行显示 `--`，不沿用旧价格。
- ATS：消费关注变化并回报保存、界面同步和行情状态；共享上下文在 Qt UI 线程展示，补充 Instock 候选状态。
- 原 pickle IPC 保留本机用途；新 JSON 网关不开放宏、脚本或交易执行入口。

## 复审补充

- 多进程回归实际启动 4 个 Python 子进程并发增删关注，覆盖新增不丢失、同股多来源、删除 tombstone、持久 revision 和操作去重标记；本进程内多线程写入也由管理器级锁串行化。
- SBC 来源统一为 `stock-strategy.sbc`，桌面入口校验 `stock-strategy.` 命名空间；未过期的不确定重试复用原命令正文和 ID。
- 桌面关注文件将工作区点号来源 ID 映射为兼容的本地来源键，并在写出/投影时往返映射；已撤销来源对应的延迟 UI 命令不会重新加入额外监控列表。
- Instock 合法空结果发布 `candidate_count=0` 快照，避免中心继续展示上一份同日候选；TK 竞价、ATS 新股和 TK 异动事件只接受同交易日新鲜证据。
- K 线标的切换会重建关注面板实例，避免上一标的的回执串显到当前标的。
- 追加回归覆盖旧快照写入拒绝、启动退市自愈的来源清理/tombstone，以及退市清理 JSON 原子替换；发现并修复该自愈写入此前以二进制模式调用 `json.dump`、导致替换始终失败的问题。

## 边界与待验收

- 关注只扩展现有监控范围，不会自动形成策略信号或下单指令；交易准入、持仓、风控和执行入口保持既有实现。
- 生产网卡地址、Docker 到 Windows 的路由、实际配置目录和在线目标仍需现场核验；本地实现与离线测试不代表 LAN 验收完成。
- S5 策略采纳需独立回放、模拟和专项审核，不由本次关注与证据联动自动启用。
