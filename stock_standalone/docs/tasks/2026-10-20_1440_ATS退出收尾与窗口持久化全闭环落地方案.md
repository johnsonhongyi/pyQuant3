## 一、 现场故障与用户痛点定性

用户在运行并关闭打包后的 `ATS_Terminal.exe` 时遭遇以下连续异常：
1. **SBC 子进程退出超时强退，ATS 退出未完成需点两次**：
   ```text
   [10-20 13:18:06] WARNING:sbc_launcher.py: 持仓盯盘进程 (PID=11528) 等待超时，执行 terminate
   [10-20 13:18:07] ERROR:sbc_launcher.py: 非安全退出 PID=11528 forced=True saved=False returncode=1
   2026-10-20 13:18:07,022 [ERROR] SBC safe shutdown not confirmed: ['SBC shutdown or persistence was not confirmed']
   2026-10-20 13:18:07,094 [ERROR] ATS final cleanup failed: ['subprocess cleanup: drain failed']
   ```
   **用户特征**：“手动提前关闭盯盘 sbc 就没有任何问题”，表明卡点在 ATS 托管 SBC 的回收链路与退出的并发冲突上。
2. **多窗口并发退出原子保存冲突（WinError 5 拒绝访问）**：
   ```text
   [save_window_position_qt] 原子保存失败: [WinError 5] 拒绝访问。: '...window_config.json.tmp' -> '...window_config.json'
   ```
   多个子窗口在 `closeEvent` 中并发调用 `save_window_position_qt`，写死同一个 `.tmp` 文件导致重命名竞争死锁。
3. **PyInstaller 运行时临时目录锁定**：
   ```text
   [PYI-10576:WARNING] Failed to remove temporary directory: G:\Temp\_MEI105762
   ```
   SBC 启动的 `LinkageProcess`（`ATS_Terminal.exe --multiprocessing-fork`）作为孤儿进程残留，持有打包解压的 DLL 句柄导致目录无法清理。
4. **退出时没有正确关闭并持久化打开的所有窗口**：
   用户关闭 ATS 时，`daily_limit_up_dialog`（连板天梯）等窗口由于 `parent=None` 无法找到主窗口实例，误将其当成用户单独手动关闭窗口，在 `closeEvent` 中写入 `is_open: False`，导致下次启动无法按预期恢复。同时 `intraday_ui_layout.json` 存在写入空列表或被非 6 位股票代码（如 `__holdings_launcher__`）污染的问题。
5. **盘中 301666 增量分时 7 秒自动驱逐死循环**：
   盘中未到 14:50 收盘时，增量分时最高分钟未达 14:50 被误判为缺失完整性，每 7 秒驱逐历史分时静态缓存，耗费大量 CPU 与磁盘 I/O。

## 二、 核心根因穿透与全量代码修复

### 1. 彻底解决 Windows 文件锁冲突 (`tk_gui_modules/window_mixin.py`)
- **根因**：原 `save_window_position_qt_visual` 使用固定文件名 `tmp_file = config_file_path + ".tmp"`。在 ATS 退出时多窗口同时触发 `closeEvent`，多个线程/进程同时写入或替换同一个 `.tmp` 文件，触发 Windows 独占锁异常 `[WinError 5]`。
- **修复**：
  - 临时文件改用进程 PID 与线程 ID 唯一命名：`f"{config_file_path}.{os.getpid()}.{threading.get_ident()}.tmp"`；
  - 增加 5 次带指数退避的重试机制，若替换失败安全清理自身临时文件，彻底消灭 `WinError 5 拒绝访问`。

### 2. 深度回收子孙进程与防污染 (`ats/ui/sbc_launcher.py`)
- **根因**：
  - 原 `_sbc_bootloader_children` 只按命令行参数严格匹配主进程，无法识别由 `linkage_service` 派生的 `--multiprocessing-fork` 孤儿进程；
  - `get_running_codes()` 混入了 `__holdings_launcher__` 内部虚拟标识。
- **修复**：
  - 扩展 `_sbc_bootloader_children` 深度遍历子孙进程树，凡是执行路径匹配 `expected_exe`（或 python 运行 `run_sbc.py`）的子孙进程一并纳入管理；
  - 在 `_close_launcher_subprocess` 终止超时后，不仅杀死主子进程，还递归强杀所有残留的子孙孤儿进程；
  - `get_running_codes()` 增加严格验证：`len(k) == 6 and k.isdigit()`，过滤所有非标准股票代码。

### 3. 分时窗口反误清空与退出性能优化 (`ats/ui/intraday_strategy_dialog.py`)
- **根因**：
  - ATS 退出时，若 ATS 进程内未持有一级分时窗口（由子进程持有），`save_all_open_sbc_windows()` 曾将 `sbc_open_windows` 直接覆盖为 `[]` 空列表，导致下次启动丢失窗口记忆；
  - 单个分时窗口在退出循环中重复写入磁盘与 Windows 注册表，造成 11 次重复写盘和 55 次注册表写入。
- **修复**：
  - `save_all_open_sbc_windows` 增加反清空保护：当内部列表为空时，保留既有合法 6 位股票代码；杜绝写入非 6 位代码；
  - `SBCIntradayChartDialog.closeEvent` 检测到系统退出（`is_app_exiting` 或 `_is_ats_shutting_down()`）时，跳过单窗口冗余持久化，由批量管线统一持久化。

### 4. 彻底修复子窗口退出时误设 `is_open: False` (`daily_limit_up_dialog.py` 等)
- **根因**：
  - `DailyLimitUpDialog` 往往以 `parent=None` 独立顶层窗口实例化；其内部 `_get_main_app()` 尝试 `self.parent()` 和 `app.main_window` 均返回 `None`；
  - 当 ATS 整体退出时，子窗口收到 `closeEvent`，由于判断不到主窗口正在退出，错误执行了 `self._save_window_state(is_open=False)`。
- **修复**：
  - 升级 `_get_main_app()`，优先寻找 `_py_parent`，并遍历 `app.topLevelWidgets()` 准确识别 `ATSMainWindow`；
  - 在 `closeEvent` 中检查环境变量 `os.environ.get("ATS_IS_CLOSING") == "1"`，只要是 ATS 系统级退出，强制保持 `is_open: True`，确保下次启动完美还原全部已打开窗口；
  - 同步为 `dragon_monitor.py`、`hot_sector_leaderboard.py`、`chart_widgets.py` 补齐环境变量与退出标记判断。

### 5. 跨进程联动服务优雅退出消除 `_MEI*` 临时目录锁定 (`main_window.py`, `run_sbc.py`)
- **根因**：`linkage_service.get_link_manager()` 会在后台启动 `LinkageProcess` 和通信线程。在 ATS/SBC 退出时，如果未显式停止该 Manager，进程在系统层退出时可能被系统挂起或滞留，导致 PyInstaller 单文件解压目录 `_MEI*` 中的 DLL 无法被安全删除。
- **修复**：
  - 在 `ATSMainWindow._complete_shutdown` 和 `run_sbc._finish_sbc_packaged_shutdown` 中显式调用 `linkage_service.global_manager.stop()`，优雅关闭跨进程队列与线程；
  - 移除 `_complete_shutdown` 中对 `close_all_sbc_processes()` 的重复调用，消除逻辑竞争。

### 6. 盘中增量分时对齐校验修复 (`ats/tdx_realtime_fetcher.py`)
- **根因**：`_ipo_frame_alignment_issue` 针对所有交易日均要求分时必须覆盖到 `14:50`。在交易日未收盘（如 14:18）时，该硬性条件必然失败，导致缓存池每 7 秒将标的从 `_history_static_bars` 中驱逐并重构，引发巨量 I/O 与抖动。
- **修复**：放行当天尚未收盘的增量分时：`day == calendar_today and not is_today_after_close`，杜绝盘中死循环驱逐。
