# ATS联动管道刷屏与早盘卡顿极限性能优化

## 背景与痛点
在 2026-10-23 实盘交易早盘监控中，操盘手反馈 ATS 出现明显的卡顿甚至假死，同时日志出现高频刷屏：
```log
2026-10-23 12:23:35,812 [WARNING] ATS watchlist status could not reach TK pipe
2026-10-23 12:23:40,808 [WARNING] ATS watchlist status could not reach TK pipe
2026-10-23 12:23:45,824 [WARNING] ATS watchlist status could not reach TK pipe
2026-10-23 12:23:50,811 [WARNING] ATS watchlist status could not reach TK pipe
2026-10-23 12:23:55,826 [WARNING] ATS watchlist status could not reach TK pipe
2026-10-23 12:24:00,944 [WARNING] ATS watchlist status could not reach TK pipe
```
原设计意图是用于打通 Web/策略端与桌面本地的自选股双向状态回执闭环（`WATCHLIST_HEARTBEAT`）。但经深入排查发现以下严重的性能黑洞与主线程绑架：

1. **Qt UI 主线程 CPU 绑架（黑洞 1）**：
   `_send_linkage_heartbeat` 挂在 5 秒间隔的 QTimer 上，直接在 UI 主线程执行。每次调用 `_linkage_heartbeat_quote_status()`，对自选股中最多 512 只股票进行全量循环，并在全市场几千行庞大的实时行情 `current_df` 中做行检索 `frame_quote_row`，还要比对时间戳、调用 `cct.get_last_trade_date()` 512 次。
2. **`frame_quote_row` 致命的 $O(N)$ 全表扫描（黑洞 2）**：
   `frame_quote_row` 中把 `if "code" in frame.columns:` 置于 `if code in frame.index:` 之前，导致每次查询都对整表执行 `frame["code"].astype(str).str.strip().str.zfill(6) == code` 的全列字符串变换和过滤。512 只股票 × 5000 行 = 2,560,000 次字符串匹配，导致早盘行情跳动时主线程直接卡死掉帧。
3. **`send_code_via_pipe` 找不到管道时硬等待 2.5 秒（黑洞 3）**：
   在 `data_utils.py` 中，当 Named Pipe 不存在（`ERROR_FILE_NOT_FOUND`）时，循环 5 次且每次 `time.sleep(0.5)`，导致后台线程单次调用被阻塞整整 2.5 秒，占用 50% 线程时间。
4. **日志高频报警刷屏（黑洞 4）**：
   在管道未建好或单机独立运行时，`_linkage_receipt_worker` 每 5 秒必定打一条 WARNING，污染交易日志。
5. **盘中 500ms（0.5秒）高频自选股轮询（黑洞 5）**：
   `_poll_favorites_loop` 在交易时段将轮询间隔缩短到 500ms，在已有 listener 监听的情况下造成无意义的盘中空转。

## 优化方案（KISS / SOLID / 零主线程阻塞）

1. **`data_utils.py` & `data_utils1.py`**：
   - 优化 `send_code_via_pipe`：遇到 `ERROR_FILE_NOT_FOUND` 立即退出（`break`），绝不执行 `sleep(0.5)` 重试，耗时由 2500ms 降为 0.1ms；
   - 遇到 `ERROR_PIPE_BUSY` 时，等待超时由 1000ms 优化为 100ms，快速释放。
2. **`system_linkage_quotes.py`**：
   - 优化 `frame_quote_row`：优先进行 `frame.index` 的 $O(1)$ 哈希命中；
   - 若必须通过 `code` 列检索，避免每次都全列调用 `.astype(str).str.strip().str.zfill(6)`，优先直接匹配或使用轻量切片。
3. **`ats/ui/main_window.py`**：
   - **心跳降频与主线程剥离**：
     - 心跳定时器由 5 秒降频为 60 秒；
     - 主线程 `_send_linkage_heartbeat` 优化：`_linkage_heartbeat_quote_status` 提取外部公用时间日期，采用短路求值（一旦检测到前序标的为 `ready` 立即短路返回，无需遍历 512 股）；
   - **管道不可达退避与日志抑制**：
     - `_linkage_receipt_worker` 中未连通管道时降为 DEBUG 日志，且加入 300 秒抑制（Suppression）机制；
     - 未连通管道时丢弃队列中陈旧的心跳，防止队列积压与反复重连；
   - **盘中自选股轮询降频**：
     - `_poll_favorites_loop` 盘中间隔由 500ms 优化为 15000ms（15秒），彻底消除半秒一次的空转。
4. **测试与回归**：
   - 编写专门的自动化测试 `tests/test_linkage_performance_and_suppression.py`，验证短路求值性能、管道 0ms 快速失败以及日志抑制生效；
   - 确保现有测试全部通过，无语法错误。
