# 每日实盘后的上下文沉淀与自动交接（session_ctx）

日期：2026-10-25 20:40｜分支：`feature/signal-fusion-ladder`

## 用户的架构纠正（三条合起来是完整设计）

1. "不需要再叠加更多分时数据，没有实际意义，底层的日线数据都有，叠加最近五日的分时数据即可……
   从来不是分时数据长度的问题，只是策略及 code 的默认状态没有很好的定位导致的。"
2. "需要更新的是每日实盘后的数据上下文能力，之前没有每日的实盘的上下文，
   每日自动持久化之前的上下文才可以更好的优化结构；
   数据底层基座就是在上下文缺失后使用上面的数据基座和 5 日分时数据构建最近的上下文，
   每日自动迭代交接才是正确的架构设计。"
3. "何况还有各种的数据库信号、记录都是构建最新上下文的基础，
   最近的热点板块、轮动、资金情况、市场温度等等都是上下文一部分，
   每次自动更新迭代交接，才能反复验证有效性。"

因此本轮**不扩分时长度**，改建"每日上下文 → 快照 → 交接"的闭环。

## 实现：`ats/fusion/session_ctx.py`（新）

| 能力 | 入口 | 说明 |
|---|---|---|
| 收盘沉淀 | `SessionContextStore.close_day(day, ...)` | 温度曲线/宽度、阶段路径、资金量能、热点板块与轮动、先锋存活、入局与可下单计数、冰点天数与饥饿度、信号账本计数 |
| 原子落盘 | `save()` | `logs/fusion_state/session_ctx/<day>.json`，tmp + `os.replace`，保留 120 天 |
| 缺失重建 | `rebuild_day(day)` | 快照不在时用日线基座（`MarketHistory.seed_from_daily`）+ 5 日分时代理重建，`source="rebuilt"` 可区分；基座也没有就返回 None，**不编数** |
| 自动交接 | `handoff(day, n)` / `render_handoff()` | 给次日盘前"最近 N 日上下文"：连续冰点天数、饥饿度、上一阶段、上一日宽度/温度/量能、反复出现的板块、哪些是重建的 |
| 信号账本 | `ledger_summary(day)` | 读 `logs/signal_snapshots/signal_ledger_latest.json.gz`；**日期不符返回空**，不把 10/22 的账记到 10/23 上 |

缺失语义：任何一组取不到就进 `missing` 列表并写 None，调用方必须能看出"这是缺的"，不用 0 冒充。

## 接线点（三处，全部异常隔离）

1. **`live_bridge.on_df`**：帧时间 ≥15:00 且当日未沉淀 → 自动 `close_session(day, frame)`；每日只沉淀一次。
   同时新增 `_update_phase()`（有温度历史才推阶段，没有就只记宽度/资金）与 `_capital_hist`（每帧全市场成交额 → 资金冲锋号）。
2. **`replay.DayReplay.run()`**：收盘时同样沉淀（阶段路径来自回放内的 `MarketLifecycle`，资金来自 `CapitalGauge`），
   使"缺失重建/上下文交接"在离线环境可验证。
3. **`pipeline.render()`**：日报最前面加"上下文交接"摘要——每日自动迭代的入口。

## 风险与未完成

1. **实盘上下文仍缺温度**：主应用的 `logs/market_temp_history.json` 目前只到 10-15，回放里温度来自横截面自算。
   实盘链路要等 `on_df` 真正接上行情回调后才有每日温度序列。
2. **热点板块只在有帧+主题图谱时才算**；回放路径未传 `frame`，故快照里 `themes` 记 missing（已在 missing 中如实标注）。
3. **阶段路径在实盘侧依赖温度历史**，没有温度就只记宽度/资金——这是故意的，不猜温度。
4. 信号账本是"最新一天"快照语义，只能覆盖最近一个交易日；要按日归档需主应用侧配合（`daily_summary_*.json.gz` 已有按日文件，可作为下一步数据源）。
