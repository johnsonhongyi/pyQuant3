# Vis手动触发推送与盘后全量同步闭环修复

## 任务背景与问题分析
用户反馈：
“审查今天codex修复的tk审核补修Vis原有触发与周期恢复，保护IPC确认并发及盘后语义 这里没有保护好原有的vis设计的功能,打开vis,在关闭vis可以触发一次后端的主动推送,但是现在是否这个功能失效.正常业务逻辑是关闭vis,在打开vis,或者打开的vis,在关闭vis,在打开vis,会触发一次数据推送,应该有已发送 UPDATE_DF_ALL (rows=5541, payload_bytes=35359880, wire_bytes=35359888, ver=1, connect_send_ms=25.7)... 下面的日志是没有开启vis,打开vis后触发了一次, 后面反复操作都没有触发,是因为版本没有变动所以没有重复触发?还是逻辑没有闭环.”

## 根因穿透与分析结论

1. **“是因为版本没有变动所以没有重复触发吗？”**
   - **结论：不是版本没有变动的锅。**
   - 证据：在 `instock_MonitorTK.py` 中，当触发显式全量同步（`_force_full_sync_pending=True` 或 `explicit_sync_pending=True`）时，`MarketStateBus.get_latest_dual(since_version=-1)` 强制读取当前权威快照；同时 `content_requires_send` 在 `explicit_request=True` 时无条件返回 True 放行，即便版本和数据内容 100% 相同也允许强制重发。

2. **“还是逻辑没有闭环？”**
   - **结论：是的，确实是逻辑没有闭环，存在 2 处致命断链！**
   - **致命断链 1（UI 事件断裂）**：
     - 在 `instock_MonitorTK.py` 第 9068-9075 行主界面控制栏 `frame_right` 中，所有的 Checkbutton 统一循环赋予了 `command=self.update_linkage_status`。
     - Codex 在前次重构时，把 `update_linkage_status` 内部原本关于 Vis 开关触发同步的代码全部抽离，但**只在设置弹窗 Tab2 绑定了 `_on_vis_toggle`，主界面的 Checkbutton 漏绑**！
     - 用户在主界面日常点击 Vis，永远只调用空的 `update_linkage_status`，根本没调用 `_on_vis_toggle`，导致请求在 UI 层完全未发出！
   - **致命断链 2（盘后 10s 退避与 `deferred_port_sync` 冲突吞噬显式请求）**：
     - `request_immediate_ipc_sync(owner)` 之前未清零 `_last_full_try_{port}`，也未从 `_deferred_port_sync` 中移除已请求端口。
     - 发送循环第 10736 行有 `now_ipc - _last_full_try_{port} >= 10.0` 检查，用户 10 秒内的连续操作会被此判断拦截。
     - 一旦被拦截，第 10756 行 `elif has_daily_update and not is_work_time: deferred_port_sync.add(port)` 错误地将显式请求端口加进了盘后延迟集合。
     - 盘后（`not is_work_time`）第 10142 行根本不会消费 `deferred_port_sync`，导致显式请求不仅被吞，该端口在盘后还会永久休眠！

## 实施改进

1. **`instock_MonitorTK.py`**：
   - 主栏 Checkbutton 创建循环修正：`cb_cmd = self._on_vis_toggle if text == "Vis" else self.update_linkage_status`，主栏 Vis 正确接入 `_on_vis_toggle`；
   - `_on_vis_toggle` 防御性加固与审计：补充用户手动开启/关闭日志（`logger.info("[send_df] User manually ENABLED/DISABLED visualization -> schedule FULL SYNC")`），清除暂存，触发 `request_immediate_ipc_sync`，并同步保存 UI 状态（`save_ui_states`）；
   - `send_df` 调度加固：第 10756 行补充 `and not is_forced_port`，防止显式请求端口被错误塞进盘后延迟集合。

2. **`tk_frame_fingerprint.py`**：
   - 加固 `request_immediate_ipc_sync(owner)`：显式即时同步在置位 `_force_sync_{port}` 的同时，将 `_last_full_try_{port}` 重置为 `0.0`，并从 `_deferred_port_sync` 中移除该端口，确保立即放行物理发送。
