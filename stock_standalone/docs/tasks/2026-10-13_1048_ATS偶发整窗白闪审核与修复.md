# ATS 偶发整窗白闪审核与修复

## 证据与边界

- 用户表现：运行一段时间后偶发整个内容区域短暂白闪，不是持续高频闪烁。
- 隔离 Qt 实验：全局 ToolTip 配色从 `#1a1a24` 切换为 `#14141f`，或反向切换，会触发已有 800×600 主窗口全区域重绘；相同配色重复设置不触发。
- 状态栏文本及样式更新实验只触发状态栏区域重绘。热力图排名交换会重建卡片，实验只观察到热力图区域重绘。
- ATS 内部恢复 SBC 使用 `as_subprocess=False`，与 ATS 共用 QApplication；外部独立 SBC 子进程不共享父进程调色板。
- 以上确认了可复现的全窗重绘触发路径，尚未捕获线上 Windows 白闪瞬间，不能将离屏测试等同于原生窗口验收。

## 实施

- `styles.py`：窗口主题只设置自身配色，显式传 app/None 才设置全局；相同配色、QSS 不重复赋值。
- `run_ats.py`：创建 QApplication 后、创建主窗口前初始化 ToolTip 配色。
- `run_sbc.py`：独立入口复用同一全局配色初始化函数。
- `main_window.py`：字号调整不再修改全局 palette。
- `intraday_strategy_dialog.py`：同进程 SBC 创建时只设置自身 palette，不再覆盖所有顶层窗口的配色。
- `heatmap_widget.py`：以板块名称复用卡片；排名、列数变化只移动，增删板块只增删对应卡片；相同文本、样式及最小高度不重复设置。
- 不使用整窗禁用更新、强制 repaint、透明背景或绘制属性覆盖；未变更行情、信号或交易规则。

## 验证与后续

- 19 项针对性测试通过：`test_ats_whole_window_repaint.py`、`test_sbc_signal_crash_regression.py`，以及 `test_ats_optimization_review.py` 中热力图复用和刷新合并两项。
- 验证弹窗主题不修改应用调色板且不触发宿主 Paint；100 次排名/数值更新不新增重复卡片或连接；新增、删除、改列数、强制刷新保留存续卡片及点击目标；删除卡片完成 Qt 延迟释放。
- Python 语法和 `git diff --check` 通过，测试使用 `QT_QPA_PLATFORM=offscreen`。
- 尚未重新打包，也未改动线上目录。打包后需验收同进程 SBC 与普通弹窗交替打开、热力图排名变化及长时间行情更新。
- 如仍白闪，应现场关联主窗口 Paint、PaletteChange、布局与原生窗口事件，再定位剩余触发源；不把本次测试结果表述为线上白闪已彻底消失。
