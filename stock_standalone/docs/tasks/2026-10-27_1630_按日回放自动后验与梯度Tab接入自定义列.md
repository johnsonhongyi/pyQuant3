## 1. 任务背景与核心诉求
用户在实盘与复盘使用融合梯度监视器（`FusionLadderDialog`）过程中，提出两项深层量化后验与灵活监控需求：
1. **按日回放中显示的是当时时间的涨幅？后面需要更新收盘涨幅，需要有自动后验的能力**：
   - 之前在「按日回放」Tab 中，仅展示了信号触发入局时刻的涨幅（例如 09:35 触发时的 `+2.36%`）；
   - 用户无法直观对比全天最终收盘时的绝对涨跌幅（例如收盘是冲上涨停 `+9.98%`，还是冲高回落 `+0.50%`）；
   - 需要具备自动后验（Post-Hoc Verification）能力，将全天最终收盘涨幅（终收%）与当时涨幅并列呈现，并提供详细的后验悬浮分析。
2. **梯度的 tab 都自动接入 ats 的 df 的自定义列功能，可以添加一个自定义列的开关，打开后 tab 可以自动显示自定义列功能**：
   - 顶部控制条增加一个「📊 自定义列」复选框开关（和极窄模式 `chk_narrow` 并列，支持跨会话配置持久化）；
   - 开启后，梯度的各个 Tab（实时梯度、按日回放、赛马跟踪）自动无缝接入 ATS 系统的 DataFrame 动态自定义列（`cct.ats_col`，如 `DFF`, `Rank`, `ch_bc2` 等，中文名称走 `cct.vis_column_map`）；
   - 数据源：从系统当前运行中的量化策略主 DataFrame（`SectorDataAggregator.resolve_active_strategy_df` / `current_df`）中动态提取并经由 `cct.format_col_value` 标准格式化；
   - 支持点击自定义列表头按照实际数值大小升降序排序；关闭复选框或在极窄模式下平滑隐藏自定义列。

## 2. 核心架构与工程实现

### 2.1 回放引擎自动后验（Post-Hoc Verification）数据链
- **底层指标精准计算** (`ats/fusion/replay.py`)：
  - 在 `DayReplay.run_day()` 中，通过 `mat["close"][i, -1]` 提取当日最终一分钟线收盘价 `_last_c` 与昨收价 `prev_close[i]`；
  - 精确计算当日最终收盘涨跌幅：
    $$\text{day\_close\_pct} = \left(\frac{\text{day\_close}}{\text{prev\_close}} - 1.0\right) \times 100.0$$
  - 在 `records.append(...)` 中显式持久化 `day_close` 与 `day_close_pct`，确保回放记录自带全天终收后验数据。
- **界面表头与多维对比呈现** (`ats/ui/fusion_ladder_dialog.py`)：
  - `_REPLAY_BASE_HEADERS` 升级为：
    `["时间", "代码", "名称", "现价", "涨幅%", "终收%", "级别", "RAR", "仓位%", "MFE%", "MAE%", "收盘%", "温度℃"]`
  - 列 4 为信号触发时刻「涨幅%」，列 5 紧邻展示当日最终「终收%」（红涨绿跌粗体）；
  - 单元格悬浮 ToolTip 提供三段式后验卡片：
    - 触发时间与入局涨幅；
    - 终收涨幅与全天收盘价；
    - 入局后收益率、最大浮盈（MFE%）、最大回撤（MAE%）；
    - 走势后验判定（持续冲高走强 vs 冲高回落）。

### 2.2 动态自定义列（`ats_col`）全链路接入与开关控制
- **标准 ATS 自定义列获取与映射**：
  - 接入 `cct.ats_col` / `cct.CFG.ats_col` 与 `cct.vis_column_map`；
  - 严格剔除表格已有的基础固定列（`BASE_EXCLUDE`），杜绝重复添加；
  - 表头名称自适应中文转换（例如 `dff` -> `DFF`，`win` -> `连阳` 等）；
  - 配备三段式深色卡片 ToolTip。
- **策略主 DataFrame 动态感知与数值提取**：
  - 通过 `_resolve_ats_strategy_df` 递归探测当前量化策略 DataFrame（`current_df` / `_last_flat_df` / `flat_df`）；
  - 在 `_extract_stock_custom_val` 中支持按 6 位纯数字代码及索引检索，并通过 `cct.format_col_value` 智能整型（`co2int` 如 `ch_bc2`）与浮点精度格式化；
  - 封装为 `NumericTableWidgetItem(value=val_txt, raw_val=val_num)`，支持表头点击按真实数值升降序排序。
- **自定义列开关与极窄模式智能解耦**：
  - 顶部控制栏增加 `QCheckBox("📊 自定义列")`，点击即时触发 `_apply_all_narrow_modes`；
  - 跨会话配置持久化（`fusion_ladder_show_custom_cols`）；
  - 当处于极窄模式时，无论自定义列开关如何，均收缩至极窄核心列；
  - 当退出极窄模式时，根据自定义列开关状态动态控制自定义列的 `setColumnHidden`，实现 0 闪烁、0 重复 I/O 的瞬时展开与隐藏。

### 2.3 赛马跟踪收盘涨幅归零根因彻底修复与点击表头高精排序
- **归零根因穿透**：
  - 在 `_get_batch_quotes_snapshot` 从 ATS 主窗口（`parent_window`）的 `current_df` 读取行情时，旧实现使用 `lc = float(row.get("last_close", row.get("close", p)) or p)`；
  - 由于策略 DataFrame 中 `close` 字段代表的是当日现价而非昨收，且未优先提取 `percent` / `pct` 涨跌幅列，导致 `lc` 错误取到了现价 `p`，计算 `(p - lc) / lc` 恒等于 `0.0`，进而导致批量行情快照将日内涨幅全部置零；
- **全链路权威涨幅四级梯队兜底提取**：
  1. 优先读取行情 DataFrame 中的权威 `percent` / `pct` / `change_pct`（例如 `+10.01%`, `+1.65%`, `+9.03%`）；
  2. 昨收价仅从真正表示昨收的字段（`lastp`, `last_close`, `prev_close`, `preclose`）提取，严禁使用 `close`；若昨收缺失但有现价与涨跌幅，通过 `p / (1.0 + dp / 100.0)` 精确反算昨收；
  3. 若快照缺失，从影子时间序列最后一根记录 `recs[-1]` 中获取实盘收盘快照涨跌幅（`day_close_pct`）；
- **点击表头按收盘涨幅数值升降序排序**：
  - 单元格将真实浮点数 `day_pct` 绑定为 `raw_val`（`_num_item(display_ret, day_pct)`）；
  - 点击表头「收盘%」时，`NumericTableWidgetItem` 严格基于真实的浮点收盘涨跌幅执行升降序排序（例如降序时涨停 `+20.00%`、`+10.01%` 稳居顶部，跌幅居前者沉底）。
