# 全市场信号融合与梯度执行层（SFL）设计与落地

> 日期：2026-10-23 22:10
> 触发场景：市场温度在 30~60 分钟内由低温直接翻转，数据流里大量标的率先启动、大单意图明确，但系统只输出"涨幅大了 / 放量了"，既没有"哪一个是低风险可参与"的集中结论，也没有任何分层执行梯度。
> 范围：设计 + 离线核心实现（未接入实盘链路，未修改任何现有交易行为）

---

## 一、结论先行

**问题不是数据不够，也不是模块不够多，而是缺一层"换算器"。**

现有系统已经具备：TDX 极速行情、ATS 的 SBC 底层、多级别 VWAP（日内 / 1d~5d / cum_2d~10d / SBC 支撑反转线）、盘口压强、外盘占比、攻角、分段净拉升、主力意图分、超短赛马、新股集中交易中心、情绪温度。

但这些能力被切成 9 套互不兼容的口径，每套只回答自己那一小段问题。于是：

1. **强度被当成了可参与度。** 涨幅、量比、攻角衡量的是"已经涨了多少、拉得多猛"，不衡量"现在买进去，止损有多近、上方还有多少空间、有没有人接"。
2. **跨源不可比，所以无法排序。** 9 套打分字段名与量纲都不同，最终只能退化成"谁涨得多谁先报"。
3. **风控是单阈值一刀切。** `bias > 5%` 一律否决，把"底部首次放量启动"和"连涨三天高位放量"当成同一件事，于是只有"能买 / 不能买"两档。
4. **执行层没有仓位维度。** ATS 自动调度固定 1000 股，信号状态机的持仓对象没有仓位字段，新股交易中心的 35%/15%/20% 只覆盖新股池。

所以本次不做新指标、不接新数据源，只做一件事：**在"所有信号"与"下单动作"之间插入一层 SFL，把连续的市场压成 5 档可执行的梯度，并给每一档绑定仓位、进场方式、止损锚、有效期与失效条件。**

## 三、设计目标与不可让步的约束

目标：
- G1 所有来源（天梯、龙头突击、超短赛马、SBC 反转、新股引擎、形态检测、竞价）输出**同一种事件**，可横向比较。
- G2 每个标的在任一时刻只有**一条**结论，包含级别、仓位、进场区间、止损、有效期、失效条件。
- G3 级别必须同时受**评分、温度阶段、先手时间**三重约束，任一不满足就降级。
- G4 结论可解释、可复算、可回溯（`evidence` / `invalidate` 必填）。

约束（对应 AGENTS.md 数据与安全不变量）：
- 不修改行情采集、不新增数据源、不改 HDF5/DB 契约。
- 过期、跨日、缺失数据不得伪装为有效信号，直接 L0。
- 本层默认 `shadow`（只读），不改变实盘下单行为。
- 单写者内存态，不引入新的跨进程共享与锁顺序。

## 五、四轴评分与风险否决

`RAR = 0.30·位置 + 0.25·承接 + 0.25·意愿 + 0.20·环境 − 惩罚`

| 轴 | 问的问题 | 子项与权重 | 说明 |
|---|---|---|---|
| 位置 `position` | 买在这里，止损多近、上方多少空间 | 止损距离 0.40 / 上行空间 0.30 / 日内位置 0.20 / 多周期 0.10 | 止损距离 2%~4.5% 最佳；<1.2% 易被扫，>6.5% 亏太多；日内位置 >0.85 显著扣分 |
| 承接 `support` | 拉上去有没有人接 | 外盘占比 0.30 / 买盘压 0.25 / 结构清晰度 0.25 / 站上均价时长 0.20 | 用"回踩不破"而不是"涨得快"来定义质量 |
| 意愿 `intent` | 拉升是否明确且持续 | 攻角 0.35 / 主力意图 0.30 / 净拉升速度 0.20 / 量比 0.15 | **刻意不用涨幅作为主变量**：涨幅是结果 |
| 环境 `regime` | 温度、板块、龙头配不配合 | 温度 0.55 / 板块共振 0.30 / 翻转状态 ±10~14 / 龙头 +8 | 翻转状态是唯一允许"提前量"的入口 |
| 惩罚 `penalty` | 会亏钱的东西 | 偏离均价>3% 起扣（上限 30）/ 涨幅7%+换手15% 扣 12 / 量比>4.5 扣 10 / 过热期非龙头扣 20 / 成交额<3000万 扣 15 | 上限 60 |

**否决器（直接 L0，不参与打分）**：行情缺失、数据过期 >20s、跨交易日、跌破底台、跌破 SBC 支撑、偏离均价 >7%、退潮期非龙头、成交额 <3000 万。

> 关键取舍：否决器刻意保持"少而硬"。如果什么都在这里拦，就又退回单阈值了。**追高由"偏离均价"惩罚 + 位置轴扣分 + 时间衰减三者叠加表达，而不是一刀切。**

## 六、五级梯度表（梯度的实体）

## 七、温度矩阵与翻转状态机

`ats/fusion/regime.py`

温度阶段 → (级别上限, 仓位系数)：

| 阶段 | 条件 | 级别上限 | 系数 |
|---|---|---|---|
| 冰点 | <35℃ | L2 | 0.50 |
| 偏冷 | 35~48℃ | L3 | 0.70 |
| 回暖 | 48~60℃ | L4 | 1.00 |
| 过热 | ≥60℃ 且斜率 <1.0，或 ≥72℃ | L2（龙头 L3） | 0.60 |
| 退潮 | 自峰值回落 ≥6℃ 且斜率 ≤−1.0 | L1 | 0.30 |

**翻转状态机**：`IDLE → ARMED → FLIPPING → CONFIRMED → FADING`

- `ARMED`（低位拐头）：温度仍 <48，但 5 分钟斜率 ≥+1.5℃/5min 且跌停 ≤8 家。此时上限 +1 档、系数 +0.10。
  **这是解决"等确认时已经涨上去"的核心机制**：提前把 L3 名额放开，允许先用 L2 试仓。
- `FLIPPING`（穿越 48℃）：斜率 ≥+2.0，系数 +0.15。
- `CONFIRMED`（涨停扩散）：温度 ≥55 且涨停家数 ≥ 前高 1.2 倍。
- `FADING`（退潮）：斜率 ≤−1.5 或封板率 <55%，上限压到 L1。

**重要修正**：过热不等于"温度高"，而是"升温趋缓/滞涨"。否则 30 分钟从 40℃ 冲到 61℃ 的加速段会被判为过热，正好在翻转窗口把仓位砍掉，与实战相反。代码中该判定已按此实现（`regime.py:_stage`）。

## 八、先手时间衰减（解决"看到就晚了"）

同一个标的，从本轮启动算起：

| 启动后经过 | 级别上限 | 仓位系数 |
|---|---|---|
| ≤10 min | L4 | 1.00 |
| ≤25 min | L3 | 0.85 |
| ≤45 min | L2 | 0.70 |
| ≤70 min | L1 | 0.50 |
| >70 min | L0 | 0.00 |

最终级别 = `min(评分级别, 温度上限, 先手上限)`。

这直接对应本次痛点：数据流**已经看到**大量率先启动、意图明确的标的，但系统没有把"先手"换算成"更高等级 + 更大仓位"。有了这一维，"第一个启动"和"第四个跟风"才在同一个坐标系里可比。

## 十一、校准闭环（梯度不能拍脑袋）

1. 每条 `FusionDecision` 落 `signal_message` 表（已有 `score/grade`，补 `tier/rar/axes_json`）。
2. 用 `live_signal_history.highest_after / lowest_after / status`（`trading_logger.py:78-196`）自动算 MFE/MAE，无需新增采集。
3. 按 tier 统计：样本数、胜率、平均 MFE、平均 MAE、盈亏比、平均持有时间。
4. 每 20 个交易日按**实际分位数**重标定 `RAR_TIER_CUTS`：L4 应落在历史前 10% 分位，而不是固定 82 分。
5. 样本 <30 的档位禁止上调仓位上限。

## 十四、风险与未决

1. **权重是先验**，未经历史分位标定。P1 影子期必须以实际分布重标，否则 L4 门槛可能过高或过低。
2. **温度样本依赖分钟级横截面**。当前 `market_pulse_db` 是状态发布，需确认能否稳定提供每分钟涨停/跌停/封板率；拿不到时退化为 `temp` 外部传入。
3. **L4 30% 需要组合级约束**。单票上限之外还需要"同板块合计上限"与"总仓位上限"，否则翻转日会同时给多只 L4。
4. **与 `ipo_trading_center` 的仓位表并存期间**可能出现同一票两套仓位口径，必须在一处收敛（建议交易中心查 LADDER，映射表保留只读）。
5. **T+1 物理约束不变**：L4 的分批在当日买入无卖出权时只影响加仓节奏，不影响退出规则。
