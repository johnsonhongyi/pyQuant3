# TK 与竞价面板内存排查

## 已确认来源
- 截图 2312.5 MB 是 5 个进程合计，不是 TK 单进程。
- 排查时主进程 PID 30836 RSS 约 1568 MB；PID 42240 约 700 MB，二者均运行 Nuitka EXE。
- 主进程文件映射驻留：trading_signals.db 约 288 MB，可执行映像约 270 MB；子进程可执行映像也约 270 MB。映射驻留含可共享页面，不应简单认定为独占堆内存或内存泄漏。
- G:/sina_MultiIndex_data.h5 文件约 163.4 MB。文件大小不等于 DataFrame 内存大小。
- 原路径：HDF 底层缓存保存大表副本，Sina 统一层保存读取返回的大表；两层可独立驻留同一代数据。
- 竞价 TickSeries 默认只保留 30 根分钟数据，起点历史最多 100 条；分钟缓存已用紧凑 NumPy。此次不裁剪历史或修改面板展示。

## 本次修改
- load_hdf_db 新增默认关闭的内部 _share_cache 参数，仅支持不做代码过滤、不做时效过滤的全量 MultiIndex 轨迹读取。
- Sina 统一缓存借用底层同一代只读数据，普通 HDF 调用仍返回独立副本；缓存命中、文件 mtime/size 检测、SingleFlight 与 UI 异步加载保持原路径。
- 写入同步产生的新缓存首次借用时通过独立副本规范空值，避免原地修改其他读取者仍持有的旧代数据。
- 共享轨迹由现有消费者只读；筛选、回放 reset_index 和聚合结果才可修改。回归覆盖输入未变及普通调用副本隔离。
- VWAP 保留累计计算顺序，只在各代码组末尾计算偏移和除法，去掉全长偏移与最终值数组及输入列副本。
- 不修改数据库缓存预算、实盘执行、风控、交易时间窗及历史保留长度。

## 应用边界
- 正在运行的 Nuitka EXE 不会加载本次 Python 源码修改，需要重新构建并重启后测量同一场景的进程内存。
- 尚未获得真实进程 Python 对象级占用清单，因此不把 2 GB 全部归因于 Sina，也不承诺固定 RSS 降幅。

## 后续深审修复与最终验证
- 复核曾发现两项缺陷：共享表被公开可写出口/索引规范化污染；仅清理统一层不能释放底层强引用。本节记录修复后的结论，不能用前一阶段的测试通过替代这两项检查。
- 公开 get_sina_MultiIndex_data 返回独立数据、行索引和列索引副本；普通 HDF 缓存读取也隔离索引底层数组。代码过滤根据实际 MultiIndex 处理，规范化仅修改临时 DataFrame 外壳。
- TK 两处历史恢复继续从内部统一缓存只读借用，reset_index/筛选后再修改，避免公开 getter 的全表保护副本额外进入内部高频链路。内部两层仍持有同一个 DataFrame。
- clear_unified_cache 同时释放两层及旧 GlobalValues 历史引用，保留 agg_metrics/lastbuy；支持指定表清理，不影响其他表或行情快照。
- 清理先取消对应 SingleFlight，再释放底层。读取代次及发布有效性检查阻止清理前已启动或延迟启动的任务回填缓存；被取消的旧任务也不能覆盖新任务的发布或删除新任务的加载状态。
- 冷启动 HDF 仍在后台线程加载，UI 返回 loading；加载失败释放 SingleFlight，下轮可重试。锁顺序为统一层锁到 HDF 缓存锁，底层发布检查仅读取 Event 状态，不反向获取统一层锁。
- 真实写入测试发现原有缓存同步缺陷：MultiIndex 的 append=False 实际落盘仍追加，但原缓存同步只保留新批次。现仅按既有 MultiIndex/rewrite 落盘规则同步缓存；物理写入逻辑未改。裁切/schema 自愈后失效当前底层缓存，下一次按实际磁盘结果重建。
- 最终 tests/test_tk_compact_memory.py：38 项通过，包括真实 SafeHDFStore 追加、append=False、rewrite=True 的原子持久化/缓存一致性/锁释放测试；全部文件位于 pytest 临时目录。
- 最终 tests/test_single_analyse_memory.py、tests/test_system_linkage_quotes.py、tests/test_tk_bidding_responsiveness.py（排除 live）：合计 44 项通过。
- 最终共 82 项针对性回归通过，UTF-8 语法及 git diff --check 通过；深审未发现本次改动中未解决的 P1/P2。未连接真实下单环境，未验证重新构建后的 Nuitka EXE 盘中行为及 RSS 降幅。

## 读写一致性复核后的修复
- 后续复核补充复现了旧链路遗留的两个问题：读取后处理期间写入提交，旧数据可被标记为新文件版本并覆盖缓存；重叠 Tick 的热缓存保留最新值、冷读却保留旧值。本节结论覆盖这些此前未测试的交错场景。
- Sina 历史缓存记录路径及 `(mtime_ns, size, inode)`，读取版本从实际打开的 HDF 文件描述符取得；发布时检查该版本是否仍对应当前文件，拒绝把旧句柄数据标记成新文件版本。
- 并发写入按同一 Sina 文件串行，保留现有跨进程文件锁；提交后、释放文件锁前同步缓存。读线程不等待写事务锁，Windows replace 重试期间仍可关闭读句柄；失败退出释放事务锁供下一线程重试。
- 写入前读取已有 Sina 文件的探测使用只读模式，避免空打开/关闭改变时间标记。文件创建、临时镜像、原子替换、rewrite 及其他 HDF 文件的写入模式保留既有路径。
- 缓存同步只能从匹配提交前版本的完整缓存推导追加结果，依据不足时失效并在下次读取实际文件；旧读被新提交取代时优先复用当前缓存，否则返回带 stale/error 标记的空结果。
- 统一层发布还验证底层 canonical 对象和文件版本；旧 GlobalValues 历史快照无版本依据，首次安全迁移到共享版本化缓存，不再把旧快照当成新读取。
- Sina `(code, ticktime)` 去重统一保留最后一条，覆盖冷读、代码筛选、输入批次及追加缓存；相同数值但不同 Tick 的记录完整保留。其他 HDF 表的原有去重规则不变。
- 同一 Tick 的价格/成交量变化仍写入，完全相同批次跳过写入；原随机采样时间判断之外增加整批内容校验，避免采样范围外的更改被遗漏。
- 本轮 tests/test_tk_compact_memory.py：57 项通过，覆盖读后处理/筛选与写入交错、上层延迟发布、双写串行、Windows 活跃读句柄、失败重试、独立进程保留 mtime/size 的原子替换、重叠批次/批内重复及同 Tick 更新、相同值不同 Tick 的无损保留。
- TK/竞价/行情联动与快照回归：44 项通过；HDF 锁与多表保留门禁：11 项通过。合计 112 项通过，语法/UTF-8 与 diff 检查通过，write_hdf_db 的公开签名保持兼容。
- 20ms 实时等待使原重试预算门禁偶发多一次尚未超时的尝试；仅将该测试改为确定性时钟模拟预算耗尽，未修改生产打开重试预算。
- 再次深审已检查文件版本、缓存所有权、锁顺序、取消加载、非只读写入及错误退出路径，未发现本轮改动中未解决的 P1/P2；缓存命中、共享大表及 VWAP 临时数组优化均保留。仍需构建并重启 Nuitka EXE 后验证盘中场景及 RSS。

## 裁切、上层版本校验和禁用 HDF 的补充修复
- 后续审核复现了此前回归未覆盖的三处遗漏：容量裁切丢失兄弟表；上层命中绕过文件版本且强引用旧表；写入包装器在禁用 HDF 时仍解析不可用路径。本节记录这些遗漏的修复与验证，不能用此前阶段的通过结论替代。
- 裁切先复制原 HDF 镜像，在临时文件中仅重写目标表，再沿用原子替换和重排流程；保留其他 table/fixed 表、兄弟表属性和文件属性。裁切失败仍回退原追加流程，裁切比例及各代码保留规则未变。
- 上层历史条目只保存路径、版本、时间和 Ready 状态，大表仅由底层缓存持有；每次命中检查路径与 `(mtime_ns, size, inode)`。底层已同步当前写入时直接借用新 canonical，不重读 HDF；文件变更、删除或切换路径时释放失效引用后后台加载，不继续返回旧表。
- 旧上层强引用条目可安全迁移为元数据，同时清除旧 GlobalValues 历史引用。仍在使用旧快照的调用方可以完成操作；上层缓存自身不再延长旧大表寿命，weakref 回归验证写入完成后无需下一次读取即可释放旧表。
- UI 对统一层/底层缓存锁均不阻塞等待，繁忙时返回现有 loading 状态；冷启动和实际 HDF I/O 仍在后台。写入大表合并移出缓存锁，发布时重新核对清理代次、对象身份及文件版本，既不在清理后复活，也不覆盖并行新读取已发布的结果。
- 句柄文件版本采集中的 PyTables fileno 操作纳入 HDF 全局锁；路径 stat 校验不获取 HDF I/O 锁，保持缓存命中的轻量路径与现有锁顺序。
- 禁用 HDF 时包装器直接调用原函数，保留原 DataFrame 返回及空值规范化契约，不解析 RAMDisk 路径、不创建写锁；公开写入签名不变。
- 本轮新增 15 项回归，tests/test_tk_compact_memory.py 共 72 项通过；HDF 锁及多表门禁 11 项通过，TK/竞价/行情联动/快照回归 44 项通过，合计 127 项。覆盖真实 ptrepack 后的兄弟表/属性保留、裁切失败回退、交易/非交易时段版本切换、保留 mtime/size 的替换、文件删除/路径切换、禁用 HDF、繁忙缓存锁、合并与清理/新读取交错，以及句柄版本探测的并发互斥。
- 项目 pytest.ini 固定 --basetemp=.pytest_temp；一次运行中临时目录意外消失，随后改用本次运行独立的系统临时目录，83 项缓存/HDF 回归全部通过。未修改项目测试目录策略。
- 最终复核覆盖重复 Tick、旧读/新写、清理代次、缓存所有权、UI 锁等待、非只读追加/rewrite、异常释放和公共签名兼容；UTF-8 无 BOM、AST 及 diff 检查通过。保留缓存命中、共享大表和 VWAP 内存优化；运行中的 Nuitka EXE 尚需重新构建、重启后验证真实盘中行为及 RSS，不能将隔离回归等同于成品运行验证。
