# 2026-10-28 任务记录：成交量30秒平滑自动更新、资金主线180秒性能隔离与SSOT同源闭环

## 一、 背景与业务目标

用户明确指示：
> **“需要逻辑对齐闭环，底部的成交量数据可以30秒自动更新，不能全资金主线高频的更新数据”**

核心矛盾与解决策略：
1. **资金主线不能高频更新**：资金主线包含全市场 5000+ 标的多维特征提取、加速形态过滤与板块资金强度等复杂计算，高频执行会导致严重的 CPU 争用与 UI 卡顿，频繁调用 TDX API 会有封禁风险。必须坚决维持原版 180 秒（3分钟）防护；
2. **底部的成交量数据 30 秒自动更新**：底部状态栏的大盘成交量数据仅涉及四大核心指数（上证、深成、创业板、北证）和全市总成交量、量比、较昨日变化，数据极轻量；
3. **逻辑对齐与 SSOT 闭环**：底部的四大指数与资金主线所展示的四大指数在计算算法、基准引用、量纲单位上 100% 同源对齐，杜绝数据割裂。

## 二、 根因穿透与架构改进

### 1. 底部成交量 30 秒轻量级平滑驱动（耗时 <0.1ms）
- 在 `CapitalDragonEngine.get_market_indices_and_volume_summary(df_all=cur_df, min_interval=30.0)` 中内置 30 秒轻量节流门禁：
  - 30 秒内（如每秒 UI 时钟触发）：直接返回已有的纯内存缓存，耗时 0 微秒，0 阻塞；
  - 跨越 30 秒：仅从 `cur_df` 中检索四大指数 4 行数据，完成极轻量计算并原子刷新缓存，耗时 <0.1ms；
  - 后台守护线程 `start_market_summary_bg_updater` 基准周期对齐为 30.0 秒，休市或冷启动时从权威日线提取收盘数据兜底。

### 2. 资金主线维持 180 秒防护，彻底实现性能隔离
- `CapitalDragonPanel` 维持 `get_cached_report(max_age=180.0, fallback_stale=True)`，坚决不高频重算全市场 5000+ 标的；
- 成交量的 30 秒高频刷新与资金主线的 180 秒深度计算在物理上完全解耦，互不干扰。

### 3. 三级数量级精准自适应（杜绝千亿大盘量级错乱）
- 穿透发现：大盘指数单日成交额高达数千亿（如上证 2800 亿）。若按个股规则 `raw_amt > 1000` 判定为万元，会导致 2800 亿元被误除 10000 变为 0.28 亿；
- 重构三大数量级门禁：
  - `>= 1e9`：判定为【元】（除以 `1e8` 转换为亿元）；
  - `>= 1e6`：判定为【万元】（除以 `10000.0` 转换为亿元）；
  - `< 1e6`（如 2800.5 亿）：判定为已是【亿元】，直接使用。

### 4. 算法与数据源同源闭环（SSOT）
- **量比科学推算**：优先读取 `vol_ratio`，次选 `volume`，若无则结合当前交易进度按 `cur_vol / (prev_vol * ratio_t)` 动态科学推算，兜底 1.0，绝不写死；
- **本地基准持久化**：引入 `market_yesterday_amount_benchmark.json`，即使网络延迟或日线未返回，始终能拿到昨日全天收盘基准；盘中时段精准呈现 `(较同期 ±xxx亿 | 虚拟 x.xx万亿)`，彻底根治 `较昨 0.0亿`；
- **资金主线同步**：资金主线每次 180 秒跑完一轮时，其四大指数产物亦会自动同步到此缓存，两端 100% 数据一致。
