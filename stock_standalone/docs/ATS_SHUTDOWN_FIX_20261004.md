# ATS 退出后控制台残留修复（2026-10-04）

## 问题与现场结论

- Nuitka 打包版运行数小时，先关闭新股检测中心和盯盘窗口，再关闭 ATS 主窗口，界面消失但控制台仍存在。
- 只读现场检查确认主进程已退出，PID 9536、11360 两个孤儿 multiprocessing 工作进程仍附着于同一控制台；通用启动参数无法确定其业务目标。
- 原退出流程没有统一等待子窗口提交的后台关闭任务；日志监听器和线程池的解释器退出等待也可能无限阻塞。

## 本次更新

- `ats/ui/main_window.py`：记录 IPO、次日盯盘关闭线程，等待这些线程与 SBC 关闭任务完成，再回收本进程拥有的 multiprocessing 子进程。
- `ats/shutdown.py`：增加共用期限的线程等待与子进程回收；遵循 multiprocessing 的正常退出策略终止仍存活的 daemon 子进程，等待非 daemon 子进程结束。
- `ats/ui/main_window.py`：退出收尾使用统一 30 秒期限，完成最终配置写入、评估档案保存或恢复日志落盘；失败或超时保留窗口及待保存状态，允许重试。
- `ats/shutdown.py`：仅在打包环境且上述收尾成功后启动 5 秒退出看门狗，在停止日志之前启用，避免日志或解释器收尾无限等待。
- `ats/next_day_watch_process.py`：闲置工作进程每 0.5 秒检查消息和父进程状态，父进程消失后执行清理并退出，避免继承的管道句柄让进程永久等待。
- `run_ats.py`、`ats/main_ats.py`：退出收尾完成后，不再由 `aboutToQuit` 重复创建档案保存线程。
- `tests/test_ats_shutdown_exit.py`：补充持久化、收尾失败、线程阻塞、孤儿进程和 daemon 子进程回收回归；`.gitignore` 增加该测试的跟踪例外。
