# ATS 内存优化验收（2026-10-09）

- 主因：TDX 单例默认恢复整份共享历史缓存。分配采样中，反序列化对象约 479.9 MiB，解压缓冲约 114.1 MiB，压缩缓冲约 24.2 MiB。
- 默认单例改为按需恢复；无历史订阅时不读整包，跨进程更新仅保留本进程已请求的标的。显式 `TDXGlobalCachePool()` 全量构造仍兼容。
- 分钟记录改为 `CompactBarRecords`：连续数值列、重复字符串字典编码、缺失字段位图；float64/int64 保留精度，大整数及异构字段原样保留。按行读取返回独立字典。
- 共享缓存继续导出旧版可读的普通 list/dict pickle；流式 zlib 读写避免整份压缩/解压/序列化字节缓冲常驻。保存时合并其他进程的标的，但不把它们留下作为本进程的常驻数据。
- 相同的增量 DataFrame 与短期缓存共用一个内部副本；对外读取仍返回副本。ATS 历史日收盘查询只选择 `close` 列。

## 针对性验证

- 3 项验证通过：精度/缺失字段/行隔离/旧 pickle 与 DataFrame 往返；未订阅时零解码、标的按需加载；选择性恢复后写盘保留其他股票且不扩大全部常驻缓存。
- 同一测试同时验证增量池和短期缓存共享 DataFrame，随后按需恢复其他标的。
- 2,400 条代表性分钟记录：递归对象内存 2,090,054 → 332,407 字节，减少 **84.1%**。此为数据结构基准，不代表全进程同比下降。
- 隔离、offscreen 主窗口构造后观察 8 秒：峰值 **168.2 MiB**，末尾约 **167.6 MiB**，无无关历史常驻；未启动实盘后端，禁用数据库加载及名称预加载，网络不可用。不与截图的实盘 exe 直接作同条件对比。
- 初始完整启动探测受现有环境的工作进程访问拒绝影响，未作为通过项；未运行无关功能或全量测试。
- Python 语法、UTF-8 无 BOM、差异检查通过；源码已实施，未重新打包或替换运行中的 exe。

旧共享文件为单体 pickle：首次按需读取和合并写入仍会短暂构造全包对象，随后释放无关标的；本次消除其默认启动加载、常驻膨胀和整包字节缓冲，没有修改共享文件格式。

## 数据兼容性复核

- 6 项针对性验证通过，包含新旧存档往返、独立解释器仅用标准库读取新存档、实际十日历史缓存重启后零网络复用。
- 新存档保持 zlib + 普通 pickle，版本号仍为 4；无需迁移或删除旧档，也不要求旧进程导入 `CompactBarRecords`。
- 补齐选择性写盘保留未订阅标的 VWAP 摘要；按更新时间和缓存代际合并，已清除的数据不会复活。
- 补齐清缓存时同步未加载标的及远端代际，验证指定标的代际 4→5 和全局清除落盘。
- 缺失字段与显式 None 区别、大整数、负零、Inf/NaN 保持；内部 records 为只读 Sequence，现有业务按行读取/list/DataFrame 路径通过。它不是可原地 append 的普通 list，修改缓存仍走既有 setter。
- 本轮未重跑 GUI、打包或实盘验收，不能把数据结构兼容验证等同于所有运行场景验收。

## SBC 历史转换补充优化

- `CompactBarRecords.to_frame()` 直接按列构造独立 DataFrame；接入静态预览、历史兜底及历史＋当日增量合并，取消完整历史 `list[dict]` 中间层。
- 保留 float64/int64、超大整数、缺失字段、显式 None、字段顺序及修改隔离；筛掉全部历史或某字段仅存在于被筛掉的行时，仍与原逐行构造结果一致。旧 list 缓存入口继续兼容。
- 2,400 条模拟分钟记录，tracemalloc 转换分配峰值：静态 3,494.2 → 432.9 KiB（减少 87.6%）；追加 240 条当日记录 3,550.9 → 869.7 KiB（减少 75.5%）。仅统计局部转换，已预先构造压缩缓存和筛选掩码，不代表进程总内存或完整业务延迟。
- 8 项针对性验证全部通过：列式转换、精度/缺失值/副本隔离、旧存档、按需恢复、盘中首分钟合并、历史预览和选择性落盘；语法、UTF-8 无 BOM 和差异检查通过。打包及实际进程内存由用户验收。
