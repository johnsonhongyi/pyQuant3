# 数据、信号买卖点与 T+1 持续优化计划书

## 1. 结论

截至 2026-09-22，昨天计划中的数据新鲜度、早盘量能归一化、S4/S5 可执行门、结构性盈亏比、交易分钟 TTL、EXIT > BUY、T+1 当日锁仓和审计字段已大部分落地；系统已经从“发现信号”推进到“收敛候选并在执行前复核”。

但当前还不能认定为完整交易闭环，主要有三项缺口：

1. **T+1 只完成了锁仓半闭环**：当日买入禁止卖出已覆盖，次日可卖后的底台破位与高潮退出仍有指令生成失败。
2. **跨日结构仍偏静态标签**：当前蓝色光标同款逻辑主要确认“多日平底 + 60F 支撑/启动 + 尾盘收最高”，尚未完整表达“昨日始终在 VWAP 下蓄势、尾盘未变盘，今日高开冲高回落”的状态转移。
3. **数据质量缺少逐层可观测闭环**：有快照新鲜度门禁，但尚缺字段级质量评分、跨源一致性、缺失降级和信号结果标签的统一日报。

因此后续优先级必须是：**先修可卖退出链，再做跨日状态机，再优化更多买点**。

## 3. 蓝色光标案例应如何重新定义

用户给出的事实是：**昨日整体运行在 VWAP 下方蓄势，尾盘没有完成向上变盘；今日高开后冲高回落。**

这与现有测试中的“昨日尾盘放量收最高、形成 SWING_PREORDER，博次日突破 VWAP”不是同一个结构。前者应是“待确认观察态”，不能沿用确认突破的 A 级预埋结论。

建议拆为以下跨日状态：

1. `D0_BELOW_VWAP_ACCUMULATION`：昨日价格主要在 VWAP 下，波动和量能收敛，底台未破，但没有有效站上 VWAP。
2. `D0_LATE_NO_REVERSAL`：14:30 后仍未站稳 VWAP，收盘不在日内高位附近；只保留观察资格，不产生可执行买单。
3. `D1_GAP_UP_PROBE`：次日高开，先判断是有效突破还是利用高开兑现。
4. `D1_BREAKOUT_HOLD`：开盘后站上昨日 VWAP/箱体上沿，并在规定交易分钟内回踩不破，量价继续确认，才升级 S4。
5. `D1_SPIKE_FADE`：高开冲高后回落，跌回开盘价、昨日箱体上沿或 VWAP 下方，且高点回撤扩大；禁止新买，并对昨仓进入减仓/退出评估。
6. `D1_FAILED_BREAKOUT`：回落跌破结构失效位；昨仓若可卖则执行退出，今仓因 T+1 锁定只能进入风险告警和次日优先退出队列。

核心变化是：**昨日 VWAP 下蓄势只是上下文，不是买点；今日是否真正站稳关键结构，才决定能否买。高开本身不加分，高开冲高回落反而应触发追高禁令。**

## 4. T+1 必须采用“双库存 + 双决策”

每个代码的持仓不能只保存总股数，必须明确：

- `total_qty`：总持仓；
- `sellable_qty`：券商/纸盘确认的今日可卖数量；
- `today_bought_qty`：今日买入、不可卖数量；
- `frozen_qty`：委托冻结数量；
- `entry_trade_date`：每一批次的买入交易日；
- `next_day_exit_priority`：因当日不可卖而顺延的退出优先级。

决策也必须拆成两层：

- **策略决策**：现在是否应该卖、卖多少；
- **合规执行决策**：当前实际能卖多少。

当策略要求卖出但 `sellable_qty == 0` 时，不应吞掉卖出信号，而应记录 `EXIT_DEFERRED_T1`，冻结任何 ADD/BUY，并把该批次放入下一交易日开盘优先处理队列。次日以柜台 `sellable_qty` 为准解锁，重新检查价格、跌停可成交性、盘口与订单幂等后执行。

## 5. 持续优化的数据闭环

### 5.1 输入数据质量

每个信号必须绑定不可变 `feature_snapshot_id`，记录：行情源、交易日、事件时间、接收时间、延迟、缺失字段、修复字段和源间价差。建议输出四个质量分：

- `freshness_score`：时间延迟与时钟倒流；
- `completeness_score`：OHLCV、VWAP、昨日结构、60F、日线字段完整度；
- `consistency_score`：TDX、实时源、账户源之间的一致性；
- `tradability_score`：停牌、涨跌停、最小交易单位、可卖数量和盘口可成交性。

任一关键分数不达标时只能降级，不允许用默认值把信号“补成可买”。

### 5.2 特征与标签

新增跨日路径特征：

- 昨日 VWAP 上方时间占比、尾盘 VWAP 上方时间占比；
- 昨日收盘距 VWAP、距日高、距箱体上沿；
- 尾盘 30 分钟价格斜率、量能斜率与主动买卖差；
- 次日开盘缺口、前 5/15/30 交易分钟最高回撤；
- 是否回踩守住昨日 VWAP、箱体上沿、结构止损；
- 高开后跌破开盘价所需分钟数；
- T+1 可卖/不可卖批次数量与延迟退出结果。

结果标签不能只记“涨或跌”，至少同时记录：最大有利波动 MFE、最大不利波动 MAE、首次触达止损/目标的交易分钟、是否因 T+1 无法执行、实际滑点与未成交原因。

### 5.3 评价分桶

按以下维度分别统计，禁止混成一个总胜率：

- 昨日在 VWAP 上 / 下；
- 尾盘变盘成功 / 未变盘；
- 次日低开 / 平开 / 高开；
- 高开延续 / 冲高回落 / 回踩再起；
- 有昨仓可卖 / 当日新仓锁定；
- BUY、ADD、REDUCE、SELL；
- 信号出现时段与市场潮汐状态。

## 6. 买卖点策略调整

### 买点

1. `D0_BELOW_VWAP_ACCUMULATION + D0_LATE_NO_REVERSAL` 只能进入观察池，默认仓位为 0。
2. 次日高开不得直接触发 BUY；至少等待 5~15 个交易分钟完成开盘区间确认。
3. 只有“站稳昨日 VWAP/箱体上沿 + 回踩不破 + 量能不过热 + RR 仍达标”才能升级为 S4/S5。
4. 高开幅度、距 VWAP 正偏离、开盘区间回撤三者共同构成 T+1 追高风险；达到阈值即 `BLOCK_BUY_T1_SPIKE_FADE`。
5. 任何买点必须同时给出结构失效价和“若今日无法卖出”的隔夜极端风险预算，据此反推仓位，而不是先定仓位再套止损。

### 卖点

1. 昨仓可卖：高开冲高回落跌破开盘价、昨日箱体上沿或日内 VWAP时，按结构强弱分批减仓；跌破结构失效位全退。
2. 今仓不可卖：保留真实退出意图为 `EXIT_DEFERRED_T1`，禁止同日补仓摊低成本。
3. 高潮限价卖单和底台破位卖单必须共享同一 `sellable_qty` 事实源、幂等键和 EXIT > BUY 优先级。
4. 次日解锁退出不得机械使用昨日价格；开盘前生成计划，开盘后用实时可成交价重新校验。

## 7. 实施顺序与验收

### P0：先修交易安全闭环

1. 修复两项失败回归：底台破位止损未生成 SELL、高潮退出未生成 LIMIT SELL。
2. 增加 `EXIT_DEFERRED_T1 -> NEXT_DAY_EXIT_READY -> SELL_SUBMITTED -> FILLED/PARTIAL/REJECTED` 状态机。
3. 覆盖昨仓、今仓、混合批次、部分成交、拒单、跌停不可成交、重启恢复。

验收：相关专项 100% 通过；策略退出意图不会因 T+1 被静默丢弃；可卖数量永不超过事实源。

### P1：跨日结构状态机

1. 落地上述六态及状态转移原因码。
2. 增加蓝色光标“昨日 VWAP 下蓄势且尾盘未变盘—今日高开冲高回落”的固定回放夹具。
3. 与现有“尾盘收最高—次日有效突破”正样本成对测试，避免一刀切。

验收：负样本不产生追高买单；正样本只有确认站稳后才进入 S4/S5；所有状态可解释、可回放。

### P2：数据和阈值持续学习

1. 日终自动生成特征—决策—执行—结果宽表。
2. 周度执行 walk-forward 评估，不使用未来数据，不盘中自动改阈值。
3. 阈值变更采用挑战者配置，先离线、再 PAPER、再人工确认；每次只改一个变量组。

验收：至少按市场状态和跨日路径给出样本量、胜率、期望、盈亏比、回撤、拒绝率和 T+1 延迟损失。

### P3：界面与复盘

交易卡片直接显示“昨日结构 → 今日状态 → T+1 可卖量 → 当前动作 → 失效条件”，并将 `观察`、`可买`、`禁止追高`、`可卖退出`、`T+1 延迟退出`使用不同状态色区分。
