## 一、审核复核与事实判断纠偏（闭环校准）

结合多次代码审查与专业审核结论，对现有系统行为的事实判断与优化策略进行严格纠偏：

### 1. 采样指纹漏更新与静默丢帧风险（纳入阶段 0 基线核查）
- **事实定位**：
  - 计算入口指纹 ([`instock_MonitorTK.py:6391-6410`](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/instock_MonitorTK.py#L6391-L6410))：在 5000 行数据中仅等间距抽取最多 50 行的价格与成交量计算哈希；
  - 主表刷新指纹 ([`instock_MonitorTK.py:17055-17075`](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/instock_MonitorTK.py#L17055-L17075))：仅抽取 5 行的一个数值列（如 `trade` 或 `percent`）计算哈希。
- **潜在危害**：
  在 `query`、`force` 等条件未触发且代码/列配置未变时，未采样个股的价格变化或仅名称、板块、均线、信号列变化，可能被相应入口的采样指纹判为“无变化”并跳过本次处理或刷新。计算入口还采用样本数值求和，采样点内正负变化相互抵消也可能漏判；下游是否还有强制刷新或其他通路，需在阶段 0 逐帧核对。
- **纠偏规范**：
  阶段 0 将“采样指纹漏更新/静默丢帧率”列为首要测量项。Golden Samples 保存原始行情、历史状态和用户操作输入，以绕过待测指纹的独立参考计算生成预期结果；仅靠单帧原始行情不足以推导有历史依赖的信号。逐层比对实际计算与展示路径，区分暂时跳过、后续补齐和持续遗漏。

### 2. 阶段 1 客观定位：主表排序策略比较与逐行移动评估（摒弃“误判”定性）
- **事实定位**：
  [`instock_MonitorTK.py:17098`](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/instock_MonitorTK.py#L17098) 中 `set(current_codes) == set(self._last_df_codes) and current_codes != self._last_df_codes` 触发 `force_full = True`，是现有系统在代码集合相同但顺序变化时**为了维持物理排序绝对正确所采取的有意策略**，而非简单的无意识误判。
- **纠偏规范**：
  不使用“排序误判”或“主表 0 侵入”这类表述。阶段 1 的任务是**对比几种排序策略在不同变动比例下的综合成本与交互行为**：
  - 策略 A（基线）：现有全量清空重建（评估大数量级下的 Tcl DOM 重建开销）；
  - 策略 B：增量更新 + 移动优化（需设计算法识别可保持相对行序的子集，单纯对比每行原/目标索引不等于最小移动序列）；
  - 策略 C：保留现有物理行的分批重排；“仅重绘视口”需重构物理行映射，归入阶段 4 单独评估；
  必须在异步批次全部提交并由事件循环完成布局更新后，实测行序、焦点与选中稳定性，以及用户可感知的最长阻塞；LIS 可作为最小移动数的候选算法，但还须验证 `tree.move` 执行顺序、插删行和中途交互。

### 3. 差分协议接收端契约与空值语义完整闭环
- **事实定位**：
  [`ipc_sync_manager.py:340-366`](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/ipc_sync_manager.py#L340-L366) 的接收端合并逻辑：
  ```python
  if isinstance(df_diff.columns, pd.MultiIndex):
      # 仅提取 val_type == 'self' 的列
      df_diff = pd.DataFrame(new_cols, index=df_diff.index)
  col_data = df_diff.loc[common_idx, col]
  valid_mask = col_data.notna()
  self.current_df.loc[valid_indices, col] = df_diff.loc[valid_indices, col]
  ```
  现行接收端仅提取 `self` 层级，且**强制使用 `notna()` 过滤**。
- **关键矛盾**：
  如果发送端发生“某个指标/信号由非空值变为 NaN（如信号失效重置）”，由于接收端用 `notna()` 跳过了空值，这个 NaN **永远无法写入接收端**！导致接收端残留脏数据。
- **纠偏规范**：
  差分协议优化必须包含**发送端与接收端的双向契约闭环**：
  - **路径 1（保持现有协议边界）**：对显示轨和日线轨各自检测非空转空及无法安全编码的结构变化，先于 `DF_DIFF_EMPTY` 判定回退 `UPDATE_DF_ALL`；每个接收端须以该轨全量包替换旧基线；
  - **路径 2（协议版本化升级）**：协同升级所有接收端（`ipc_sync_manager.py`、`ats/ui/main_window.py`、`trade_visualizer_qt6.py` 等），定义显式空值编码协议（如带 mask 的增量包）；
  - 无论采用何种路径，均须用全量快照与差分累加结果逐帧对照验证一致性；单纯退回旧 `DataFrame.compare()` 不能修复当前接收端的空值跳过。

### 4. 数据所有权与不可变边界的可执行规则（取代“封印”口号）
- **事实定位**：
  Pandas DataFrame 引用与版本号无法阻止运行态修改。现有系统在总线发布后，仍存在后台线程与主线程的混合写入点（如 TWAP 注入、情绪评分赋值、自选股标记）。
- **可执行所有权契约**：
  必须制定明确的《数据生命周期表》，界定“谁拥有、谁借读、何时复制、旧版本何时释放”：
  1. **独占写阶段（Single-Writer Stage）**：按各轨列出生产者、实际写入点与先后依赖；现有 `send_df` 在总线读取后仍调用 `attach_multiday_twap_to_df`，须先调整或保留隔离拷贝，不能宣称目前所有衍生列均已在发布前算齐；
  2. **只读发布点（Frozen Publish Point）**：仅在确认后续无写者的轨道评估发布引用。开发期可组合底层数组只读标志、关键写 API 包装和发布前后内容校验；`df[col].values.flags.writeable = False` 对新增列、Pandas 内部复制及扩展类型不是完备防写机制，不能保证抛异常；
  3. **借读契约（Borrowing Contract）**：`send_df` 广播线程与 UI 渲染线程仅作为**借读者（Borrowers）**，只读读取快照；若某分析模块需要派生临时列，必须显式调用切片拷贝（Copy-on-Write），严禁原位修改；
  4. **版本生命周期**：记录借读者持有、缓存、延迟任务与外部引用；由代码审计和内存采样验证旧版本实际释放时点，不以 Python 引用计数作为已消除跨代滞留的保证。

### 5. 撤销未经验证的性能与恢复承诺（回归科学工程态度）
- **撤销“10ms 极速自愈”**：Windows 环境下进程创建（`mp.Process.start()`）通常需要数十毫秒至数百毫秒，且从磁盘反序列化复杂状态机需严格耗时，不应虚构 10ms 承诺；
- **撤销“主进程完全释放 GIL”**：主进程仍然承担 UI 事件分发、过滤、排序及差分协议计算，优化目标是消除主进程中超额的纯 CPU 信号计算，而非脱离实际的“100% 释放”；
  - **完善自愈机制设计**：快照覆盖 `_state_dfs`、`_cached_data` 等跨帧状态，并绑定已完成计算的输入版本；临时文件和目标文件须位于同一卷，写完校验后再替换，并验证 Windows 文件占用下的失败行为。补帧重放的前提是存在连续、可重放的输入帧日志；坏快照或缺帧时须定义冷启动/全量重算与信号降级边界，不能承诺无损恢复。

### 6. 四个新增热点的实事求是核对
1. **主线程 `update_idletasks()` ([line 2573](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/instock_MonitorTK.py#L2573))**：
   每 5 个任务调用一次。20ms 调度预算仅在任务之间检查，单个慢任务仍可超时。先分别统计该调用与任务本身的耗时，并回归布局更新，不妄称“屏幕撕裂”，仅在实测证明其构成主要阻塞且移除后布局稳定时才调整；
2. **概念板块统计 ([line 17826](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/instock_MonitorTK.py#L17826))**：
   其统计仅基于 `head(50)` 且摘要结果常驻主窗口状态栏，不能以详情窗口隐藏为由跳过摘要更新。更值得测量的是重建概念标签的成本；应按完整输入版本与展示状态分别控制摘要和详情更新；
3. **自选股管理器 ([line 661](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/performance_optimizer.py#L661))**：
   所列调用均在各批处理循环外，主要开销是 `get_favorite_stocks()` 每次持锁生成新集合。列为低优先级测量项，评估在单次更新批次内复用只读集合，同时确保自选股变更时及时失效；
4. **字符串格式化 ([line 588](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/performance_optimizer.py#L588))**：
   `Series.map('{:.2f}'.format)` 仍逐元素调用 Python 格式化函数，并非 C 向量化。全量准备路径已按列预格式化，增量路径才逐行处理。应分开计时两条路径，重点验证 NaN、异常值及显示精度一致性。

#### 1. 目标

3. **业务一致性验收门禁**：
    - 在高频并发读取、生产者持续更新与旧版本滞留回放中，快照数据与版本号始终对应，且无已知写入路径污染旧版本；
   - 内存分配带宽与峰值有确切的实测下降指标。

### 阶段 3：差分正确性闭环与候选提速（Full-Column Fidelity Diffing）

> **准入门槛**：阶段 0 发现差分重建错误时，先处理正确性，不受性能占比限制；仅在 `DataFrame.compare` 的绝对耗时和占比共同构成瓶颈、替代方案有净收益时启动提速。

#### 1. 目标
定义显示轨与日线轨各自的发送、接收、基线版本和空值契约；在正确性通过后再评估向量化差分。

#### 2. 具体规划
1. **空值语义与接收端契约闭环**：
    - 审查 `ipc_sync_manager.py`、`ats/ipc_bridge.py`、`ats/ui/main_window.py`、`trade_visualizer_qt6.py` 等实际接收端的 MultiIndex、`self`、`notna()`、新增行/列及重连基线行为；
   - 规划双端契约：
      - 若维持旧协议：发送端逐轨检测非空转空、增删行、列/索引及无法安全表达的 dtype 变化，先于空差分判定发送对应轨的 `UPDATE_DF_ALL`；接收端以全量包替换旧基线；
      - 若升级新协议：差分包显式携带“单元格发生变化”的掩码及版本，所有接收链在兼容旧客户端的条件下同步升级；
   - 两轨的发送门禁必须独立：显示轨 `DF_DIFF_EMPTY` 时，日线轨仍可能需要 `UPDATE_DF_ALL`；核对 Pipe、Socket、订阅端的实际发送条件及各自版本。
   - 更新上一帧缓存与已发送版本的时点须区分；发送失败或被节流后，接收端下一次差分必须有可用基线，否则强制全量同步。
2. **分类型向量化比对**：
   - 对数值列（Float/Int）、字符串/分类列（Object/Str）分块比对；正确处理 `NaN`、`None`、`pd.NA` 的相等性；
    - 任何增删行或列/索引结构不一致均先回退全量包，除非所有接收端已验证相应增量语义；不以“变化幅度大”作为唯一条件。
3. **业务一致性验收门禁**：
    - 分别对两条轨逐帧回放全量与差分消息，真实接收端合并结果逐列等于该帧全量真值；覆盖显示轨不变但日线轨变空、空值双向转换、增删行、发送失败、乱序和重连。
   - 严格保留现有动态订阅、静态端口探测、临时动态端口与首次连接必须发全量包的物理规则。

### 阶段 4（候选）：视口虚拟化架构与交互状态机（Virtual Scrolling Viewport）

> **准入门槛**：阶段 1 后主表仍是经分项测量确认的主要交互瓶颈，且物理行数量而非单个慢回调或标签重建是主因；门槛数值由阶段 0 基线和交互目标确定。

#### 1. 目标
验证基于逻辑主键映射的虚拟化视口是否降低延迟，同时保留已列出的操盘交互语义。

#### 2. 具体规划
1. **基于 `stock_code` 的逻辑主键映射层**：
   - 废除以 Treeview 物理 iid 识别股票的逻辑，引入逻辑选中管理器 `SelectionManager`；
   - 视口滚动或刷新时，根据 `self.select_code` 自动反查并高亮对应的虚拟物理行；若当前选中股票已滚出屏幕，明确定义焦点和快捷键行为（锁定所选股票代码，操作不串股）；
2. **虚拟滚动条与交互事件接管**：
   - 根据底层真实总行数计算虚拟滚动条滑块大小与位置；
   - 拦截键盘 `Up`/`Down`、`PageUp`/`PageDown`、鼠标滚轮，映射为数据行偏移，平滑驱动视口切片。
3. **业务一致性验收门禁**：
    - 虚拟化作为独立配置开关灰度测试；出现焦点错股、快捷键目标错误等正确性问题立即回退；滚轮抖动先按可复现条件及延迟门槛判定；
   - 键盘连续翻页、快速切码、表头双击排序、单元格双击穿透与右键菜单等交互与现有主表完全等价。

### 阶段 5（候选）：`detect_signals` 状态化迁移与子进程解耦（Stateful Signal Migration）

> **准入门槛**：阶段 0 证明 `detect_signals` 的主进程 CPU/GIL 占用与主事件延迟存在可复现关联；再用原型测得进程启动、序列化、IPC、快照与恢复后的净收益为正。该候选独立于阶段 3/4。

#### 1. 目标
将重度 CPU 运算移入子进程，同时保障信号状态跨周期连续性与子进程重启自愈。

#### 2. 具体规划
1. **依赖拓扑梳理**：
   - 理清情绪评分与信号检测的真实依赖顺序，确保输入数据流时序正确；
2. **跨进程状态快照与原子自愈**：
   - 完整盘点 `SignalManager` 的 `_state_dfs`、`_cached_data` 及跨帧状态；
    - 快照绑定最后完成计算的输入版本与输出版本；临时文件和目标文件在同一卷，写完并校验后替换，测试 Windows 打开句柄/占用失败；仅在持久化成功后公布可恢复版本。
    - 补帧重放须有连续输入日志、确定的重放顺序与保留期限；现有总线只提供最新快照，不能从版本号恢复遗漏帧。缺帧或坏快照时按明示的冷启动/全量重算与信号降级规则处理。
3. **业务一致性验收门禁**：
    - 在输入日志连续且状态快照有效时，强退重放后的信号逐帧等于不中断参考运行；缺帧或坏快照时验证降级与重新建立状态的边界，不承诺无法重放的历史帧仍完全一致；
   - 在真实 Windows 环境下实测进程启动与恢复时延。

---

### 实验性探索项（独立分支验证，不列入主线前提）

1. **共享内存（mmap / IPC Shared Memory）**：
   - 须攻克 Windows 文件锁、进程崩溃孤儿句柄、写完再发布及读者防撕裂读机制；
2. **GC 阈值微调**：
   - 仅当 GC 停顿被测为瓶颈时，在长周期压测中对比默认阈值与调整阈值的实际停顿分布及内存增长；
3. **数值类型降型（Downcasting）**：
   - 逐列审计精度（价格需 2~4 位）、大金额（数十亿防止溢出）与空值表示，不做全表粗暴降型。

## 四、阶段准入与回退门禁

以下 200ms、100ms、30% 仅可作为阶段 0 采样时的观察标签，不能在缺少机器、数据量、盘中负载和用户可接受延迟定义时充当固定工程门槛。阶段 0 后应先固定测试环境、输入集、采样窗口、P95/P99 与正确性阈值，再决定性能改造是否准入。

| 阶段 | 准入决策 | 回退条件 |
| :--- | :--- | :--- |
| **1 排序** | 完成三种保留物理行策略的同源回放；仅在排序对交互延迟有可测影响且候选方案有净收益时采用 | 移动/分批路径变慢，或最终行序、焦点、选中、刷新中途操作不一致时，保留现有全量路径 |
| **2 总线** | 所有权审计必做；逐轨证明无发布后写入、无可写别名且内存/延迟收益可测，才移除对应拷贝 | 发现任何旧快照污染、版本错配或并发异常，恢复该轨隔离拷贝 |
| **3 差分** | 重建结果错误立即进入正确性修复；提速须证明绝对耗时和占比均构成瓶颈 | 新比较器不保真时退回已验证的旧比较器；若旧协议不能表达空值变化，仍须保留该情形的全量回退，不能仅退回 `compare()` |
| **4 虚拟化** | 阶段 1 后仍确认物理行数量是主要瓶颈，并有独立交互回放环境 | 焦点或快捷键错股立即关闭灰度；滚轮/布局问题按复现样本及延迟门槛回退 |
| **5 信号迁移** | CPU/GIL 关联及扣除 IPC、快照、重放后的净收益均经实测成立 | 有连续输入仍无法重建一致状态，或恢复时间超预算，则保留原执行路径；缺帧按预定义降级处理 |
