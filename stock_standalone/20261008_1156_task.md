# 任务清单：ATS Nuitka 打包退出后控制台停住未自动释放根治 (2026-10-08 11:56)

## 背景与现场定性
- **现象**：ATS 使用 Nuitka 打包后，主程序全部退出并打印出 `[ATSMainWindow] 退出收尾完成：数据已持久化，子进程关闭任务已回收。` 之后，控制台停住卡死，没有自动释放。
- **对比**：使用 PyInstaller 打包的 ATS 打开相同的后台关闭后可以正常退出；历史项目 `instock_MonitorTK` 与 `trade_visualizer_qt6` 曾遇到类似退出卡死问题，最终通过 `os._exit(0)` 与进程树回收根治。
- **根因确认**：
  1. Nuitka Onefile 的两层进程模型（Bootstrap 外壳 + Payload 内核）导致 `multiprocessing.active_children().terminate()` 仅杀死了外壳 Bootstrap，而内层 Payload 变成了孤儿进程，继续附着在控制台上，导致 Windows 控制台无法关闭；
  2. ATS 主窗口在完成所有数据持久化和收尾工作后，未对齐 MonitorTK / TradeVisualizer 规范执行工业级物理退出 `os._exit(0)`，而是依赖软退出 `app.quit()` 和 `sys.exit()`，极易在 Qt C++ 析构、COM 释放、非 daemon 线程或 atexit 钩子处永久挂起；
  3. 原 5 秒 exit watchdog 设为 `daemon=True`，在解释器终结（`Py_FinalizeEx`）或加载锁生效期间容易被操作系统/解释器冻结，失去保底救命效果；
  4. `is_packaged_env()` 判定在部分 Nuitka 模块上下文中可能存在盲区。

## 任务拆解与实施计划

- [x] **Task 1: 进程树递归深度回收与孤儿进程彻底终结 (`ats/shutdown.py`)**
  - 重构 `reap_multiprocessing_children`，引入 `psutil` 递归探测并回收全部子孙后代进程（children tree），彻底根除 Nuitka Onefile 下 Payload 孙子进程脱钩残留；
  - 加固 `start_exit_watchdog`，将默认超时优化为 1.5 秒，移除易被解释器终结冻结的单一依赖，提供可靠的短超时兜底。

- [x] **Task 2: 主窗口退出收尾工业级物理终结闭环 (`ats/ui/main_window.py`)**
  - 在 `[ATSMainWindow] 退出收尾完成` 日志之后，对齐 `instock_MonitorTK` 和 `trade_visualizer_qt6`，安排由主线程与保底看门狗双重触发的 `os._exit(0)` 确定性物理终结（`QTimer.singleShot(150, lambda: os._exit(0))`）；
  - 避免进入不可控的 CPython 解释器二次挂起和 PyQt 析构死锁。

- [x] **Task 3: 启动入口退出收口对齐 (`run_ats.py`, `ats/main_ats.py`)**

  - 确保测试模式（`ATS_TEST_MODE=1`）与正常运行模式的一致性与安全退出。

- [x] **Task 4: NextDayWatch 与环境识别自愈加固 (`ats/next_day_watch_process.py`, `sys_utils.py`)**

  - 全流程配合全树进程终结杜绝孤儿。
