# 2026-10-09 18:48 【MonitorTK 性能与内存深度审核及视图滚动卡顿/点击延迟根治闭环】

## 1. 任务背景
用户反馈今天 MonitorTK 做的一系列内存和性能优化之后，视图滚动依旧卡顿，点击存在明显延迟。需要全面穿透今天的改动，定位根因并实施彻底修复。

## 2. 根因深度诊断
经穿透今日多项 commit（`7a7cc0bd` ~ `644474eb`），定位到导致主线程卡顿与交互延迟的 5 大核心瓶颈：
1. **【P0-1 分批渲染高频回调霸占事件循环】**：
   `performance_optimizer.py` 中的 `_render_in_chunks` 使用 `after(1, render_batch)` 仅留出 1ms 间隙，对 5000+ 行数据拆分为 ~80 批次渲染，近 1 秒持续紧密抢占 Tkinter 事件循环，导致 Windows 鼠标滚动和单击事件被严重饿死。
2. **【P0-2 Qt 事件泵 16ms 高频空转】**：
   `instock_MonitorTK.py` 中的 `_process_qt_events` 每 16ms 强行调度一次（60fps），在无 Qt 事件时依然产生高频 Python 回调，与 dispatch 队列和分批渲染形成三重事件争抢。
3. **【P0-3 主表格刷新双重 5000+ 行全量转 list 与 set 运算】**：
   `instock_MonitorTK.py` 中的 `refresh_tree` 在每次刷新时无条件执行两次 `df['code'].astype(str).tolist()` 以及庞大的 `set()` 集合运算进行排序变更检测，在主线程产生 5~10ms 无效 CPU 开销。
4. **【P0-4 Dispatch 循环内热路径高频 import 与锁争用】**：
   `_record_latency_sample` 每次调用都在热路径局部 `from ats.performance import record` 并获取 `_latency_samples_lock`，每个轻微任务都在锁竞争和字典维护中产生开销。
5. **【P0-5 分批渲染每批重复导包与重复获取全局自选股】**：
   `performance_optimizer.py` 中 `_prepare_rows_fast` 和 `render_batch` 在每个 64 行批次循环中都重复执行 `GlobalFavoriteManager().get_favorite_stocks()` 与模块导包，5000 行产生 78 次重复查询与加锁。
6. **【P0-6 跨环境属性缺失与异常隐患】**：
   新增加的 `_capture_sort_state`、`_panel_closing`、`_snapshot_retry_timer`、`_get_detector_ui_snapshot` 缺乏防御性属性检查（getattr/hasattr），在特定环境或 mock 测试下抛出 AttributeError 导致流水线被阻断。

## 3. 具体实施措施
- [x] **修复 P0-1**：将 `performance_optimizer.py` 中 `_render_in_chunks` 与 `_chunked_insert` 的批次调度由 `after(1, ...)` 调整为 `after(16, ...)`，让 Tkinter 事件循环在每帧之间有充足时间（~16ms）处理滚动与点击交互。
- [x] **修复 P0-2**：将 `instock_MonitorTK.py` 中 `_process_qt_events` 的轮询间隔从 16ms 调整为 50ms（20fps），在保证 Qt posted events 正常流转的同时释放 68% 的空转回调。
- [x] **修复 P0-3**：重构 `refresh_tree` 排序检测逻辑，利用 `tuple(df['code'].values)` 单次缓存与长度比对，消灭重复全量 `tolist()` 与冗余 `set` 比较。
- [x] **修复 P0-4**：在 `instock_MonitorTK.py` 顶层预导入 `_ats_record` 消除局部导包开销；并在 dispatch 循环中对任务耗时采用自适应采样（慢任务 >=5ms 100% 记录，微任务 1/5 采样），削减锁争用。
- [x] **修复 P0-5**：在 `performance_optimizer.py` 顶层预导入 `GlobalFavoriteManager` 和 `cct`；在 `_render_in_chunks` 外部预提取一次 `favorites` 集合并在分批闭包中完全复用，传给 `_prepare_rows`，消灭 78 次重复获取。
- [x] **修复 P0-6**：为 `_capture_sort_state`、`_put_deduped_task`、`_panel_closing`、`_last_source_df`、`_snapshot_retry_timer`、`_get_detector_ui_snapshot` 全面补齐 `getattr`/`hasattr` 防护，彻底杜绝主流程被异常中断。
- [x] **单测对齐与回归验证**：更新 `test_tk_runtime_performance.py` 中的 mock 闭环对齐；36 项专项性能与响应性测试 100% 秒级纯绿通过。
