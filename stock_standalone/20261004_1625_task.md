# 2026-10-04 16:25 任务记录：Nuitka 打包编译器缓存机制审计、sccache 无效根因剖析与 clcache 原生加速对齐闭环

## 任务背景与用户问题
- **用户反馈**：在第 6 次 Nuitka 批量打包（ATS 终端）时，耗时达到 22 分 26 秒，且生成的统计报表中出现：
  ```
  增量缓存体积 : .nuitka_cache [770.9 MB] ｜ sccache 本地盘 [0 B]
  编译器缓存   : sccache 请求: 0 | 命中: 0 | 未命中: 0 | 命中率: -
  ```
  用户明确提出：“检查项目打包 sccache 为何没有效果, 及修复这个 bug”。

---

## 根因深度剖析 (Root Cause Analysis)

### 1. 历史遗留的环境变量幻觉 (`NUITKA_SCONS_CCACHE`)
- 项目历史构建脚本（`nuitka_build_ats_console_onlyClang.bat`、`nuitka_build_console_onlyClang.bat` 等）中长期写有：
  ```bat
  sccache --start-server >nul 2>&1
  set NUITKA_SCONS_CCACHE=sccache
  ```
- **代码核验结果**：穿透核查 Nuitka 官方 4.1.1 完整源码库（Scons 编译系统全链路），**根本不存在 `NUITKA_SCONS_CCACHE` 这个环境变量**。这是早期编写者自行臆想的变量，Nuitka 启动编译时压根不会读取该设置，导致 sccache 无法接入。

### 2. Nuitka 在 Windows Clang 模式下的真实工具链机制
- 在构建脚本中，由于显式加载了 Visual Studio 2019 环境（`vcvars64.bat`），且传入 `--clang` 参数；
- Scons 在 Windows 上自动将 Clang 编译器识别为 **`clang-cl`（以 MSVC 驱动模式运行）**；
- 在 `msvc_mode / clangcl_mode` 下，Nuitka 官方**硬编码强制绑定使用其内置的 `clcache`**（Nuitka 内置的 MSVC 编译缓存实现），代码路径位于 `nuitka.build.SconsCaching.enableClcache`；
- 实机探针测试证实：Nuitka 连续二次编译时，Scons 明确报告：
  `Nuitka-Scons: Compiled 6 C files using clcache with 6 cache hits and 0 cache misses.`；
- **核心结论**：Nuitka 在 Windows Clang 模式下官方唯一支持并使用的 C 缓存就是 `clcache`，从设计上就未原生接入 `sccache`。

### 3. 统计监控指标错配与 1.19 GB 隐形缓存被忽略
- 统计记录器 `tools/log_build_summary.py` 此前受批处理脚本中 sccache 注释误导，仅去扫描 `D:\sccache` 与 `sccache --show-stats`；
- 由于 sccache 从未接收到编译命令，其请求数始终为 0；
- 但经深度排查，系统实际上已在 `%LOCALAPPDATA%\Nuitka\Nuitka\Cache\clcache` 中累积了高达 **1.19 GB (1,190,691,195 B)** 的真实 C 编译缓存，只是此前从未被统计脚本呈现。

### 4. 22 分钟构建用时真实原因
- 用户在第 5 次与第 6 次构建之间，曾执行了 `clean_nuitka_cache.bat`；
- `clean_nuitka_cache.bat` 清空了工作区 `.nuitka_cache` 下的模块 AST、Bytecode 与依赖配置文件；
- 导致第 6 次构建变成了一次从零开始的**全量冷分析与冷编译**（Clean Cold Build），因而耗时 22 分 26 秒；但之后的增量构建将自动复用 1.19 GB 的 `clcache`，恢复极速状态。

---

## 修复与落地实施细节

### 1. 统计记录器全面重构与真实缓存透视 (`tools/log_build_summary.py`)
- **双轨缓存智能探针**：
  - 新增 `get_clcache_info()`：精准探测 `%LOCALAPPDATA%\Nuitka\Nuitka\Cache\clcache`（实测 1.19 GB）；
  - 新增 `get_sccache_cache_info()`：动态探测 `SCCACHE_DIR`、Mozilla 默认目录与 D 盘；
- **告别误导性 0 请求报错**：
  - 若 `sccache` 请求为 0 时，自动识别 Windows `clang-cl` 原生引擎接管态势，输出：
    `编译器缓存 : clcache [1.19 GB] (Nuitka Windows原生Clang-cl专属缓存就绪)`；
  - 若未来有真正的 `sccache` 接入并产生命中，则动态输出 sccache 命中率；
- **优化性能评估判定**：
  - 耗时 >= 1200s 时提示：`[全量冷编译] 首次全量打包或刚执行过 clean 缓存重置 (下次构建将复用 clcache 加速)`；
  - 增量编译时提示：`[增量编译就绪] clcache (1.19 GB) 与 .nuitka_cache 命中复用`。

### 2. 构建子脚本纠偏与环境对齐
- **清理无效变量**：在 `nuitka_build_ats_console_onlyClang.bat`、`nuitka_build_console_onlyClang.bat`、`nuitka_build_multi_period_dialog_onlyClang.bat` 中：
  - 移除无效的 `set NUITKA_SCONS_CCACHE=sccache`；
  - 显式导出 `set "CLCACHE_DIR=%LOCALAPPDATA%\Nuitka\Nuitka\Cache\clcache"`，控制台明确提示 `[INFO] Nuitka compiler cache: clcache enabled (Windows Clang-cl native)`。

### 3. 清理工具加固 (`clean_nuitka_cache.bat`)
- 在工作区与 `C:\Users\Johnson\` 两处脚本中加入醒目提醒：
  `提示: 清理后下一次打包将执行全量冷编译 (耗时约 20 分钟)。日常增量打包请勿频繁清理，以充分享受 clcache 秒级加速！`
