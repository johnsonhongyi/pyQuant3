# AGV 启动时闪窗：隐藏控制台继承方案

- 用户确认闪窗发生在启动 AGV 桥时。
- 原方案为 CREATE_NO_WINDOW + SW_HIDE。CREATE_NO_WINDOW 令进程没有控制台窗口句柄；只给第一层设置该标志，不能保证第三方程序内部的后续控制台创建行为。
- 新方案：仅对 AGV 使用 CREATE_NEW_CONSOLE + STARTF_USESHOWWINDOW / SW_HIDE，在创建时保持控制台隐藏，供后续控制台子进程继承。覆盖管理器 → 独立 worker → Python agent → agy models/聊天/策略；不在管理器 UI 进程内调用 AllocConsole，也不扫描隐藏其他应用的窗口。
- 共用 run_bounded_cli 新增可选 hidden_console 参数，默认仍为原有无窗口行为；Codex 等默认调用路径保持原行为。管道读取、超时及进程树清理契约保持。

## 验证与限制

- 实际执行只读 agy models：新方式正常返回 6 项目录，10ms 采样观测到的所属控制台 visible=false；旧方式在本次采样也未观测到可见窗口，因此这次探测没有复现用户的闪窗，不能据此声称原问题已完全复现或彻底消失。
- Windows 隔离测试：实际管理器进程启动路径与测试子进程共用同一个隐藏控制台；CLI 父子继承、stdout 管道、默认调用参数不变、超时清理测试通过。未启动真实业务桥、未领取生产任务或发起模型推理。
- 需要重新构建并更新打包管理器，再彻底退出旧实例后验证真实启动。如果第三方程序显式另建窗口，仍可能绕开控制台继承；本次没有采用全局窗口钩子或事后强行隐藏用户窗口。
- 参考：[Windows Process Creation Flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags)、[STARTUPINFOW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-startupinfow)。

## 修正：GUI 打包启动链不创建控制台

- 后续确认打包入口在 `manage_window_layout.spec` 中为 `console=False`。先前给 GUI 父进程再创建隐藏新控制台，可能让子启动链产生可见控制台；“没有 console”并不会自动弹窗，但显式 `CREATE_NEW_CONSOLE` 会建立新控制台。
- AGV 管理器启动 worker、agent 调用 AGY 目录/聊天/策略、非冻结 runner 启动 agent，现均走 `CREATE_NO_WINDOW`；继续使用 stdout/stderr 管道记录输出。隐藏控制台功能仍作为 bounded runner 的可选通用能力，AGV 不再启用它。
- 此次没有访问或操作用户桌面窗口；修改后需要重建 GUI 打包程序并重启后验证。开发环境与 Codex 启动模式未更改。
