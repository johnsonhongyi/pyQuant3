# Muse 会话归组与研究索引

## 实现链路

Web 提交研究指令，Go API 持久化；独立模拟 worker 冻结市场、资金和股票池证据并排队。Windows 桥经既有 IPC 身份与 HMAC 领取任务，启动已安装桌面 Codex 的官方 app-server（本地 stdio）。模型通过限定的只读市场、逐股和 ATS 工具分析；结构化提案校验后回传，原执行门禁决定是否模拟成交，成交事件再触发复盘。

当前不是操作桌面聊天框，也不是连接桌面共享 daemon；桥使用桌面安装附带的 codex.exe 引擎。模型/强度来自任务冻结配置，每日目录与升级空闲切换规则保持。

## 原因与改动

- 每轮独立证据任务保留独立会话以限制历史增长。原日期标题重复、cwd 指向临时目录、首条消息为大段 JSON，导致最近会话拥挤且难以定位。
- 新增 muse_research_threads.py：固定研究目录与原生项目，标题包含时分、阶段、优先股票代码/名称、跟随/观察/回避计数和短 ID；失败标题含错误码。合成及桌面验收明确区分。
- 首屏改为中文任务索引，完整冻结证据经原只读工具取得。结构化提案仍作为程序结果，另外生成中文逐股摘要与最近 100 份研究索引；摘要包含资金判断、失效条件和数据缺口，研究建议不冒充成交。
- reports/ 与 INDEX.md 为本地运行产物，已忽略；不提交研究数据、密钥或运行数据库。报告及索引原子替换，呈现失败记录 presentation_error，不否定已完成的策略结果。
- 历史 16 个会话及本轮 1 个验收会话已重命名并放入可见侧栏分组“Muse 模拟策略”；17 份摘要已生成。
