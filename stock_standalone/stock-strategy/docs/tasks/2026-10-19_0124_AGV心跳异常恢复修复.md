# AGV HTTP 400、502 与心跳断连

## 原因与证据

- HTTP 400：AGV 停止分支调用 `heartbeat("stopped", ...)`。后端 `auto_follow_ai.go` 只接受 `ready/analyzing/degraded` 且 detail 不超过 16KB。安装目录最后一次 agent 状态为 stopped、心跳 400，detail 仅约 1.8KB；nginx 对应心跳 400 响应长度 35，吻合 `invalid desktop status` 响应。停止状态不应作为远程心跳发送。
- HTTP 502：持久化 nginx error.log 在香港时间 00:29:14、00:55:11 的 `/api/v1/linkage/strategy/heartbeat` 明确记录连接上游 `172.18.0.2:20081` 被拒绝，access.log 同时为 502。属于网关到 API 的连接失败，不是模型推理失败。
- RemoteDisconnected：客户端约 00:59:38 断连；当前 API 于 00:59:41 启动、Web 于 00:59:53 启动；网关在 00:59:29 已记录 upstream 拒绝连接及提前关闭。与服务切换时间相符，但没有该 TCP 连接的完整服务端记录，不能进一步断言它由哪个进程关闭。当前两容器健康，当前容器 restart count 为 0。
- 恢复机制缺口：AGV 就绪心跳在任务领取的 try/except 之外；领取失败后又向相同后端发送降级心跳，第二次失败可直接退出 worker。外层运行器将整段 worker 生命周期标作 agent_start，因此历史日志容易被误读成启动失败。

## 修复

- AGV 单轮调度纳入异常恢复边界；保留本地 worker、目录及 durable outbox，网络错误只在本地记录 degraded，10/20/40/60 秒封顶退避，再发送 ready 重新进入领取流程。错误不靠另一次故障后端心跳上报。
- 停止只写本地 stopped，不发送后端不支持的状态；退避每秒检查停止标志。未中断在途模型任务，未修改交易行为。
- 统一队列仅在 404/405 时降级旧领取接口；正常空队列不再额外调用 chat_claim，502/400 不伪装为接口不支持。
- 共用 DesktopPeer 保持错误后丢弃连接、下次重连；保留已知协议错误原因，不记录任意响应正文或 nginx HTML。AGV 面板显示准确失败阶段、后端原因及重试间隔。
- AGV 本地状态写入加锁，写入失败记录错误；退出逐项清理资源，某一项清理失败不跳过后续清理。

## 验证与生效范围

- Python 37 项通过：包含 400/502/RemoteDisconnected 后恢复、无二次故障心跳、可中断退避、停止不发非法心跳、404/405 兼容、真实本地 HTTP socket 丢弃/重连、AGV 流与结果回传/outbox 回归。
- 语法、UTF-8 无 BOM、git diff --check 通过。未运行 Go 测试，未修改后端契约。
- 仅只读查询线上状态及过滤后的协议/网关日志；没有部署、重启容器、修改生产队列或发送真实模型请求。
- 修复位于桌面桥源码。安装目录中的旧打包程序未替换，需重新构建并重启 AGV 桥后生效；客户端恢复无法消除 API/网关切换窗口本身的瞬时 502。
