# Muse 新会话自动归组与升级兼容

## 已实现及部署

- desktop_sidebar.py 使用已安装的官方 Codex App Tools MCP 服务。每次连接查找本机运行时与插件，不固定版本号、引擎哈希或分组 ID；通过 tools/list 核对接口与参数，不直接修改桌面内部数据库。
- 仅调用 list_threads、create_sidebar_section、move_thread_to_sidebar_section。分组按唯一名称“Muse 模拟策略”定位，不存在时创建；重名时保留 pending 并报告错误，避免移动到错误分组。
- 独立桥在 thread/start 后立即将新会话及任务 ID 提交到自己的 agent.db/sidebar_threads。研究成功、失败或中断后自动归组；主循环继续处理待办。调用移动后再次读取侧栏成员确认，确认前不标记 grouped。
- 桌面离线、旧连接失效、协议能力变化时保留待办，10 秒起指数退避、最长 300 秒。重启后继续待办；失效连接重新发现。心跳暴露 sidebar_pending、sidebar_error、sidebar_group。每次仅探测一个连接，限制对研究主循环的阻塞。
- 侧栏与原生项目各自保持独立接口；无需等待桌面项目注册表同步，不依赖手工整理。对未来破坏性协议变化不能承诺无条件兼容：明确 pending/错误，恢复接口后自动重试。
- 最终修复已再次空闲重启 StockStrategy-CodexATSBridge。未改 Docker/API/Web/worker、TK/ATS 包、账本或实盘行为。

## 验证

- 24 项专项与相关回归通过：自动创建/移动/读取确认、幂等、离线退避、重启恢复、重名保护、缺少确认不假成功、安装目录升级发现、破坏性 schema 拒绝、工具白名单，以及原项目/摘要/引擎策略；语法检查通过。
- 真实官方 MCP 在无继承当前聊天连接环境时发现桌面成功；模拟旧连接失效后重新发现真实端点并读取确认通过，不依赖固定连接名。
- 浏览器控制工具本轮因临时目录 realpath 初始化异常不可用，改用已有 Edge 独立实例；未安装软件或重启用户浏览器。测试实例已关闭。
- 本轮没有实际安装/升级 Codex；升级兼容证据为动态目录/能力检查测试与真实失效连接恢复。下一次实际升级仍应观察 sidebar_pending/sidebar_error，不把测试称作未来版本保证。

## 观察与回退

- 研究失败不等于归组失败：以 sidebar_threads 状态和官方侧栏成员为准；研究回执仍以任务 completed/failed 为准。
- 后续额度恢复后，需补一次完整研究成功回执验收；自动归组已用实际 Web 新会话验证，不需要再次手工整理。
- 回退代理到上轮提交并空闲重启桥，保留 agent.db、sidebar_threads、密钥与账本。现有侧栏分组无需删除。
