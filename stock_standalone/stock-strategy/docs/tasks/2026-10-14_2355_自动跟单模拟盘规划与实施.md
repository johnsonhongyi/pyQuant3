# 自动跟单模拟盘：规划、实现与验收边界

日期：2026-10-14。用户明确选择“先模拟盘全自动，验证后接实盘”。本地基线 `6e3899c2` 加工作区；现有交易引擎参数保持 v1.9。

## 已实现

- 根目录 `auto_follow.py` 是独立 Python 后台 worker，消费现有 Go HTTP API，不引入新依赖或券商执行接口。`--watch` 每轮完成后间隔 60 秒，非 A 股交易时段不请求行情；支持单次、状态、dry-run 和独立 kill。
- 连板路径：昨日至少二连板的主板非 ST 标的。题材路径：当日涨幅排名前三且上涨节点多于下跌节点的题材，每题材最多取五只后端 leader_stocks；合并去重后每轮最多检查 20 只。此排名是首版候选规则，不等同于旧关注池 score，不把 rank_score 冒充 min_pool_score。
- 共用当前 service/strategy.yaml 的 max_day_chg、amount_per_trade、max_positions、止盈止损、VWAP 止损和 kill 阈值；P8 量价与偏离、P25 日线 VWAP 排列和 MA20 另作数据完整性检查。本地默认读取当日盘前 sentiment 文件，缺失阻止新买；LXC 部署使用下述 Go 情绪门禁。持仓退出先于新买门禁。
- LXC 没有 PyYAML 和 Muse 当日情绪文件；发布包包含本地 v1.9 的无密钥 JSON 参数快照，不安装或升级库。EASY_STOCK_FOLLOW_MARKET_SOURCE=backend 时读取现有 Go emotion-history：盘中快照必须当日、非 stale、更新时间不超过 660 秒，高位报价覆盖率至少 75%；只允许“高位延续/高位震荡”且风险分 <40。它是独立跟单规则，不把原生风险分换算为 Muse -100~100，不声称等同 P2/P3/P5/P27。
- 首版为 `paper-follow-v1` 独立规则，不是完整 Muse 引擎替代品：不启用 P27 最低半仓，不做 P11/P12/P15/P18/P19/P20 的自动加减仓，也不覆盖原纸账户。时间止损沿用旧引擎自然日计算；不声称实现全部 P 规则。
- 新鲜行情要求 source/stale/fetched_at/trade_time，核验前收与涨跌幅一致；日线必须覆盖上一已完成交易日。VWAP 禁止估算，识别 Go TDX 的 volume_shares，拒绝未知单位。
- 只支持 00/60 主板、100 股整手，保留 7% 入场上限；连板股封板不假定成交，跌停卖出也不假定成交。模拟成交是最新报价参考，不代表真实可成交量、滑点或排队结果；股票费率沿用旧纸账户 0，绩效不能直接当实盘收益。
- 50 万独立初始纸资金；SQLite WAL + FULL 同步，一个事务原子提交现金、持仓、去重键和日志，BEGIN IMMEDIATE 串行写入。失败回滚，重启恢复；当日同股只买一次。熔断持久保存，解除需 `--kill off`；原引擎 kill 文件异常时阻止新买。
- 状态在独立 `logs/auto-follow.db`，生产必须通过 EASY_STOCK_FOLLOW_DB 指向外置持久化目录。原账本、生产数据库和正式群均不改动。事件最多保存最近 2000 条，closed 持续保存；后续统计归档不能删除账本事实。

## 运行入口

Windows 在项目根目录使用：

```powershell
python auto_follow.py --dry-run --db "$env:TEMP\easy-stock-follow-check.db"
python auto_follow.py --watch
python auto_follow.py --status
python auto_follow.py --kill on
```

Linux 宿主机在同一项目根目录使用 `python3 auto_follow.py --watch`，依赖既有策略 Python 环境；设置 EASY_STOCK_API_URL 为实际可访问的 API 地址（不能假定宿主机 127.0.0.1:20081），沿用服务 .env 的鉴权，不打印或复制凭据。设置 EASY_STOCK_FOLLOW_DB 为外置账户路径。
