# 行情外发限流与 TDX 日线闭环

## 目标

减少东财、同花顺等外部热榜和板块请求；A 股日线统一读取 Instock 的 TDX 文件底座，并避免将未完成回补的数据标为新鲜。

## 实现

- 热榜、行业/主题板块及板块成分请求按资源建立跨 Python/Go 共享冷却。成功后至少 30 分钟不重复外发，冷却在请求发出前原子占位，覆盖强制刷新和并发请求；不同板块成分各自限频，允许首次板块构建获取多个不同板块。
- 外部源返回 429 默认冷却 30 分钟，403 默认 60 分钟；读取 `Retry-After`，重复受限按指数增加冷却，最高 24 小时。冷却状态写入共享 SQLite，缓存过期时可回退带有缓存状态的旧热榜数据。
- Python 行情服务和 Go API 通过只读挂载读取 Instock `forwardp` 日线。启用共享 TDX 后，A 股日线不再回退外部日线源；Instock 盘后补入策略库时通过本地 API 批量读数。CN 盘后任务发现 TDX 目录缺失会失败关闭。策略盘后首轮安排在 16:20，17:20 重试。
- Instock 在请求盘后快照前先验证 TDX 股票代码清单；目录或清单不可用时不请求新浪快照、不创建替代空目录。回补统计输入、有效、处理、异常和历史缺口；任何输入行情未处理、无效 OHLCV、历史缺口未补、交易日历不可验证时，不写最终完成标记，保留重试路径。
