## 功能与入口

- 系统设置增加“AI 对话接入方式”：Hermes 本地运行时、桌面 Codex 登录账户可选。Codex 可选择已登记节点、动态模型目录和模型支持的推理强度，无需填写 API Key。
- 原 AI 对话保留历史、消息界面、停止按钮及状态回调，按所选运行时分发。Hermes 未安装不阻止单独使用 Codex；默认仍为 Hermes，不静默切换。
- Web 和项目桌面前端均同步公共组件与适配器。对话中也可选择已配置的运行时、模型和强度；当前运行的任务使用提交时配置，新消息生效。
- 普通对话续聊映射到同一原生 Codex thread；切换模型、强度或节点后使用新的会话关联，携带有界的历史上下文，不向错误运行时发送旧会话 ID。
- 沿用桌面每日模型目录刷新、升级后空闲切换及自动归组。只有声明 ai_chat_v1 的桥会被视作支持普通对话，旧策略桥在线不等于新能力就绪。

## 底层契约

```text
原 AI 对话 / 系统设置
  → 独立对话运行时配置与任务 API
  → 既有 control.db 中的独立 desktop_chat_* 表
  → 已登记身份 + HMAC 的 chat_claim / chat_result
  → Windows 独立桥 + 已安装 Codex app-server
  → 普通助手文本增量回传、会话映射、原对话历史
```

- 新增 GET/PUT /api/v1/ai/runtime，POST /api/v1/ai/desktop/jobs、GET/DELETE /api/v1/ai/desktop/jobs/{id}；通过既有 strategy HMAC 路由增加两个明确操作，不放宽为任意路径。
- desktop_chat_config、desktop_chat_sessions、desktop_chat_jobs 使用原外置 control.db。原策略 ai_jobs、提案校验及模拟执行门禁不变，普通聊天不能成为自动订单。
- 共享运行时修改需管理员；普通对话沿用已有登录/内网规则，逻辑会话及任务结果按用户隔离。校验节点、模型能力、队列容量、同会话并发、租约与超时，取消后拒绝回传并中断原生 turn。
- 普通对话只提供只读市场快照工具，沿用既有研究报告/心法上下文富化。禁用 shell 和网络检索、使用只读沙箱；不转交 Hermes Skills/MCP 或模型密钥。
- 原生成功结果先写桥自身账本，回传失败后可在租约重领时重放，避免重复调用模型。结果及配置均有明确错误状态，不用默认值伪装完成。
- Codex 登录凭据保留在桌面，Hermes 密钥继续由原 Hermes .env 管理；不将研究数据、会话数据库或凭据加入版本库。
- 新桥访问旧 API 的聊天接口 404/405 时继续原策略功能；旧 API 不提供运行时配置时前端保留 Hermes。其余认证/网络错误明确显示，不静默降级。
