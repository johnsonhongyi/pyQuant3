# 自动跟单控制台：设计、实现与发布验收

用户目标：在现有后台直接查看自动跟随板块、强势股、模拟买卖、持仓及未入场原因，并可控制自动跟单。范围继续为独立模拟盘，不接实盘，不全量迁移 Muse v1.10。

## 使用流程

1. 侧栏“自动跟单”，直达 `#auto-follow`，查看 worker 在线状态、心跳、当前轮次和模拟资金。
2. “跟随看板”设置连板/趋势题材路径；不选题材则动态择强，指定题材则在所选范围内择强。参数必须等控制回执后生效。
3. “强势股跟踪”查看候选、路径/题材、状态、报价时间和拦截原因，可按路径/股票筛选并打开现有个股分析。
4. “模拟持仓”查看 T+1、最近报价时间和浮盈；“成交与复盘”包含未平仓与已平仓交易、退出原因、累计已实现及平仓胜率。
5. “决策日志”和“控制指令回执”核对实际执行情况。暂停只停新开仓，继续监控退出；紧急停止可越过普通待执行指令，仍保留硬风控和时间窗。

## 实现契约

- Go 新增 `GET /api/v1/auto-follow`、`POST /api/v1/auto-follow/commands`，经过既有 API/Web 鉴权。外网登录用户须管理员才能控制；沿用既有内网访问政策，匿名 LAN 可控制。任何携带跨源 Origin 的控制请求拒绝；仅允许白名单模拟指令，不能输入账户路径、下单接口或修改资金。
- `account.db` 保存账户和交易事实；独立 `control.db` 保存指令与心跳。Go 只写控制库，worker 单写账户；行情扫描持有账户事务时不阻塞控制入队。
- 指令有唯一 ID、pending/applied/rejected 回执。worker 将处理过的 ID 与账户状态一起持久化，再确认控制库；进程故障后可重放幂等指令，不重复执行交易。候选买入前再次检查暂停/kill 待执行指令。
- worker 心跳在控制库即时更新，每次 API 调用前后刷新；界面每 5 秒读取，切到其它工作台后停止该轮询。账户和日志保持原子写入，状态 API 限制返回最近 300 条事件、200 笔平仓和 30 条回执。
- `paper-follow-console-v2` 是遥测/控制增强；既有 `paper-follow-v1` 账户可读，资金和持仓不重置。保留当前单笔/持仓/止盈止损参数，不接入 p22，不覆盖 Muse 原账本。
- API 容器 UID/GID 10001。账户目录使用 root:10001、2770，既有文件 0660，worker umask=0007，使 API 可访问独立模拟账户但不放开其它用户。预检查账户放在独立子目录，不与真实模拟控制队列混用。
- Web 入口落在实际发布的 `source/easy-stock-web`，使用原生深浅色变量与响应式表格；不误改未发布的另一套 frontend。
