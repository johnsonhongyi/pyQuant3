## 实现内容

### 1. 桥节点识别与管理器视图

- 管理器增加“后台桥名录”，汇总后台已登记桥、节点/工作区短标识、用途、心跳及后台运行/排队数；详细 ID 放在悬浮提示中。
- 管理器的桥状态判定不再仅凭 `bridge.pid` 是否对应一个存活 PID。只有桥状态处于活动状态且进程身份与桥运行目录/启动信息匹配时才报告运行，避免 PID 被其他程序复用后误报在线。
- 桥退出时仅清理与当前进程 PID 一致的 `bridge.pid`，避免旧 PID 文件残留。
- 独立 worker 的 stdout/stderr 写入运行目录日志；启动错误、阶段、操作、网络状态和系统 I/O 细节会展示为更易读的中文。
- 心跳时间解析兼容后端返回的 RFC3339Nano 与不同精度的 epoch 时间；名录与历史时间能够显示本地时间及相对时间。

### 2. Web 对话与 Codex 闭环可靠性

- Web 任务结果回写针对超时、网络错误及 HTTP 408/429/5xx 进行有界重试；成功结果先存入桌面本地账本，瞬时回写失败时保留结果并在任务重领后重放。
- Codex thread 恢复遇到过期/不存在的会话时会创建新会话继续执行，避免把“expired”直接显示为最终失败。
- 全链路检测会显示桥领取、引擎启动、工作区/会话准备、Codex 回复、结果回写等阶段和耗时；终态后清理 Web 临时 job/session。
- 桥接端先保存本机心跳状态再报告后端；网络错误记录错误阶段和系统原因，不因一次心跳故障丢失本地状态。
- 后台重试等待会逐秒检查停止请求；管理器请求停止后不必等待整个退避周期结束。

### 3. RAMDisk/PyInstaller 临时路径问题

- 用户截图中的失败路径为 `G:\Temp\_MEI263162`。PyInstaller one-file 的 `__file__` 可能位于该临时解包目录；把 Codex 项目路径放在这里会使运行目录依赖临时目录的生命周期和文件系统行为。
- 已改为打包运行时从 `sys.executable` 的位置推导应用安装根目录，并把 Codex 项目固定到安装目录下的 `stock-strategy\muse-research`；源码开发模式仍使用源码目录。
- 这修复了当前日志所指向的临时项目路径选择问题，但仍需在用户手动重打包后验证目标目录存在、当前 Windows 用户具有读写权限，以及实际 RAMDisk 文件系统的创建/原子替换行为。不能仅凭这一条 OSError 推断 RAMDisk 整体不可用。

### 4. 检测会话清理

- 全链路检测产生的 Codex thread 在终态后尝试归档；其桥本地 `chat_results` 与可用的 `sidebar_threads` 测试行会清理。
- 既有普通对话不会按检测清理规则删除。此前遗留的三个检测对话已通过 Codex 归档操作归档，不在活动会话列表中。
