# 2026-10-03 14:45 本地 AI 编程审计会话追踪时间排序修复、方案A严格单调递减与 --created 参数平滑回退闭环

## 任务背景与用户需求
在 `tools/codex_token_stats.py` 中，用户指出 `Session Route & Speed Audit` 会话追踪表中出现时间“跳回昨天”（例如 `10-02 20:17:00` 出现在 `10-03 12:56:11` 之前），询问会话排序依据。
- **根因核实**：排序依据一直为会话的【最新物理活跃时间（Last Active Time / mtime）】，但表格第 1 列打印的是【会话首次创建时间】。对于跨天长会话（如昨天创建、今天中午还在交互的会话），按活跃排在最前，但第一列显示昨天时间，引发视觉上的“时间倒挂”。
- **用户裁决**：采纳方案 A（默认以【最后活跃时间】展示且时间严格单调递减），同时支持参数开关（`--created` / `--show-created` / `--time-mode created`）切回原样式显示【创建时间】，以便查看活跃会话的创建起源。

---

## 核心实现与架构设计

### 1. 双时间戳采集与对齐 (Dual Timestamp Tracking)
- **Codex 适配器 (`get_codex_stats`)**：
  - 遍历 JSONL 交互日志时，精准记录 `session_first_time`（首次请求）与 `session_last_time`（最后一次交互输出）；
  - 兜底结合文件物理 `mtime`，构建 `created_time_str` 与 `active_time_str`；
  - 记录 `active_ts` 作为权威排序 Key。
- **Antigravity 适配器 (`get_antigravity_stats`)**：
  - 遍历 SQLite `gen_metadata` 与 `transcript.jsonl`，提取 `sess_first_dt` 与 `sess_last_dt`；
  - 结合 SQLite 文件的最新修改时间 `db_mtime` 确保包含最新一步的活跃时刻；
  - 同样记录 `active_ts`、`active_time` 与 `created_time`。

### 2. 方案 A 默认落地与时间严格单调递减 (Strict Monotonic Order)
- 默认状态下：
  - 表头第 1 列动态显示为 `活跃时间 (UTC+8)`；
  - 按照 `active_ts` 严格排序并倒序展示；
  - 列表自上而下时间 100% 严格单调递减，彻底消除“时间跳回昨天”的视觉倒挂缺陷。

### 3. 参数开关友好支持 (`--created` / `--time-mode`)
- 新增命令行参数：
  - `--created` / `--show-created`：快捷开关，切换显示会话首次创建时间；
  - `--time-mode {active, created}`：显式指定展示维度；
- 表头自适应：
  - 开启时表头自动变为 `创建时间 (UTC+8)`；
  - 列表仍然按最新活跃优先排序，方便用户一目了然看清当前活跃的会话究竟是何时启动创建的；
  - 表格底部的 `💡 指标物理定义说明` 动态提示当前模式的物理含义。
