# 2026-09-24 10:20 SBC 5日/10日多日分时跨日实时数据不更新根治与增量缓存全生命周期门禁加固

## 一、问题背景与现象
用户反馈：
- 昨天修复了 SBC 的多日缓存异常问题；
- 但是今日（2026-09-24）SBC 窗口中：
  - 1日分时图（1m）正常显示今日走势；
  - 5日分时（5d）与 10日分时（10d）最右侧完全缺失今日数据，走势折线和右侧现价标签停留在昨日（2026-09-23）收盘价 431.00 元，盘中不自动更新实时分时。

## 二、根因定位分析
1. **增量分时缓存 `get_incremental_intraday` 跨日锁死**：
   - 昨日收盘后所有条目被打上 `frozen=True` 并持久化到 RamDisk；
   - 今日开盘后，`get_incremental_intraday` 读取条目时未区分“盘中交易时段”与“盘后固化时段”，且未校验 `entry.get("date") == today_str`；
   - 盘中直接判定 `is_frozen=True` 且绕过 2.4s TTL，把昨日收盘数据作为 100% 命中的不可变缓存返回，彻底阻断了向 TDX 拉取今日增量数据的主通道。
2. **开盘跨日滑动窗口滚动检测自满短路**：
   - `__init__` 初始化直接将 `self._current_date_str = today_str`；
   - 导致开盘后 `_check_date_rollover` 因 `today_str == self._current_date_str` 而误以为“今天已滚动过”直接退出，无法执行滑动窗口向前滚动。
3. **`_load_from_ramdisk` 载入旧增量污染**：
   - 允许将 `cache_day < today_str` 的条目载入今日的 `self._incremental_intraday_pool`。
4. **`fetch_multi_day_intraday_bars` 短路校验不严格**：
   - 增量缓存命中后未校验是否包含今日数据就直接 return。
5. **分钟滞后粗暴返回空 DataFrame**：
   - 超过 15 分钟滞后时直接返回空，导致画幅白屏。

## 三、修复措施与实施
1. **`get_incremental_intraday` 重构与门禁**：
   - 实盘交易期（09:15~15:05）动态解除 `frozen` 锁死：`is_frozen = (bool(entry.get("frozen", False)) and not is_trading_active) or is_after_close`；
   - 跨日旧增量毫秒级淘汰：强校验 `entry.get("date") == today_str` 与 `today_str in df['date'].values`，昨日旧数据进入实盘期自动失效并从 pool 中清理；
   - 重构提取闭包 `_check_and_return_entry()`，消除 80 行 DRY 冗余代码。
2. **`_check_date_rollover` 滚动检测修复**：
   - 引入 `_last_rolled_date` 记录真实完成滚动的日期，开盘交易时段跨日自动触发滑动窗口向前滚动（淘汰最老 1 天，昨日并入静态历史不可变序列）。
3. **`_load_from_ramdisk` 与 `fetch_multi_day_intraday_bars` 双向拦截**：
   - 开盘交易时段从 RamDisk 丢弃昨日旧增量条目；
   - `fetch_multi_day_intraday_bars` 增加 `inc_has_today` 校验，未包含今日数据的缓存不直接 return；
   - 分钟滞后检查软降级为 warning/debug，保留数据平滑呈现。
4. **RamDisk 缓存净化**：
   - 清理所有旧增量条目，持久化为干净的今日实时状态。
