### 2. 尊重已有局部优化，拒绝重复造轮子与脏检查入口化
- **已有优化资产**：

- **重构着力点**：
  现有的指纹检查位于刷新链的末端（策略内部）。此时，主线程已经完成了网络/缓存取数、日志字符串拼装等大部分开销。**新脏检查必须移至刷新链的最入口（`reload_chart` 头部或调度器推送入口）**；同时指纹必须完整涵盖会改变信号与界面的核心维度（最新价、成交量、五档盘口、交易状态），一旦无变动直接阻断后续整条链路（包括日K通道获取、日志拼接与图元排版）。

### 3. 条件路径与缓存行为客观界定（剔除“每次必然”过满表述）
- `force=True` 确实会绕过 `mtime` 校验与 1.0s 节流，导致热路径反序列化开销；但系统内仍存在分钟数据 TTL 缓存（如实盘期 2.5s），且 [`1m` 分支 (line 6578)](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/ats/ui/intraday_strategy_dialog.py#L6578) 的多周期快照有 5.0 秒的内存冷却控制。
- 绝不承诺未经实测的“耗时直降 90%、20ms 完成”等空头数值，收益与瓶颈必须以基线实测的耗时、调用计数与阻塞分布为准。

### 4. 集中调度器的现实网络边界与报价转换复用
- **安全批次限制**：通达信 HQ 协议对单次批量行情查询存在报文长度约束，[`get_security_quotes_safe` (line 2957)](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/ats/tdx_realtime_fetcher.py#L2957) 明确以 40 只为一个安全 chunk。
- **报价转换逻辑复用**：集中拉取到的原始 quote 字典必须复用 [`fetch_stock_snapshot` (line 3142)](file:///d:/MacTools/WorkFile/WorkSpace/pyQuant3/stock_standalone/ats/tdx_realtime_fetcher.py#L3142) 的转换逻辑（处理 VWAP、流通盘换手率计算、价格突刺平滑等），将标准快照注入缓存并派发。
- **协议客观现实**：TDX 协议中分时 K 线 (`get_security_bars`) 必须逐标的单独请求，无法跨股票单包批量拉取。调度器仅能做到“标的去重”与“分时增量统一调度”，不能承诺所有股票分钟 Bar“一次网络包搞定”。

### 5. 定时器瓶颈客观归因
- `snap_timer` (200ms) 与 `_geo_save_timer` (350ms) 均为 `setSingleShot(True)` 单次防抖定时器，在用户拖动/拉伸窗口结束后触发一次即停止，不是盘中持续高频空转的主要原因。
- 核心瓶颈在于各个窗口长期运行且在 UI 主线程执行同步调用的 `poll_timer`。治理焦点集中在 `poll_timer` 的收敛，非核心定时器待实测唤醒代价后再行决策。

### 阶段 1：缓存止血（Cache Pool Hardening & De-forcing）
- **实施内容**：
  1. **热路径移除 `force=True`**：
     - 将 `get_static_history_bars` (line 1473)、`set_static_history_bars` (line 1528)、`get_multi_day_df` (line 1570) 及 `set_incremental_intraday` (line 1687) 调用的 `_maybe_sync_from_ramdisk(force=True)` 中的 `force` 改为 `False`；
     - 依赖 `now - self._last_mtime_check_ts >= 1.5`（1.5 秒节流）与 `mtime > self._last_ramdisk_mtime` 的正常文件版本探测机制。
  2. **跨进程语义保全**：
     - 保留 `invalidate` (line 1817) 中的强制同步与代际清除写入逻辑；
     - 保留 `_load_from_ramdisk` 针对外部进程代际递增时的丢弃逻辑；
     - 保留损坏缓存自愈（corrupt pickle 自动清理）与跨日开盘滚动（`can_rollover`）逻辑。
  3. **检验逻辑前置与按需化**：
     - 将耗费 CPU 的 `_validate_and_repair_records`（包含中位数、正则等）固定在写入端（`set_static_history_bars`），反序列化读入时仅做轻量数据结构合法性检验，杜绝读取时的全量数组中位数风暴。
- **验收标准**：
  - 本地缓存命中时完全不触发磁盘文件读取与反序列化；
  - 另一进程更新或 `invalidate` 后，本进程在 1.5~3 秒内平滑感知并正确同步；
  - 极端损坏文件或进程强退中断后重启，缓存能安全恢复不崩溃。

### 阶段 2：窗口异步打开与两阶段渲染（Two-Phase Instant Open）
- **实施内容**：
  1. **剥离构造函数主线程 IO**：
     - 移除 `SBCIntradayChartDialog.__init__` (line 4597) 中的同步 `self.reload_chart()`。
  2. **两阶段秒开机制**：
     - **第一阶段（瞬间响应）**：优先从内存快照（`VWAPFactory` / 本地已存 snapshot）读取数据直出第一帧；若无任何数据（冷启动），直接展示整洁的高质感深色骨架屏与基准刻度，主线程耗时压至微秒级，窗口瞬时呈现，键盘鼠标绝无迟滞；
     - **第二阶段（异步取数与回填）**：通过后台 Worker 线程发起实际的数据拉取，数据获取完毕后通过 Qt 信号传递给 UI 线程更新画布。
  3. **过时请求防护 (Epoch / Request ID Guard)**：
     - 异步请求附带 `(stock_code, period_mode, request_id)`；
     - 窗口在等待返回期间若发生标的代码切换、周期模式切换或窗口关闭，直接将旧序号的返回数据就地丢弃，杜绝时序错乱导致脏数据覆盖当前画幅。
- **验收标准**：
  - 无论网络延迟如何，无论是否断线，打开窗口及连续打开 5 个持仓窗口时，UI 界面保持完全可交互（鼠标不转圈、窗口随意拖拽移动）；
  - 切码与切周期无串屏、无旧数据闪烁覆写。

### 阶段 3：进程内集中订阅调度中枢（In-Process Dispatcher）
- **实施内容**：
  1. **构建单例 `SBCRealtimeDispatcher`**：
     - 运行于后台守护线程，维护当前进程内存活 SBC 窗口的订阅表 `{code: Set[window_ref]}`；
     - 窗口在 `showEvent` 时注册，在 `hideEvent` / `closeEvent` 时注销。
  2. **批量报价拉取与标准化**：
     - 每 2.5~3.0 秒（遵循全局 `cct.ats_tdx_interval` 退避策略），提取去重后的订阅代码集；
     - 按每批最多 40 只分批调用 `get_security_quotes_safe`；
     - 复用 `fetch_stock_snapshot` 的算法将原始行情转化为包含 VWAP 与换手率的标准快照，注入 `_quotes_cache` 并广播至对应窗口。
  3. **分时分钟 Bar 协同增量更新**：
     - 监控各标的分钟边界变动，由后台线程按需拉取当日增量 Bar 并送入 `VWAPFactory.sync_frame`；
     - 调度验证等价稳定后，平滑废除各窗口独立的 `poll_timer`。
- **验收标准**：
  - 同一进程无论打开多少个观察相同股票的窗口，每轮调度对同一股票只发起 1 次报价拉取；
  - 窗口关闭后自动停止请求，无孤儿订阅；
  - 网络断线或异常时限流退避正常，无任务堆积。

### 阶段 4：入口级脏检查与渲染去重（Dirty Check & Render Decoupling）
- **实施内容**：
  1. **刷新链入口脏检查**：
     - 在窗口接收更新通知的入口处，维护前序状态指纹：
       `entry_fp = (last_price, turnover_rate, volume, last_bar_time, bar_count, current_period_mode, is_trading_active)`；
     - 若最新行情与状态指纹等价：
       仅刷新顶部标题或微调现价 Label（耗时忽略不计），彻底短路跳过日K网络获取、8层防守策略评估（`_eval_vwap_proactive_strategy`）、日志文本格式化及 Canvas 重绘。
  2. **多日分时与 1日分时数据源统一**：

- **验收标准**：
  - 稳定横盘或非交易时段，主线程绘图与重算次数压降至接近零；
  - 数据变动（如价格跳变、产生新一分钟 Bar）时，图表与策略标记准确、即时更新，与重构前信号 100% 吻合。
