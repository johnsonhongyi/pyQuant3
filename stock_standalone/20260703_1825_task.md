# Task: K线备份查看器 (KlineBackupViewer) 保存确认弹窗与多数据表 HDF5 保存拦截防御

## 目标
防止用户由于无意点击“Save Changes”导致文件静默覆盖，并彻底杜绝在加载多数据表（HDF5/`.h5`）文件时，因直接调用 Pickle (`to_pickle`) 保存覆盖而导致原始 HDF5 文件被格式覆盖损坏、其他 Table 丢失的严重 Bug。
1. **保存前置确认与路径展示**：点击“Save Changes”时，弹出双重确认框（`QMessageBox.question`），并详细展示将要保存的目标物理文件路径，交由用户决策。
2. **保存成功后置提示**：保存成功后弹出通知框（`QMessageBox.information`），明确提示已成功写入的具体物理文件路径。
3. **拦截多数据表 HDF5 文件直接保存**：在保存逻辑中，检测当前打开的文件类型，如果是 `.h5` / `.hdf5` / `.hdf` 格式，则直接拦截并弹出警告提示，禁止保存以避免文件损坏。

## 具体变更
1. **重构保存确认与提示逻辑 (`minute_kline_viewer_qt.py` 中的 `on_save_changes`)**：
   - 内存模式同步：在调用 `service_proxy.kline_cache.from_dataframe` 前，增加 `QMessageBox.question` 同步确认框；同步成功后，通过 `QMessageBox.information` 反馈成功。
   - 文件模式保存：在执行 `to_pickle` 写入磁盘前，检测当前文件的后缀名 `ext`。
   - 如果 `ext` 为 `.h5`、`.hdf5` 或 `.hdf`，则弹出 `QMessageBox.warning` 说明保存被拦截的原因（防多数据表覆盖丢失），并不再执行写盘动作，实现拦截保护。
   - 如果为其他单数据表格式（如 `.pkl`），则弹出 `QMessageBox.question` 确认框，展示待写入的文件全路径，用户确认后再执行 `to_pickle`。
   - 写盘成功后弹出 `QMessageBox.information` 展示已保存成功的完整文件路径，且状态栏反馈同步。
2. **编译与验证**：
   - 使用 `python -m py_compile` 工具对 `minute_kline_viewer_qt.py` 执行了物理编译校验，确认逻辑结构和缩进均正确，编译通过。
