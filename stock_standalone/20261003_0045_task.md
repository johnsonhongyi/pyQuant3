# 2026-10-03 00:45 任务：全面解决 ATS Nuitka 打包体积偏大问题与多周期打包配置深度优化对齐

## 背景与问题诊断
- 用户反映：
  1. TK 打包后（93.4 MB）小于 PyInstaller（95.36 MB）；
  2. 多周期打包后（64.69 MB）小于等于 PyInstaller（63.55 MB）；
  3. 唯独 ATS 打包后（71.95 MB）居然比 PyInstaller（66.06 MB）大出近 6 MB！
- 经全量解压对比与深度分析，排查出 5 大体积膨胀根因：
  1. **MFC 动态库与 win32ui 冗余拷入**：包含 `mfc140u.dll` (5.35 MB) 和 `win32ui.pyd` (1.09 MB)，ATS 代码 0 行依赖 MFC，系 `pywin32` 未排除导致；
  2. **强行 `--include-module=pandas/numpy/pyqtgraph/sqlite3`**：严重破坏了 Nuitka Anti-bloat 摇树优化机制，强行引入上百个未用到的子模块与格式后端；
  3. **强行枚举 30 多个 `ats.xxx` 子模块**：破坏 Nuitka 模块依赖图，应按照用户指示不强行包括 ats，让 Nuitka 自动分析依赖处理；
  4. **全量 `--include-package=trading_kernel`**：硬塞了 151 个 Python 模块 Clang C 编译进二进制，而 ATS 仅需几个数据类；
  5. **重复打包 Windows Runtime DLLs**：Nuitka 默认打包了 MSVC 运行时，应传入 `--include-windows-runtime-dlls=no` 依赖系统原生 UCRT。

2. **`nuitka_build_ats_console_onlyClang.bat` 稳健配置二次校准**：
   - **IPO 学习与自学习交易链保障**：经排查 `gate_orchestrator` 与 `unified_paper_account` 动态调用链路，规范保留 `--include-package=trading_kernel` 及 `contracts`, `gateway`, `kernel_service` 核心模块（仅几百 KB 纯 Python），并排除 `trading_kernel.tests`，100% 杜绝 `--ipo-learning` 独立自学习模式运行时缺失动态模块；
   - **Win10/Win11 任意纯净系统开箱即用**：移除 `--include-windows-runtime-dlls=no`，恢复默认随包打包微软 VC++ 运行时动态链接库（约 1.5 MB），杜绝全新未装运行库的 Windows 报错丢失 `VCRUNTIME140.dll`；
   - **底层行情联动 100% 安全**：明确排除的是 `win32ui`（微软老旧 MFC 框架包装，0 行依赖，省下 5.35MB `mfc140u.dll`），而用于通达信/同花顺联动与窗口管理的底层核心 `win32gui`、`win32api` 完整保留；
   - 移除 30 个繁杂的 `ats.xxx` 机器码强行编译枚举，让 Nuitka 自动分析依赖，根除主程序二进制虚胖。
3. **`nuitka_build_multi_period_dialog_onlyClang.bat` 同步优化**：

   - 补充 `--nofollow-import-to=win32ui`，添加 `--noinclude-dlls=mfc140u.dll`、`mfc140.dll`；
   - 移除 `--include-windows-runtime-dlls=no`，对齐跨机器系统运行库保障；
