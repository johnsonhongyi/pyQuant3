# 2026-09-27 14:35 任务跟踪：全面审核 TK 监控端后台 CPU 异常占用与非交易日底层逻辑 Bug 诊断及修复

## 1. 任务背景与问题现象
- **现象描述**：
  - 用户反馈启动 Nuitka 打包的 TK 监控端后，主进程 `Stock Monitor` (PID 14460) CPU 占用率达 **18.6%**（单核 100% 跑满），内存占用突破 **1032.5 MB**。
  - 用户重新启动 Python 原生开发环境后，主进程 `Stock Monitor` (PID 19748) CPU 占用约 0.7%，内存约 862.4 MB。
  - **核心痛点**：当前是非交易日（2026-09-27 星期日），市场没有任何行情更新，后台如此高的 CPU 占用与内存膨胀完全不合理，底层逻辑存在严重缺陷。

## 2. 深入排查与实证分析（Root Cause Analysis）
通过对实时进程线程监测、`instock_tk.log` 运行日志以及底层源码的深度剖析，查实系统在非交易日存在 **五大核心底层逻辑 Bug 与无谓自耗链条**：

### 🚨 缺陷 1：`data_utils.py` 中 `fetch_and_process` 启动时穿透非交易日检查
- **位置**：`data_utils.py:3345`, `data_utils.py:3528`
- **根因**：
  - 变量 `START_INIT` 初始值为 `0`。
  - 循环入口处的非工作时间拦截条件写为：`elif START_INIT > 0 and not cct.get_work_time():`。
  - **严重 Bug**：启动首轮循环时 `START_INIT == 0`，非工作日拦截直接失效！`fetch_and_process` 强行无差别读取 5555 只股票的 HDF5 历史数据（耗时 5.8s），执行全量日线指标计算管线，并将全量 5555 行大字典推入 `mp.Queue`，瞬间引发主进程内存暴涨与多线程级联计算！

### 🚨 缺陷 2：`stock_live_strategy.py` 时序颠倒与非交易日误判
- **位置**：`stock_live_strategy.py:1386`, `stock_live_strategy.py:1451`, `stock_live_strategy.py:1463`
- **根因**：
  - **交易日误判**：第 1386 行 `is_trading_active = (915 <= now_time_int <= 1505)` 仅仅检查了当前时钟是否处于 9:15-15:05，完全没有调用 `cct.get_trade_date_status()` 检查是否为交易日！在周日下午会被误判为活跃交易中。
  - **时序致命颠倒**：向多线程池提交 100 只监控股票的全量形态与策略检测 `self.executor.submit(self._check_strategies, ...)`（单次耗时达 4.58 秒！）竟然写在 `if not is_trading:` 的前面！虽然 1463 行获取了 `is_trading = False`，但大计算早已被提交并发执行，导致非交易日后台无休止进行 V 型反转与诱多跑路扫描！

### 🚨 缺陷 3：`sector_focus_engine.py` 龙头扫描与 30 分钟同步缺失交易日守卫
- **位置**：`sector_focus_engine.py:2688-2694`
- **根因**：
  - 代码在 30 分钟整点强制扫描逻辑中，仅根据 `0 <= m_offset <= 330` 判断是否处于 9:30-15:00，完全未结合 `cct.get_trade_date_status()`。
  - 日志实锤：周日白天每 30 分钟准时触发 `[Controller] 到达 30 分钟同步节点, 触发全量引擎对齐`，在非交易日疯狂对 5000+ 股票执行全量板块对齐与集中破位检测（`_scan_pullbacks` 报出 73 只破位、24 只龙头信号），持续消耗宝贵算力。

### 🚨 缺陷 4：`instock_MonitorTK.py` 非交易日周期性后台轮询空转
- **位置**：
  - `instock_MonitorTK.py:2370-2377`：`_bg_kernel_heartbeat` 每 15 秒提交一次 `bg_kernel_auto_execute_once`，无休止对持仓进行模拟买卖与止损扫描，并被 `trade_gateway` 拦截报错。
  - `instock_MonitorTK.py:6990-6995`：启动后触发 `warm_up_indicator_cache`，将 5542 只股票的指标全量刷入内存缓存，直接吃掉上百兆内存。
  - `instock_MonitorTK.py:6858`：`_apply_tree_data_sync` 在非交易日仍每隔 `duration_sleep_time` 触发一次 `_inject_focus_engine`，强行驱动后台交易决策。

### 🚨 缺陷 5：Nuitka 编译环境下的 C-Loop 吞噬单核 CPU 放大效应
- 原生 Python 解释器受制于字节码评估循环（每 5ms 强制切换 GIL），在计算间隙释放 CPU。
- Nuitka 将密集数学与状态机逻辑编译为原生 C 循环，缺乏显式休眠时会独占单核 CPU；结合上述四大非交易日频繁触发的重度运算，使打包版进程瞬间占满 1 个 CPU 核心（18.6%）。

## 3. 优化与修复方案规划
1. **数据源层彻底截断非交易日空转**：
   - 优化 `data_utils.py`：在 `START_INIT == 0` 的冷启动阶段，若检测为非交易日（`not cct.get_trade_date_status()`），仅快速读取一次离线静态盘面供 UI 显示，随后立即进入长周期待机（如 120s 甚至 300s），绝不再重复拉取与重算。
2. **策略与板块引擎增加前置非交易日熔断**：
   - 优化 `stock_live_strategy.py`：将交易日与交易时段判断移至 `_check_strategies` 与 `_scan_hot_concepts` 提交之前。非交易日或非交易时段，直接快速返回，0 秒开销。
   - 优化 `sector_focus_engine.py`：30 分钟整点强制对齐必须增加 `cct.get_trade_date_status()` 守卫，非交易日坚决不触发后台全盘重算。
3. **主进程后台心跳节流与静默模式**：
   - 优化 `instock_MonitorTK.py`：非交易日降低 `_bg_kernel_heartbeat` 频率或跳过买卖决策；UI 心跳与调度循环在长闲时拉长 interval，使 CPU 彻底归零（<0.1%）。
