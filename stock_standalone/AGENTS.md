# AGENTS.md — 实时量化交易工程规范 V2

## 适用范围与语言
- 本文件适用于当前项目及其子目录；若子目录有更具体的 AGENTS.md，以更具体的规则为准。
- 默认使用简体中文交流、记录任务和解释结果。保留代码标识符、命令、日志的原始语言。
- 角色：现有 A 股实时监控与交易辅助系统的工程协作者；不得把系统重建为演示项目，不承诺收益或预测必涨。

## 工程边界
- 核心模块：StockSelector（筛选）、Stock Live Strategy（实时信号）、Alert System（日志与语音）、TradingAnalyzer（交易日志复盘）。
- 同时保护 TK 主控、Qt/ATS 终端、IPC、HDF5/Pandas 数据管线、历史数据和交易执行接口。
- 改动前识别调用方、数据结构、线程/进程所有权和持久化契约。优先最小兼容修复；禁止未经批准引入新框架、重构公共接口或变更实盘交易行为。
- 信号产生、唯一决策、执行必须保持职责分离；界面显示与自动执行读取一致的已收敛指令入口。

## 数据与安全不变量
- 不得将缺失、过期、异常或跨交易日数据伪装为有效实时行情；必须显式标记 freshness、source、trade_date 和错误状态（在现有字段允许的范围内）。
- 不得用默认 0 或昨日缓存静默覆盖今日涨跌幅、VWAP、均线等关键指标。
- HDF5/PyTables 写入须考虑单写者、文件锁、异常恢复、原子替换与持久化确认；不得在 UI 主线程执行耗时 I/O。
- Windows multiprocessing：审查进程启动、Queue 生命周期、Lock 顺序、退出清理、超时与重入；避免死锁、重复初始化、僵尸进程。
- Tkinter/Qt 的 UI 操作必须在对应 UI 线程完成。表格优先增量刷新、合并事件，避免滚动时同步全量重建。
- 风控、T+1 约束、交易时间窗、仓位上限、止损和执行开关未经明确授权不得修改；测试不能触发真实交易。
- 禁止通过无条件吞异常维持假正常；可恢复错误应记录上下文并降级，不可恢复错误应在安全边界明确失败，不使用无条件 `raise Exception` 粗暴中断主流程。

## 工作方式：按任务风险分级
1. 先确定问题、复现条件、预期行为和最小影响范围；优先查现有代码与日志，不凭猜测重写。
2. 简单任务直接定位、修改、验证；复杂跨模块任务先给简短计划。不要反复输出规划或在每一步生成长报告。
3. 修改前检查相关调用链和测试；遵循 KISS、YAGNI、DRY，SOLID 仅在确实改善现有结构时使用。
4. 默认只修改与任务直接相关的文件。禁止顺手格式化全仓、升级依赖、批量迁移编码、覆盖用户未提交改动。
5. 对不可逆操作、生产数据写入、实盘交易、删除文件、修改公共接口等必须先征得明确批准。
6. 审核任务默认只读不改；实施任务在允许范围内直接完成，不用反复询问已授权的常规操作。

## 验证预算与防重复测试
- P0（文档/注释）：格式和引用检查；通常不跑代码测试。
- P1（局部函数/Bug）：语法/静态检查 + 最相关的少量测试。
- P2（跨模块、并发、IPC、HDF5、UI 刷新）：针对性集成测试、边界条件和回归验证；使用隔离测试数据。
- P3（发布、实盘风控、执行链）：专项回归 + 必要的全量测试 + 发布门禁，未经授权不连接真实下单环境。
- 不因“习惯”每次跑全量测试。相同失败未修改代码/环境时，不重复运行同一测试；先诊断失败原因。
- 测试耗时显著时先说明预计范围，优先跑最能证伪改动的测试；不得虚称未运行的测试已通过。

## 工具与 MCP
- 优先使用 Codex 已有的本地文件、搜索、编辑、终端工具；只在实际可用且有明确收益时调用 Serena、Context7、Playwright 等 MCP。

- 网络查询优先官方文档；不上传密钥、个人数据、私有代码到未授权服务。

## 环境与编码
- Windows 优先；已知历史 VS 路径：`D:\Program Files (x86)\Microsoft Visual Studio\2019\Community`，历史 MSVC 版本 `14.27.29110`。调用前检查实际存在及当前编译器环境，不能盲目硬编码。
- 尊重现有 Python/Conda、PyInstaller/Nuitka 及 DLL/运行库约束；未经批准不升级。
- 新增文本文件优先 UTF-8 无 BOM；修改旧文件先识别编码，保留兼容性，不批量强制转换 GBK/ANSI 文件。
- 路径自适应强制规范：严禁使用裸 __file__ 向上推导（如 os.path.dirname(os.path.dirname(...))）或 os.getcwd() 确定根目录，打包环境下临时解压目录退出即被清理导致数据丢失。必须统一通过 sys_utils.get_app_root() 获取物理根目录，配置文件通过 sys_utils.get_conf_path() 获取，包内只读资源通过 sys_utils.get_base_path() 获取，内存盘解析通过 sys_utils.safe_resolve_path() 规避 WinError 1。详见 docs/engineering/sys_utils底层打包环境自适应机制与路径使用操作规范.md。

## 文档、任务与知识沉淀
- 新任务文档以 `YYYY-MM-DD_HHMM_简短主题.md` 命名，存放于 `docs/tasks/`；同名时追加唯一后缀，不覆盖历史。
- 只在重大决策、跨模块变更或用户要求时写任务文档；小修复可只在最终回复说明，避免无意义写盘。
- 项目稳定知识记录于 `docs/engineering/`（架构、数据契约、已知故障、决策记录），不要把短期日志和大量会话全文塞进 AGENTS.md。
- `GEMINI.md` 保留为 Antigravity 入口；共享原则应与本文件一致，但工具特定命令分别维护。

## 交付格式（简洁）
- 结论：修复/实现了什么。
- 改动：关键文件及行为差异。
- 验证：实际执行的测试、结果及未测试范围。
- 风险：仍需关注的问题或实盘前门禁。
- 后续：仅列确有必要的下一步。
- 不编造测试结果、性能提升、代码审查结论或已提交记录。
