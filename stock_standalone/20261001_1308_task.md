# 任务清单：ATS 性能优化与深度加固全面闭环 (20261001_1308)

## 任务背景
在初轮 ATS 性能优化的基础上，结合第二轮静态代码审查发现的 6 项关键深度隐患（Worker 线程销毁崩溃风险、TDX 超时软边界、历史读取异常退避遗漏、归档锁与快照一致性风险、策略过滤 UI 线程同步计算、名称缓存永久短路滞后），进行全面深度技术加固与代码级修复，建立包含 9 项专项测试的完整自动化回归测试矩阵，并全量回归验证。

## 深度加固对象与实施清单
1. **[P1] 全球行情面板 Worker 线程协同退出与生命周期解耦** (`ats/ui/global_market_panel.py`)
   - 引入 `self._stop_event` 与 `stop()` 方法，在网络请求与并发循环中增加中断检查；
   - 创建 Worker 时设 `parent=None`，由模块级 `_ACTIVE_GLOBAL_WORKERS` 保持活引用防过早 GC；
   - `closeEvent` 中断开信号连接并触发 `stop()`，面板销毁时不再引发 Qt C++ `Destroyed while thread is still running` 致命崩溃。
2. **[P2] TDX 批量扫描硬超时边界与非阻塞关闭** (`ats/channel_bottom_reversal_strategy.py`)
   - 废除 `with ThreadPoolExecutor` 隐式阻塞等待，改用 `try...finally` 显式纳管；
   - `finally` 中执行 `executor.shutdown(wait=False, cancel_futures=True)`，取消待决任务且绝不阻塞等待正在执行的慢请求，主线程毫秒级硬返回；
   - `wait()` 引入小切片轮询超时 `step_timeout = min(0.15, max(0.01, rem_sec))`，最多等待 150ms 即可感知取消与超时。
3. **[P2] 历史数据读取异常纳入 30 秒退避** (`ats/ui/main_window.py`)
   - 彻底清除 `_time.time() - (300 - 10)` 的历史遗留逻辑，在 `last_err is not None` 时同步将当前时间写入 `self._history_lock_fail_times[code] = fail_ts`；
   - 准入过滤 `is_lock_conflict(c)` 支持 `c` 与 `c_clean`，将锁冲突、文件缺失与读取异常统一纳管至 30 秒有限退避 TTL。
4. **[P2] 归档缓存锁范围精简与 Pending 原子快照** (`ats/bounded_evaluation_store.py`)
   - `read()` 缓存命中时锁内仅提取不可变引用与版本号，锁外执行 `copy.deepcopy`；
   - `put()` 与 `append()` 在获取锁前提前在锁外完成版本与收盘日 stat 查询，锁内零文件 I/O；
   - `pending()` 在持锁期内原子生成不可变快照 `copy.deepcopy(entry["value"])`，彻底消除锁外复制被并发 `append()` 原位修改导致的列表撕裂与大小变动异常。
5. **[P2] 策略过滤移出 UI 线程与 Revision 异步安全提交** (`ats/ui/main_window.py`)
   - 将 DataFrame 拷贝、列重命名映射与 `query_engine.execute` 全部移入后台 Worker 线程，UI 主线程仅递增请求版本并启动线程，UI 耗时 0ms；
   - 结果投递接入 Qt 信号 `_filter_eval_ready = pyqtSignal(int, object)`，通过 `QueuedConnection` 跨线程安全投递；
   - 主线程增加 Revision 校验：仅当 `req_rev == self._filter_eval_revision` 时才更新 `filtered_codes_set`，防止旧计算结果覆盖新行情帧或新公式。
6. **[P2] 名称缓存跨日重置与 60s 增量同步（更名/ST 覆盖）** (`ats/ui/main_window.py`)
   - 引入跨日自动失效机制：检测到日期变更时自动重置 `_name_cache_initialized = False` 和 `_last_name_cache_sync_t = 0.0`，次日开盘首帧必定全量重扫；
   - 准入条件收敛为 `_last_sync_t == 0.0 or _cur_len > _last_len or (_now_sync_t - _last_sync_t >= 60.0)`：冷启动或行数扩容即刻就地同步；此后每 60 秒允许一次极速原地字典覆盖（耗时 <1ms），60 秒内 0 纳秒跳过，兼顾更名时效与零线程开销。
