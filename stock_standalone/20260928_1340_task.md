# 2026-09-28 13:40 新浪行情接口 502/网关超时卡死根治与 HDF 缓存优雅降级加固任务

## 任务背景与核心痛点
用户反馈在运行 TK (`instock_MonitorTK.py`) 时遇到持续的报错：
```
ERROR:commonTips.py(get_url_data_R:4369): socket timed out error:HTTP Error 502: Bad Gateway - URL http://vip.stock.finance.sina.com.cn/...
```
并且反映两个严重业务与工程痛点：
1. **网络与接口风控**：新浪官方接口因高并发请求出现 502 Bad Gateway 网关超时与频率限流；
2. **TK 流程彻底卡死**：系统发生网络受阻后，未能加载本地持久化的 HDF5 缓存（Cache）数据，导致 TK 初始化和轮询主干流程被完全挂起，无法继续后续流程。

---

## 根因深度剖析

1. **网络底层深藏 30s/60s 异常死锁休眠**：
   - `JohnsonUtil/commonTips.py` 中 `get_url_data` 发生异常时竟然调用 `sleeprandom(60)`；
   - `get_url_data_R` 发生除 456 以外的异常时调用 `sleep(30)`；
   - `JSONData/realdatajson.py` 中 `_fetch_with_delay` 在被封禁状态下执行 `await asyncio.sleep(600)`（整整 10 分钟死等）；
   - 在高并发多线程或网络抖动时，线程池和异步任务瞬间全部被长休眠打满，主线程彻底僵死。

2. **HDF 缓存“假缺失”与穿透误判（Cache Miss）**：
   - 入口处调用 `load_hdf_db(h5_fname, table=h5_table, limit_time=limit_time)`，未传 `timelimit=False`；
   - 当本地持久化缓存时间超出 `limit_time`（默认仅几分钟）时，底层的 `load_hdf_db` 判定过期直接返回 `None`；
   - 导致程序以为“本地无缓存”，完全跳过了所有缓存复用逻辑，盲目冲向网络；
   - 而网络因 502 报错后，上层又未写入 HDF，导致每一次循环都重复判定为 None，陷入“拉取失败 -> 未写HDF -> 再次强拉 -> 卡死”的死循环。

3. **URL 构造阶段的级联超时（CountURL）**：
   - `_get_sina_Market_url` 为获取 `sh_a`、`sz_a`、`hs_bjs` 三大市场的股票总数，在构造 URL 时对每个市场均发起网络请求；
   - 一旦网络受阻或被代理拦截，每个请求超时卡顿数秒，三次请求直接导致主线程在未开始拉取数据前就卡死十几秒。

## 实施改进与修复方案

### 1. 通信协议与防风控参数加固
- **协议全面升级为 HTTPS** (`JohnsonUtil/johnson_cons.py`):
  - `JSON_Market_Center_RealURL` 与 `JSON_Market_Center_CountURL` 升级为 `https://vip.stock.finance.sina.com.cn/...`。
- **现代浏览器请求头强化** (`JSONData/realdatajson.py`):
  - `sinaheader` 统一采用现代 Chrome UA 与标准 `Referer: https://finance.sina.com.cn/`，规避新浪反爬与网关拦截。
- **并发批次与错峰降速** (`JSONData/realdatajson.py`):
  - 默认 `batch_size` 从 50 调降至 8，盘中动态限制在 3~8，彻底废除数十并发冲击；
  - 同一批次内的并发请求增加 `stagger_sec=idx * 0.08` 错峰延迟，避免瞬间脉冲打穿网关。

### 2. 彻底拔除网络底层长休眠锁
- **清除 `get_url_data` 的 `sleeprandom(60)`** (`JohnsonUtil/commonTips.py`):
  - 异常时仅轻量避让 0.5s 并立即 break 返回控制权。
- **清除 `get_url_data_R` 的 `sleep(30)`** (`JohnsonUtil/commonTips.py`):
  - 遇 502/503/504 轻量 sleep 1s，遇其他异常 sleep 0.5s，超速释放调用方。
- **根除 `_fetch_with_delay` 中的 600s 死锁** (`JSONData/realdatajson.py`):
  - 冷却状态下使用 `[SINA-COOLING-SKIP]` 快速跳过并返回 None，单次请求超时缩紧至 3.5s。

### 3. URL 构造内存缓存与级联熔断
- **引入 `_MARKET_COUNT_CACHE` 与静态兜底** (`JSONData/realdatajson.py`):
  - 内置 `sh_a: 2350`, `sz_a: 2980`, `hs_bjs: 280` 默认股票总数；
  - 仅在首次且网络无异常时探测 1.5s，一旦异常立即使用预估值，0 毫秒完成 URL 列表构造。

### 4. HDF5 本地缓存保底与秒级优雅降级
- **无条件加载快照，杜绝 None 误判** (`JSONData/realdatajson.py`):
  - 入口处显式传入 `timelimit=False`，确保内存始终握有磁盘上真实的 5474 行股票全集。
- **三层极速拦截（0 毫秒穿透）**：
  - **拦截 1**：处于冷却期或 10 分钟内曾发生失败，直接返回本地缓存（0.06s）；
  - **拦截 2**：非交易日（周末/节假日）直接复用本地缓存（0.06s）；
  - **拦截 3**：缓存时效内或强制缓存直接返回（0.06s）。
- **批次调度硬熔断与回退保底**：
  - 单个批次加入 `asyncio.wait_for(..., timeout=4.5)`；
  - 只要批次异常或超时，5 秒内立即触发 `[SINA-FAST-FAIL]`，优雅降级返回已加载的 5474 行 HDF 缓存继续后续主流程，并记录 `last_failed_ts` 保护后续 10 分钟不再死循环冲撞网络！
