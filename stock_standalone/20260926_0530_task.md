## 优化分析与补充维度规划

- [x] **维度 1：候选池历史追踪与评估行查找的微观性能瓶颈闭环**
  - 剖析 `_candidate_row_lookup` 内部对 5000 行全市场宽表的切片、`copy()` 与最慢的 `iterrows()`（逐行构造 `pd.Series`）；
  - 揭示循环中针对每一个历史候选重复调用 `_candidate_row_lookup(df, [candidate])` 引发的 $O(K \times N)$ 宽表重复拷贝遍历灾难；
  - 规划方案优化：单次索引字典投影（Single-Pass Dict/Array Projection），将 $O(K \times N)$ 降至 $O(K + N)$，淘汰 `iterrows()`；
  - 历史追踪文件扫描有效交易日窗口剪枝（Trade-Day Window Pruning），消除全历史目录无界 glob 扫描；
  - 脏检查免重写机制（Dirty Flag），阻断 checkpoints / stats 无变动时的重复原子落盘写放大。

- [x] **维度 2：Qt 渲染重构风暴与表格列宽性能灾难治理**
  - 揭示 Tab 2 中 `_on_eval_loaded` 与 `_on_event_row_selected` 每次刷新无条件调用 `resizeColumnsToContents()` 引发的全表单元格字体包围盒（font metrics）遍历与几何重排计算，以及用户自定义列宽被粗暴覆盖的缺陷；
  - 规划方案优化：彻底废除数据刷新路径上的 `resizeColumnsToContents()`，仅在首次构建时初始化；
  - 自动刷新定时器（3s）的主线程同步 I/O 消除与视口可见性、窗口最小化、非今日历史日期三重短路守卫。

- [x] **维度 3：Windows 平台并发文件锁竞争与原子替换健壮性**
  - 揭示 Windows NTFS/ReFS 下 `os.replace` 在目标文件被并发读取打开时抛出 `PermissionError` (WinError 32 / WinError 5) 的真实工程风险；
  - 规划方案优化：跨进程原子交换工程模式（文件级互斥/重试退避/抖动，临时文件故障保护与自愈，杜绝静默失败导致的数据分歧）。

- [x] **维度 4：配置系统只读快照化与主线程无感知写入**
  - 揭示主线程轮询每 4 秒调用 `load_config` 并内嵌损坏自修复写盘的隐患；
  - 规划方案优化：配置只读单例快照（Immutable Config Snapshot），启动单次加载，文件变动驱动热重载，彻底将自修复从热路径剥离；
  - `save_config_nodes` 异步化队列（Config Write Queue），彻底根除主线程中因文件锁竞争导致的累计高达 450ms 的 `time.sleep`。

- [x] **维度 5：业务事件两阶段持久化确认协议（2PC-like Reliable Delivery Protocol）**
  - 揭示当前 `emit(signal)` 后立刻调用 `mark_events_delivered` 假交付致命缺陷（队列入队不等于消费端持久入库）；
  - 规划方案优化：两阶段交付确认机制（`PENDING_DELIVERY` -> 消费者事务落盘 -> 回传 `EVENT_ACK` -> 原子翻转 `DELIVERED`，超时未确认安全重发，配合幂等去重彻底杜绝信号丢失与重复消费）。

- [x] **维度 6：休市板块确定性负缓存与容量模型、验证矩阵升级**
  - 非交易日板块缺失的期限负缓存，消除每 5s 的无意义 glob 与 gzip 解压；
  - 容量模型升级：精准反映行查找与历史剪枝的数学复杂度优化；
  - 验证矩阵升级：增加 WinError 32 锁竞争注入测试、`resizeColumnsToContents` 零调用门禁、两阶段事件确认重放测试。
