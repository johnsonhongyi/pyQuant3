## 一、任务背景与解决的问题

1. **历史架构痛点**：
   - 历史代码中，核心行情与缓存适配模块 `JSONData` 一直游离在项目包外（位于 `/data/InStock/JSONData`，而主业务在 `/data/InStock/instock`）；
   - 导致大量脚本必须依赖 `sys.path.append("/data/InStock")` 才能导入，且部分新策略中试图直接调用 `from instock.JSONData...` 会静默失败，项目内模块层级和包导入路径严重不一致；
   - 长期以来由于缺乏规范的 Git 版本库，日常热修复依赖多层 Dockerfile 和 shell 脚本重复构建镜像，容易引入镜像漂移、覆盖丢失与更新问题。

2. **核心目标与交付成果**：
   - **路径规范统一**：将 `JSONData` 完整规范化纳入 `instock/JSONData/` 内部，成为官方标准包路径 `instock.JSONData`；
   - **全面同步关联文件**：重构更新所有消费模块（`stockfetch.py`, `strategy_enter-edit.py`, `prewarm_history.py`, `run_statistics.py` 及内部跨引用），支持自适应优先从 `instock.JSONData` 导入；
   - **向后兼容零风险**：在 `__init__.py` 中自动注入兼容别名，并在容器根目录建立软链接 `/data/InStock/JSONData -> /data/InStock/instock/JSONData`，保障历史外部脚本绝对零故障；
   - **生产热部署安全落地**：在 `strategy_enter.lock` 保护下原子部署至 LXC 102 生产容器 `inStock`，全模块语法与导入验证 100% 绿灯；
   - **制作独立 InStock Git 版本库**：导出 13MB 纯代码资产至本地 `InStock` 目录，配置严格的数据挂载过滤规则（`.gitignore`），初始化独立 Git 仓库并完成首版提交；以后直接使用版本控制进行同步，彻底告别重复 Docker 构建。
