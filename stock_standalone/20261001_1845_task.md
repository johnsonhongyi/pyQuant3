## 2. 核心架构与工程设计

### 2.1 原生二进制 Protobuf 轻量解码器 (`decode_protobuf`)
- **原则**: KISS + 零外部依赖。不引入任何体积庞大的 `.proto` 编译或三方库；
- **实现**: 原生 Python 实现 Varint 与 Length-Delimited 递归解析，直接解构 `gen_metadata` 二进制数据。

### 2.2 字段语义与指标确诊
- `Field 1 -> SubField 19`: 模型名称（`gemini-3.8-flash`, `gemini-3.8-flash-n`, `claude-sonnet-4-6` 等）；
- `Field 1 -> SubField 4`: 性能指标：
  - `tag 2`: 新增未缓存输入 token (`uncached_input_tokens`)
  - `tag 3`: 输出生成 token (`output_tokens`)
  - `tag 5`: 命中缓存的输入 token (`cached_input_tokens`)
  - `tag 9`: 思考/推理 token (`reasoning_output_tokens`)
  - 总输入 Prompt = `uncached + cached`，总消耗 = `Prompt + Output`，缓存命中率 = `cached / Prompt * 100%`（实测稳定在 90.6% ~ 92.9%）；
- `Field 1 -> SubField 11`: API 执行总时长（包含 TTFT 首字等待）；
- `Field 1 -> SubField 12`: 原生流式阶段耗时（`stream_dur`）。

### 2.3 性能优化与毫秒级预过滤
- 本地历史可能包含上百个数据库（实测 191 个）；
- 引入基于 `os.path.getmtime` 的时间戳预筛选：仅对修改时间处于 `cutoff_ts` 范围内的 DB 进行 SQLite 连接读取；
- 全库 191 个数据库扫描耗时从数秒压缩至 **0.2 ~ 0.5 秒**！
