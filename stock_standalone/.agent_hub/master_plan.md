# ATS 多 Agent 主计划

## 最终目标

把 ATS 从“异动提示工具”升级为可审计的交易决策系统：市场事件感知 -> 结构信号 -> TradePlan -> 风险闸门 -> 模拟执行 -> 次日盈亏复盘 -> 参数迭代。

## 角色

- GPT/Codex（主脑）：架构、任务拆解、代码审查、验收、风险决策、迭代规划。
- Antigravity（执行）：按任务书实现、测试、提交证据，不决定实盘上线。
- 用户（最终负责人）：确认盘感是否被正确表达，批准高风险变更和实盘开关。

## 阶段

### P0：协作控制面（当前）

- [x] 文件驱动任务状态机
- [x] 任务模板与执行协议
- [x] 原子领取、提交、审查、归档 CLI
- [x] 状态看板和事件审计日志
- [ ] 用真实任务完成一次端到端演练

### P1：交易能力审计与事件感知

- [ ] 审计新股/次新股现有信号链、缓存和交易中心连接
- [ ] 建立市场事件数据契约和市场阶段状态机
- [ ] 生成可回放的 `MarketContextSnapshot`
- [ ] 将事件阶段映射到信号阈值和仓位上限

### P2：验证闭环

- [ ] 首日/次日/第 3-10 日分层回放
- [ ] S4/S5 信号逐笔归因
- [ ] 次日盈亏、最大回撤、错失与误报日报
- [ ] GPT 仅提出参数候选，回测通过后人工批准

### P3：受控自动化

- [ ] 自动扫描、自动任务生成、自动测试和自动审查
- [ ] 模拟盘自动执行
- [ ] 实盘保持硬风控和人工授权

## 硬约束

- `AUTO_MERGE=OFF`
- `AUTO_REAL_BUY=OFF`
- `AUTO_REAL_SELL=OFF`（结构止损自动化需单独批准）
- 任何 Agent 不得读取、输出或修改券商密钥。
- 同一业务文件同时只能属于一个 `running` 任务。
