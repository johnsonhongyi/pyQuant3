# 持久历史缓存与全策略扫描

## 已部署行为

- 镜像：`instock:johnson250103-sina-runtime-perf-hotfix10f-20261006`，直接基于既有 hotfix9 构建，不依赖本次中间试验镜像。
- 默认保留最近 150 条交易记录；突破平台 210、低 ATR 260、回踩年线 310、均线多头最多 1000。均线多头实际包含月线 MACD，不能统一截成 150 日。实际条数受原历史查询范围和源文件覆盖限制。
- 缓存位于原持久挂载 `instockcache/hist`，采用定长 NumPy 数组和元数据。日期存为 int32，常量列只保存一次，数值保持原精度。重复运行映射缓存，不重新解析完整 TDX 文本或旧 pickle。
- 每批最多 64 只股票，同一批依次计算所选策略，释放历史 DataFrame 后加载下一批；不再构造全市场历史大字典。逐股检查仍使用最多 2 个线程，策略之间复制输入，避免污染。
- 网页两策略、勾选策略、全策略入口以及盘后策略入口均接入分批扫描。盘后进入策略阶段前释放此前历史单例；此前指标、形态阶段仍使用其既有流程。
- 交易日 08:20 使用原共享锁初始化基线，节假日跳过。150 日默认预热，长周期只预热已使用过的缓存；首次选择长周期策略时按需构建。源版本未变仅推进元数据，不重解析源文件。
- 同一股票盘前只读取最大的必要窗口一次，再派生较短窗口，避免多个缓存规格重复解析源文件。
- 静态运行增加结果缓存：对行情内容、历史源/缓存版本、交易日期、窗口、策略及关联代码、库版本和机构榜依赖作指纹验证。完全相同的输入直接恢复结果并更新对应表，跳过历史 DataFrame 构造和计算；实盘报价运行仍重新计算。最多保留 32 组缓存，策略选择子集可以复用已有全策略结果。
- 交易日当前报价独立叠加，基线在当日不反复重建。非交易日仅给恰好缺上一交易日的基线追加已持久行情；更长历史缺口不补造 K 线。显式历史日期范围使用完整日期指纹，避免串用最新基线。
- 扫描完成并验证覆盖率/错误数后才发布结果；全策略不重复执行回测，仍由既有独立回测任务补充。
- Docker 仍限制 2 CPU、1280 MiB、无容器 swap，CPU shares 256；未增加 iKuai/PVE 的资源争用上限。

## 统计与验证

- 最近 10 次统计继续持久化；运行中也记录处理数、缓存命中、实际源读取、峰值 RSS、I/O 和分阶段耗时。
- 新增各策略结果摘要哈希，按股票排序后生成，便于验证重复运行一致性；记录 `history_gap_stocks`，区分历史缺口与性能问题。
- Windows 与实际 Linux 容器 21 项测试通过；覆盖真实 mmap、精度、缓存隔离、版本推进、分批边界、失败时不发布、盘后单例释放、最后交易日追加、单次盘前读取及结果缓存数据/代码/外部依赖失效。
- 全市场基准使用独立统计库、共享策略锁和 `INSTOCK_SCAN_DRY_RUN=1`，不写策略结果表。缓存补齐、全策略热运行、两策略热运行分别报告，不将补齐阶段冒充纯冷启动。
- 网页命中结果缓存时显示“静态结果缓存”，`cache.result_hits` 单独记录；不会把结果复用误报为逐股计算耗时。
- 扫描期间采样：inStock Docker 约 224 MiB，PVE 可用约 1433 MiB，I/O PSI avg10 some/full 约 0.06%/0.03%；默认网关 20 次探测 0 丢包。这是采样证据，不代表无限期连通性保证。

## 数据边界

现场发现部分 TDX 文件最后记录为 2026-08-18，而行情表已有 2026-09-30 报价。缓存可以加速现有数据，不能修复缺失的中间交易日；缺口单独记录，不通过一根最新行情伪造完整历史。150 日原型曾使均线多头少命中一只，已据实际月线依赖增加窗口，该原型计时不作为最终效果。

最终实测结果在完整基准完成后补充。
