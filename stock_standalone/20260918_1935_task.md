# 2026-09-18 19:35 任务记录：新股检测工具自动轮询后台测评与集中交易中心全局统筹（山外有山）

## 1. 核心业务诉求与痛点
- **操盘手现场明确指示 (P0)**：
  > “新股检测工具的自动轮询,后台更新后会对守护的code进行测评感知,交易中心需要接受各自守护的提交的报告,根据全数据继续交易,需要全面整体的能力,不能各管一摊,自己看着自己守护的个股很好不知道山外有山”
- **核心痛点**：
  1. 单守护标的测评感知后处于局部盲区，只看自身走势，误以为形态良好可重仓，不知道全池已出现 9:31 拔地而起的 96 分超级首发领头羊（如沈鼓集团）；
  2. 交易中心缺乏汇交全数据横向仲裁机制，无法对跟风标的进行“山外有山·禁止分仓”的统筹拦截；
  3. 缺乏持续交易闭环：持仓动能衰竭时无法自动执行“弃弱留强·换马调仓（SWITCH_SWAP）”，且缺乏统一的订单执行通道与集中交易指挥室。

## 2. 架构设计与工程落地 (KISS / SOLID / DRY)
1. **守护者客观体检报告汇交机制 (Guardian Perception & Report Submission)**：
   - 扩充 `VWAPDetectorSignal` 包含：`global_fleet_role`、`global_arbitration_desc`、`relative_to_leader_gap`；
   - 守护标的后台自动轮询更新后，生成体检报告统一汇交至 `IPOTradingCenter.submit_stock_perception_report()`。
2. **交易中心掌握全数据横向赛马与“山外有山”统筹仲裁 (`ats/strategy/ipo_trading_center.py`)**：
   - 全池冒泡赛马确立绝对标杆领头羊（Top 1）；
   - 计算各标的相对领头羊差距（`relative_to_leader_gap`）；
   - 赋予全局仲裁角色：
     - `LEADER` (🥇 领头羊)：全池第 1，重仓配资 35%~40%；
     - `VANGUARD` (🥈 梯队前锋)：Top 2~3，顺风配资 15%~20%；
     - `FOLLOWER` (🥉 后排跟风·山外有山)：明确提示落后领头羊 XX 分，资金聚焦头部，禁止分仓追高；
     - `STOP_LOSS` (⛔ 买错立斩)：跌破 VWAP 0.6% 坚决清仓；
     - `CLIMAX_EXIT` (🚨 高潮平仓)：偏离 VWAP 极限且天量滞涨，锁定翻倍胜果；
     - `ICE_ABORT` (❄️ 全局冰点)：次新池站稳率不足 20%，全员避险。
   - 将仲裁决议反哺回写到各 signal 对象，驱动表格每行操盘决议实时显示全局仲裁。
3. **持续交易闭环：弃弱换马调仓与订单撮合执行**：
   - 引入 `SWITCH_SWAP` 指令：当持仓标的动能滞涨落后（差距 >= 20分），而全池涌现出更强的 Rank 1 领头羊时，果断卖出弱势持仓，资金无缝切换至新领头羊；
   - 支持 `execute_all_pending_directives()` 一键执行，以及 `set_auto_follow_trading()` 全自动跟随交易；
   - 精确维护可用现金、持仓股数、持仓均价、浮动盈亏与峰值回撤。
4. **集中交易指挥室弹窗 (`ats/ui/ipo_command_room_dialog.py`) 与主看板联动**：
   - 在主看板顶栏新增【🚢 集中交易指挥室】快捷按钮；
   - 弹窗呈现：全数据赛马天梯、实盘持仓组合、待执行指令清单、一键批量执行决议与全自动跟随交易开关。
