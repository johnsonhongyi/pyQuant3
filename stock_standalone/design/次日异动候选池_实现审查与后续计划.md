# 次日异动候选池：实现审查与后续计划

审查日期：2026-09-25。范围：当前工作区的 TK 盘前冻结、ATS TDX 轮询、候选账本、检测中心与考核文件。本文记录现有实现的复核结论及待办，不表示已完成实盘验证；配置继续保持关闭。原《次日异动候选池_最小侵入落地计划》中的 TK 盘中确认和 SIGNAL 传输设想已由 ATS 轮询架构取代，以本文件描述的当前接线为准。

## 当前结论

- 已有盘前清单、A/B/C 通道模板、TDX 候选轮询、两帧事件、日考核及检测中心展示的基本链路。
- 两帧仅按本机轮询时间判断，没有验证 TDX 报价确实更新；相同报价重复两次可确认。成交额或成交量无效时，TDX 转换器把现价写入 `vwap`，下游又将其当作真实 VWAP。
- 事件在 Qt 信号发出后即写为 `delivered`，没有 ATS 账本成功准入的回执。检测中心写入本地 `signals_map` 后只刷新指挥室界面，未立即向交易中心提交感知报告。
- 配置中的 `required_fields`、`followup.proof_any` 未实际控制对应准入/后验；启用的模板仅允许 `channel_stepup`。盘前任务在成功生成清单前就记录当日已冻结，失败、关闭或源数据未就绪不会自动重试。
- 每轮完整改写随采样增长的考核 JSON，并扫描全部历史清单；4 秒只是定时器目标，尚无端到端时延实测。

## 修复顺序与完成标准

| 顺序 | 最小改动 | 可验证完成标准 |
|---|---|---|
| P0-1 报价证据 | 在 ATS 轮询适配处保留源行情时间或可验证的成交量/成交额序列与接收时间；同一报价、倒退序列、午间/盘后缓存不得充当新帧。仅当 `amount>0`、`vol>0` 且单位核验通过时提供 `vwap`，否则记不可验证。 | 用重复报价、缓存报价、空量额、时间倒退、跨午休五类样例回放，均不得产生确认；两份有效新报价在 8 秒内可确认。 |
| P0-2 交付闭环 | 保留事件未交付状态直到 UI 处理结果和 `LedgerUpdateResult.entry` 成功，并明确持久化边界；拒绝、异常和进程重启后按稳定 `event_id` 重试。处理前不写已见；一票多策略的来源信息可查。 | 模拟账本拒绝、Qt 回调异常和重启：事件不丢失；成功重放不产生重复账本记录或重复提醒。 |
| P0-3 盘前冻结 | 从预处理完成标记核验宽表交易日期为 T，目标日为 T+1；确认全市场数据完整、配置有效后才提交冻结成功。失败允许在 09:15 前重试，留有明确错误状态。 | 关闭后开启、首次宽表未就绪、字段缺失、日期错位、后台异常均不生成错误清单；数据就绪后可在窗口内成功补冻且只冻一次。 |
| P0-4 后验一致性 | 收盘结论基于当日全部有效检查点和首次确认事件，保留首次新高/VWAP 上移时间；目标日成功不得再标 `DAY_MISS`，目标日未命中后走强只记 `DELAYED`。VWAP 不可用单独记证据缺失。 | 回放“早盘确认、尾盘 VWAP 走平”“全天无有效报价”“次日才突破”，事件与按版本统计互不矛盾。 |
| P1-1 配置兑现 | 让 `required_fields` 真正阻止该策略该股票入池并计 `data_invalid`；`proof_any` 决定后验判定。对更多策略先复用已注册谓词组合，仍只使用 T 及以前字段；配置变更只影响未冻结目标日。 | 缺任一必需字段不会入池；两个策略各自计数；当日改配置不改变已冻清单和考核规则。 |
| P1-2 性能与 UI | 只读取观察期内尚未完结的历史候选；盘中保留有限检查点及首次证据，关键状态增量落盘；文件扫描和 JSON 解析移出 Qt UI 线程。 | 以实际候选池做整日负载回放，记录 TDX 拉取、计算、落盘、Qt 响应 p50/p95 与漏采率；p95 两帧间距满足 8 秒门槛，UI 无明显停顿。 |
| P1-3 中心联动 | 检测中心将确认事件以明确的“只观察”来源提交交易中心的感知/展示路径，指挥室读到相同 `event_id` 与策略版本；不得因展示事件生成下单动作。 | 端到端跟踪同一事件在日文件、ATS 账本、检测中心、指挥室的时间与状态，断线重连幂等。 |
| P1-4 板块与竞价 | 将 TK 盘前板块快照与 ATS 当日竞价/热点快照按板块标识、采集时间衔接；缺失或过期显式标记，不改变已有个股证据。 | 09:25 前后及开盘时能看到板块同向/背离、快照时间和缺失状态；旧快照不能冒充当日联动。 |

## 启用与验证流程

1. 先做隔离回放：固定 T 日宽表、两类 TDX 报价和配置版本；覆盖重复帧、无效 VWAP、跨日、失败重试、同代码多策略、午间与断线。保存候选文件与事件断言；这一步不连接真实交易动作。
2. 在真实 TDX 环境观察至少一个完整交易日，记录原始 `vol/amount/price/high`、单位、可用时间字段、服务端与本机时间差、40 只分批耗时和缓存返回比例；由实测确定候选容量及 4 秒目标是否可达。
3. 对照 TK 盘前宽表的来源日期、全市场行数与 `last*` 字段含义，核对股票代码和板块映射。每次冻结保留输入日期、配置哈希、候选数与失败原因；不使用盘中行情补盘前历史特征。
4. 完成 P0 后，功能仍以影子模式观察至少 5 个交易日：人工核对目标日新高、真实 VWAP 上移、`DAY_MISS/UNVERIFIABLE/DELAYED`，并比较提示时间与实际启动时间。按 `strategy_id+version` 报候选数、确认率、目标日命中率、延后率及缺证率；不凭 5 日样本决定策略收益。
5. P1 闭环与影子运行通过后，再在下一交易日前开启配置。先限定少量候选和观察来源，逐日查看延迟、漏报、误报与 UI 负载；异常时关闭开关并保留原始日文件便于复盘。参数迭代必须升版本，只作用于以后冻结的交易日。

## 当前审查复现

- 临时目录输入一只满足通道条件的股票，配置额外声明缺失的 `lastv4d` 为必需字段：清单仍入池 1 只，`invalid_count` 为空。
- 将同一份 `high=11, trade=11, vwap=10.4` 报价在 09:30:01 和 09:30:05 重放：第二次生成 `NEXT_DAY_WATCH_CONFIRM`，其中 `verified_vwap_rise=false`。
- 以上是确定性本地复现；真实 TDX 轮询时延、字段口径与端到端联动仍未验证。
