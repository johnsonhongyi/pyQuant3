## 二、Antigravity 复审报告的事实校正

1. **“没有自动回退”已过时。** 当前工作区保留的仿真产物 `data/ipo_learning_simulation/20260928T115828-3554f3-antigravity_cli/simulation_manifest.json` 记录：请求 Provider 为 `antigravity_cli`，实际 Provider 为 `codex_cli`，主 Provider 错误为 `SCHEMA_OUTPUT_NOT_JSON`，Worker `submitted=1 / succeeded=1 / failed=0`，交互日志 1 条。
2. **“UI 未接入”不准确。** 学习台已读取运行状态和交互日志，并在冷启动时立即执行一次只读状态刷新；之后市场活跃时约每 2 秒轮询，非活跃时最长 60 秒轮询。这是轮询式呈现，不是事件推送，也不构成生产运行授权。
3. **“15/41 就绪”与当前证据不一致。** 当前 `data/ipo_learning/acquisition.latest.json` 记录 10/41、`UNREADY`，生成时间为 2026-09-28 17:38:48（香港时间）。该快照到本次复核时已陈旧；未找到与报告中 15/41 同时间、同配置哈希的产物，不能把两个数字当成连续可比的进度曲线。
4. **合成 `ENTRY` 不能作为 Gate 生产验收。** 上述仿真产物使用合成输入，Gate 结果为 `ENTRY`、RiskGate 为 `APPROVED`，但 `real_data_used=false`、`order_submitted=false`、`real_trading_enabled=false`、`production_qualified=false`。它证明的是测试夹具、Worker、Provider 回退和日志链，而非真实门禁上下文或订单链。
5. **仿真产物的 Gate 4 解释文本早于当前代码修正。** 产物仍显示旧的“数据不足”解释；当前 Gate 4 代码和回归断言已改为按上市日龄描述适用 VWAP 结构。旧产物不应作为当前 Gate 4 文案快照。
6. **“本地 Antigravity SDK 已接入”不成立。** 当前配置选中 `antigravity_cli`，模式标为 `remote_api`；`antigravity_sdk` 是 `local_litert` 配置，但模型路径/哈希/模型 ID 为空。CLI 仿真使用临时授权配置，不能代表正式配置已开启。
7. **自动回退有启动前置条件。** 当前工厂在组装双 Provider 路由时，会先要求两端 CLI 路径和专用 `scratch_cwd` 都存在；因此当前能证明的是“两端已可启动时，主端响应失败可回退”，不能证明“AGY 缺装/路径失效时仍由 Codex 自动接管”。

## 三、本轮稳定性问题与处理

### 已修复

- `JSONData/realdatajson.py`：非交易日只返回本地缓存，跳过 Sina 冷启动/残缺缓存网络请求；交易日状态读取异常时按关闭处理。
- `stock_live_strategy.py`：非交易时段在任何策略扫描/线程池提交之前返回；保留交易日 15:00 后的一次性日结算。
- `popularity_resonance_gui.py`：相同快照不重复写盘；自动持久化设置 5 分钟间隔并在冷却期跳过完整序列化；临时文件按进程/线程区分，降低 Windows 并发覆盖冲突。
- `ats/ipc_bridge.py`：非交易时段收到差分时不推进版本游标；下一次活跃时段先请求一次全量基线，避免旧缓存与后续增量静默错位。
- `popularity_resonance_gui.py`：TDX 同步工作线程即使刷新抛异常也会排队完成/重试回调；Tk 已关闭无法排队时清除忙状态，避免永久假忙。
- `ats/strategy/gate_orchestrator.py`：Gate 4 放行因果说明改为上市日龄适用结构，避免把合法的早期上市结构误报为数据不足。

### 本轮测试暴露并已补的回归

复跑发现此前“性能保护”未实际处于当前 HEAD：Sina 非交易日冷启动仍触发刷新；策略在非交易日仍提交 `_check_strategies`。已将两道保护补入真实入口，并由既有回归用例验证。收盘结算路径仍保留。

### 尚未关闭的首刷时延验收

`get_sina_Market_json()` 在交易日没有 HDF 基线或缓存不足 1000 行时执行同步首刷，这是 ATS 冷启动获取首份行情的既定契约，不能为了追求表面“零阻塞”而取消或改为空快照。`_SINA_REFRESH_LOCK` 让并发请求不等待首刷锁，直接返回当前缓存；首刷失败后后续调用仍可能重试。剩余验收点是确认首刷调用线程及真实耗时：若调用落在高频轮询或 UI 线程，需把首刷移到后台并保留完成通知/重试；若由启动工作线程承接，则按现有首刷契约保留。非交易日不应触发首刷。
