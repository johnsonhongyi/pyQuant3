# 次日异动候选池：最小侵入落地计划

状态：按方案实施首版，并已按实时数据源约束调整接入。TK 只在盘前基于全市场宽表冻结清单；盘中两帧（间隔不超过 8 秒）、高点与 TDX 成交额/成交量 VWAP 验证由 ATS 的 TDX 实时报价驱动，确认后进入 ATS 账本及新股次新股检测中心/指挥室。功能默认关闭；需在真实 TDX 环境验证轮询节奏与字段口径。目标是在每日既有全市场盘前预处理之后，按自定义策略生成次一交易日分层候选池，持续跟踪“企稳→抬升→加速”，并按策略版本逐日评估；不直接生成买入指令。

## 3. 数据契约：先通过，再谈筛选

时间基准为最近**已收盘**交易日 `T`，清单供下一交易日 `T+1` 使用。盘前不得把实时 `close/high/low/vol` 当作 `T` 的历史日线。数据准备完成的判定依据须取现有预处理流程的“完成版本/交易日期”，不可仅凭文件修改时间；索引日期、宽表日期和 `T` 不一致则不生成清单。

所有策略共同必需：六位 `code`、可靠的已收盘交易日期、行情新鲜度、可交易状态。其余字段由策略逐项声明：通道企稳示例需要 `lastp/lasto/lasth/lastl/lastv1d..5d`、`ch_dir`、`ch_slope_deg`、`ch_lower`、`ch_pos`、`td_sell`；另一策略不必被通道字段阻断。具体列名、计量单位和“1d=最近已收盘日”应在实施首步对实际宽表抽样确认；不存在的列不可用当天值或相邻列静默补齐。某策略字段不足时，该策略对该股票记 `data_invalid`，其他策略仍可正常筛选。

可选字段：`category`/概念映射、市场指数历史日线、成交额和同时间段量能基线。没有这些字段时保留个股结构观察，但板块或相对强度项显示“缺失”，不能当作零分或用旧缓存填充。VWAP 验证只接受真实且已确认计量单位的 `成交额/成交股数` 或可信的显式 VWAP；`ats/intraday_strategy_engine.py:2597` 中四价均值、现价等兜底值不可当作 VWAP 上移证据。

## 4. 可自定义盘前策略：只用 T 及以前的信息

每个模板有稳定 `strategy_id`、`version`、`enabled`、`required_fields`、`universe`、`pre_filter`、`tiers`、`rank_weights`、`capacity`、`followup`。`pre_filter` 支持白名单特征上的 `all/any`、`> >= < <= == between` 和固定日线滞后引用；配置加载时校验字段、单位、日期边界、运算符、权重及范围，错误模板单独禁用并报错，绝不“解析失败返回全市场”。不执行任意 Python/SQL 表达式。可将已核验的 TK 字段注册为特征；不因要配置策略而改动查询引擎。

先把全市场一次性转成向量化特征表，再让多个启用模板共享计算结果。一个股票可以同时进入多个模板；盘中只订阅候选代码并集，但保留各模板的入池理由、评分、失效边界和后验结果。模板配置在目标交易日 09:15 前冻结，记录哈希；当天盘中不得根据已出现的走势修改当天规则。

下面的 A/B/C 是**通道企稳模板**的初始配置示例，所有阈值待回放校准；其他模板可定义自己的层级、条件和观察期限。

| 层级 | 首版条件与说明 | 次日重点观察 |
|---|---|---|
| A 通道底部 | `ch_dir=1`、`ch_slope_deg>1.5`、`5<=ch_pos<=60`、`lastp1d>=ch_lower*0.985`、`td_sell<5`。过去 3–5 日至少两次低点不再明显下移；十字星按 `abs(收-开)/max(高-低,最小跳动)` 小于约 0.3 记加分，不作所有形态的硬门槛。 | 通道下沿及最近 2 日低点是否守住。 |
| B 逐级抬升 | 满足 A，且 `lasth1d>lasth2d>lasth3d`、`lastl1d>lastl2d>lastl3d`；容忍一个小于约 1% 的高点停顿时降级为观察，不误判为完全破坏。若有指数历史，近 3 日相对大盘逐日走强加分。 | 昨高、昨日收盘、前一日低点；竞价板块是否同向。 |
| C 温和蓄势 | 满足 B，且近 3 日量能逐步改善：`lastv1d/lastv3d` 约在 `1.1–2.5`，三日中至少两日量比前一日不低于 `0.9`，单日不出现 `>3.2` 的突发放量。昨日大阳或近 3 日已大涨只降低“提前发现”优先级，不自动删除。 | 次日量价协同是否启动，还是高开冲高回落。 |

示例模板排序先按 C>B>A，再用通道位置、低点抬升幅度、温和量能、相对指数强度和过热惩罚排序；每层容量如 A 100、B 60、C 40 也由模板配置。这些是**容量上限而非命中阈值**，应按实际观察容量和后验命中率调整，不沿用现有动量模块的 top 5 输出。

用户给出的 `lasth{1-3}h` 应按日线核成 `lasth{1-3}d`；`lastl{1-3} > lastl{1-3}` 是自比较，应为 `lastl1d>lastl2d>lastl3d`。`{OR:per{1-9}d>6}` 用于识别已经大涨的股票，不应作为提前发现的必要条件。

配置形状示例（仅展示关键字段，数值不是已验证参数）：

```json
{
  "strategy_id": "channel_stepup",
  "version": 1,
  "enabled": true,
  "pre_filter": {"all": [{"field": "ch_dir", "op": "==", "value": 1}, {"field": "ch_slope_deg", "op": ">", "value": 1.5}]},
  "tiers": [{"id": "A", "rule": "support_stable"}, {"id": "B", "rule": "higher_highs_lows"}, {"id": "C", "rule": "gentle_volume_growth"}],
  "followup": {"trading_days": 3, "proof_any": ["daily_high_break", "verified_vwap_rise"], "failure_consecutive_checkpoints": 2}
}
```

`rule` 是已注册特征/谓词的名字，不是动态执行的代码；模板可组合或调阈值，但新增底层特征仍需先核验口径和日期。配置更新只影响未来清单，历史模板按原配置哈希回放。

每日重新预处理时，用 `strategy_id+code` 对接前几日尚在观察期的候选，保留 `first_selected_date`、连续入池天数、A→B→C 阶段迁移、首次确认和连续未进展次数。新候选、继续走强、降级、退出分别记原因；当天退出的记录仍留在后验考核分母中。由此可以看见“先企稳、后抬升、再加速”的过程，而不是每天重新生成一张互不相干的股票名单。

## 5. 次日状态与信号边界

| 时段 | 更新规则 | 可写入 ATS 吗 |
|---|---|---|
| 盘前清单 | 各启用模板从 T 日宽表生成自己的 `WATCH_<层级>`；固定关键价位、特征、原因码与模板版本。 | 否，仅待观察。 |
| 09:15–09:25 集合竞价 | 从现有 `racing_detector` 读板块 `score`、`score_diff`、`follow_ratio`、`leader`、`ts`；按代码的现有板块映射做精确归属。仅使用当日且新鲜的快照；09:20 后尤其记录 09:25 附近状态。`板块走强+个股相对强` 提高优先级，板块转弱则降级。 | 否，竞价只留观察/种子。 |
| 09:25–09:30 等待开盘 | 锁定最近有效的竞价快照，标出最后更新时刻；此段不视为新的连续竞价行情。 | 否。 |
| 09:30–09:45 开盘确认 | 仅扫描清单内代码；价格守住 `lastp1d*0.985` 与 `lastl1d*0.98`，高低点继续抬升或有效越过昨高。量能采用同时间段基线或已经验证的现有量比；不能拿 09:31 的累计量直接除昨日全天量。连续两个间隔不超过 8 秒、带不同时间戳的新快照满足条件才产生 `CONFIRMED` 事件。 | 是，仅通过 `update_candidate()` 准入 RADAR/WATCH；不直接进入 TRADE 或下单。 |
| 09:45、10:30、11:30、收盘及随后 1–2 个交易日 | 按模板观察期限检查是否继续创新高、VWAP 上移和是否保持在 VWAP 上方；结论从 `EARLY_VALID`、`ACCELERATING`、`DELAYED`、`MISSED` 中更新。已入池但未开盘确认的股票也要考核，不能从成功率分母中消失。 | 只更新策略考核和观察优先级，不自动下单。 |
| 失效/冷却 | 跌破底部关键低点、板块联动消失、冲高回落或数据过期，分别记 `INVALIDATED`、`SECTOR_FADE`、`EXHAUSTED`、`STALE`；同日同代码同形态只允许一个首次确认事件，状态变化可更新。 | 只更新观察状态，不重复准入。 |

板块数据缺失时可继续个股观察，但事件标记 `sector_unverified`，首版不做“板块共振”确认。涨停无法成交、高开过度和量能异常只标识“已启动/不追价”，不把这类事后信号混入提前发现成功率。时间基准复用 `ats/session_clock.py` 的市场时区；该模块把 09:15–09:30 整体称为 AUCTION，业务规则仍须按交易所实际 09:15–09:25 集合竞价、09:30 连续竞价区分（[上交所交易时间](https://one.sse.com.cn/onething/gptz/)、[深交所交易时间](https://investor.szse.cn/institute/rules/t20230629_601434.html)）。

**后验命中的明确口径**：`daily_high_break(D)` 指 D 日最高价严格高于前一交易日最高价；若要求“持续新高”，还需收盘站上前高或连续两个有效检查点站上前高。`verified_vwap_rise` 指同一交易日内 09:45→10:30→11:30 等有效检查点的真实 VWAP 连续抬升，或收盘真实 VWAP 高于前一交易日收盘 VWAP，按模板选择口径；跨日比较前必须确认两日成交量单位和 VWAP 来源一致。单次高点刺破或单点 VWAP 抖动只记弱证据。模板可设 `proof_any` 或 `proof_all`：**目标日收盘既无持续新高也无可验证 VWAP 上移，当日立即记 `DAY_MISS`，从次日重点池降权/退出**；若观察期内次日才进展，另记 `DELAYED`，不能追改目标日命中。连续两个检查点无进展可先降级，整个观察期仍无进展则最终记 `MISSED`。这样每日筛选质量当天可检验，后续反弹只作为择时偏差单列。

`ACCELERATING` 必须比“命中”更严格：价格刷新前高、VWAP 持续抬升且价格处于其上方、量能增加但不过热，并有清晰发生时间。所有判断均从原盘前清单的日期向前推进，不能用 D 日收盘后结果反写 09:30 的信号。

## 6. 日文件与事件字段

清单文件头：`schema_version`、`source_asof_trade_date`、`target_trade_date`、`generated_at`、`source_version`、`universe_count`、各启用模板的 `strategy_id/version/config_hash/invalid_count`。候选项：`code/name/sector`、`strategy_id`、`tier`、`score`、`reason_codes`、`feature_values`、`support_price`、`breakout_price`、`invalid_price`。同代码多模板可共享盘中行情缓存，但独立保留模板归属；价格保留原始值与计算口径。

事件至少含 `event_id=target_date+code+strategy_id+first_confirm`、`observed_at`、`phase`、`tier_before/after`、`price`、`sector_name`、`sector_snapshot_ts`、两帧证据、`strategy_id/version/config_hash`。ATS 收到后检查事件日期与目标交易日一致、时间戳不倒退、`event_id` 未处理；同代码同日多个模板只建立一条 ATS 候选记录，附上全部策略来源，避免重复提醒。异常或缺字段时只记诊断日志，不准入。

考核文件按候选逐日记录 `first_observed_at`、各检查点 `high/vwap/vwap_source/price/volume/sector_state`、首次新高时间、首次 VWAP 上移时间、最大有利/不利波动、当日 `DAY_MISS` 与最终 `EARLY_VALID/ACCELERATING/DELAYED/MISSED/INVALIDATED/UNVERIFIABLE` 及原因。`UNVERIFIABLE` 单列计数，不能从分母偷偷删除或当作命中。盘前清单和配置哈希版本化保留；历史特征与考核结果分文件，后验只追加事实，不改盘前预测。

## 7. 实施顺序与验收门槛

1. **字段核验（半天）**：用最近几个已收盘交易日的真实 `df_all` 抽样，确认字段、日期、成交额/量单位、显式 VWAP 的来源、股票板块映射及 `ch_*` 计算时点；产出一张字段映射表。若示例策略的 `ch_*` 在盘前不可用，只禁用该模板或提供经过核验的历史高低点替代特征，不影响其他模板。
2. **配置与离线清单（约 1–2 天）**：实现模板白名单校验、共享特征计算、A/B/C 示例模板、按日衔接与日文件写入；挂在 `self.df_all` 完成更新后的后台任务。固定输入与配置哈希重复运行应得到相同候选。先只输出清单、原因和历史状态，不联 ATS。
3. **次日跟踪与后验考核（约 1–2 天）**：复用现有行情刷新和竞价探测器，只跟踪候选并集；按模板检查新高与真实 VWAP 上移，写检查点和每日命中/未命中报告，先不准入。
4. **ATS 准入适配（约半天）**：只把 TK 已完成双快照确认的事件送现有 `SIGNAL` 接收分支。ATS 验证两帧证据与事件键后，对该专用来源调用 `update_candidate(required_frames=1)`，避免 TK 和 `CandidateCache` 各自重复等待两帧；其他来源仍用原默认值。开关可立即回退到仅记录。接入时验证实际 Pipe/Socket 发送函数与 ATS 线程调度，不在 IPC 工作线程直接操作 Qt 控件。
5. **回放与灰度（至少 5 个交易日）**：先影子运行并核对逐日状态、VWAP 原始数据与失效案例。5 日只用于发现实现问题；策略有效性需跨不同强弱行情积累更多样本，再定阈值。配置迭代仅影响次日以后的候选，不用当天结果改写当天规则。

验收用固定历史快照做因果回放：T 的清单只能读到 T；变更模板只影响未冻结的新交易日；次日竞价只留种子；开盘后两帧才准入；无历史字段/旧板块快照/跨日事件一律不准入；真实 VWAP 缺失时不能用近似均价判命中；同代码同日 ATS 不重复；ATS 关闭或重连不阻断 TK。性能记录全市场盘前共享特征计算耗时、每轮候选扫描耗时与内存增量；目标是盘中成本与候选并集大小成正比，不再每帧全市场跑策略。

每日按 `strategy_id+version` 输出：盘前入池数、跨日继续入池数、层级迁移、当日新高率、真实 VWAP 上移率、`DAY_MISS` 率、候选转确认率、首次提示距突破的提前量、确认后最大有利/不利波动、最终 `MISSED/DELAYED/UNVERIFIABLE` 占比，并按板块、市场强弱及层级拆分。同一股票多个模板分别计策略效果，但总体独立股票数只计一次。用所有盘前候选作筛选质量分母，用已确认候选作信号质量分母；同时与同日全市场/相同板块的基线比较，避免牛市普涨被误记为策略能力。只用当时可交易的信息产生信号，结果统计才可读取后续走势。

每日日报给出“保留/降权/暂停模板”的**建议与证据**，例如连续两日没有新高且 VWAP 不上移的候选比例升高、某层级只在弱板块误报。首版不自动修改策略权重；人工确认后生成新版本供下一交易日使用，保留旧版本和对照结果。这样每日迭代的是有记录的策略假设，而不是只看当日涨幅换阈值。

## 8. 范围外与回退

首版不接入自动下单、不新增重型数据库/服务、不为自定义策略新增 UI、不把现有全部策略改写成状态机，也不要求 ATS 面板常驻才能生成板块信号。关闭新开关即恢复原有筛选与 ATS 行为；本地候选和考核文件仍可供人工复核。若关键日期/字段或 VWAP 口径无法验证，相关模板或考核项停用并显式标注，绝不把缺失证据当作命中。
