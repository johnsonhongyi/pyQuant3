# 次日异动候选池 UI 及 JSON 配置管理功能实施计划

## 规划编制日期：2026-09-25 21:55
## 状态：规划就绪 / 准备实施

### 一、背景与问题回顾

针对“次日异动候选池”（`next_day_anomaly_watch`）的系统审查，当前链路已初步打通盘前宽表冻结、ATS 盘中 TDX 轮询、候选账本、检测中心展示的基本流程，但面临以下两大核心短板：
1. **缺乏专属可视化交互界面**：当前无任何界面可直观查看盘前候选清单、分层依据、盘中检查点序列、两帧确认证据和跨日顺延统计，完全依赖命令行和 JSON 日志查看；
2. **缺乏可视化策略与配置管理能力**：策略调整只能手动编辑 `config/next_day_watch_strategies.json`，存在缺少参数范围校验、配置容易被破坏、修改未版本化回溯等隐患；且底层存在 `required_fields` 缺失仍入池、`proof_any` 未动态兑现等 P1 配置漏洞，以及重复报价误确认等 P0 隐患。

---

### 二、设计原则与架构定位 (KISS, YAGNI, SOLID, DRY)

1. **简单至上 (KISS)**：
   - 界面采用经典紧凑的 4-Tab 架构：`[📋 盘前候选清单]`、`[⚡ 盘中实时后验]`、`[📊 跨日跟踪成效]`、`[🛠️ 策略配置管理]`。
   - 配置管理采用“可视化表单”与“标准 JSON 源码编辑器”双向实时同步模式，直观且灵活。
2. **精益求精 (YAGNI)**：
   - 依托既有文件数据体系（`next_day_anomaly_watch_*.json`、`eval_*.json`、`stats_*.json`），不引入外部数据库或重量级 Web 前端。
   - 仅实现当前明确需要的策略查看、参数调整、版本克隆与规则保存，不搞脱离业务的过度抽象。
3. **职责单一与模块解耦 (SOLID)**：
   - **S (单一职责)**：配置读写与校验抽离为 `NextDayWatchConfigManager`；底层计算逻辑保持在 `next_day_anomaly_watch.py`；UI 仅负责展现与用户交互。
   - **O (开闭原则)**：策略模板与特征字段列表模块化定义，未来新增特征或后验条件无需重写 UI。
   - **D (依赖倒置)**：UI 与计算引擎通过结构化数据协议交互，避免 UI 线程直接执行盘中密集计算或文件锁死。
4. **杜绝重复 (DRY)**：
   - 复用系统既有的 `BaseATSTableWidget` 表格基础设施、深色高对比度样式表以及 `_valid_config` 规则引擎。

### 三、系统架构与 UI 原型设计

#### 1. 承载宿主与双端接入

- **TK 快捷入口 (`instock_MonitorTK.py`)**：

- **独立运维启动器**：
  - 根目录提供 `run_next_day_watch.py`，支持独立进程秒级启动调试。

#### 2. 四大核心功能面板详细规划

##### Tab 1: 📋 盘前候选池总览 (Premarket Manifest Viewer)
- **数据源**：`datacsv/next_day_anomaly_watch_<trade_date>.json`
- **顶部操作栏**：
  - 交易日选择下拉框（默认最新交易日，列出所有历史盘前文件）；
  - 策略筛选（All / channel_stepup 等）；
  - 分层筛选（All / Tier A / Tier B / Tier C）；
  - 快速搜索框（支持股票代码、拼音、名称快速过滤）。
- **指标摘要卡片**：
  - 来源基准日（T 日）、目标交易日（T+1 日）；
  - 候选总数、各层分布（A: N只, B: N只, C: N只）；
  - 全市场扫描宽表样本量、特征缺失剔除数（`invalid_count`）。
- **候选表格视图 (Candidate Table)**：
  - **列定义**：代码、名称、所属板块、策略ID/版本、分层Badge (绿A/橙B/蓝C)、综合分、当前阶段 (Phase)、选入特征 (展开可查看 `lasth1d`, `lastp1d`, `ch_slope_deg`, `ch_pos`, `td_sell`, `lastv1d~3d`)、板块证据、状态。
  - **交互**：
    - 单击行：底部详情卡片联动展示该股盘前入池逻辑与特征值雷达/列表；
    - 双击行：调起该股 ATS SBC 分时走势与多周期 K 线图；
    - 右键菜单：复制股票代码、联动外部看盘（通达信/同花顺/大智慧）、一键加入自选。

##### Tab 2: ⚡ 盘中实时后验与两帧确认 (Intraday Live Verification)
- **数据源**：`datacsv/next_day_anomaly_eval_<trade_date>.json`
- **实时看板状态条**：
  - TDX 轮询状态指示灯（最近轮询耗时 ms、候选监控标的数、已确认数、待投递事件数）。
- **确认事件流与证据链钻取**：
  - **事件列表**：按时间倒序展示盘中触发的 `NEXT_DAY_WATCH_CONFIRM`、`PHASE_CHANGED` 事件；
  - **两帧确认核心证据面板**：
    - 首帧时间戳 vs 确认帧时间戳（间隔必须在 8s 窗口内）；
    - 突破条件：`sustained_high`（突破昨日高点并站稳）或 `verified_vwap_rise`（真实 VWAP 持续抬升）；
    - 当时现价、涨跌幅、偏离度、成交量额真实有效性校验结果；
    - 事件投递状态（是否成功写入 ATS 交易中心/账本，`delivered` 标记与 `event_id`）。
- **标的检查点时序微图 (Checkpoints Sparkline/Timeline)**：
  - 选中某只股票时，右侧展示 09:30 以来的全部检查点序列表格及 High / Trade / VWAP 走势微图。

##### Tab 3: 📊 跨日顺延跟踪与成效看板 (Multi-day Followup & Stats)
- **数据源**：`datacsv/next_day_anomaly_stats_<trade_date>.json` 及历史关联文件
- **策略表现对比表格**：
  - 维度：`strategy_id` + `version` + `target_trade_date`；
  - 核心指标：候选样本数、即日确认数 (EARLY_VALID)、次日顺延命中数 (DELAYED)、目标日未命中 (DAY_MISS)、彻底失效 (MISSED)、证据缺失 (UNVERIFIABLE)、真实 VWAP 不可用 (vwap_unavailable)；
  - 转化率指标：即日确认率、顺延命中率、整体有效率。
- **顺延兑现明细表 (Delayed Winners)**：
  - 列出哪些在目标日 DAY_MISS 但在后续 1~3 天内突破走强的股票，记录实际顺延天数及走强幅度，为策略参数优化提供实证数据支持。

##### Tab 4: 🛠️ 策略与规则 JSON 配置管理 (Strategy & JSON Config Manager)
- **数据源**：`config/next_day_watch_strategies.json`
- **双向联动编辑区**：
  - **左侧：可视表单编辑器 (Form Editor)**
    - **顶层全局配置**：全局启用开关 (`enabled`: True/False 单选切换，带当前生效状态说明)、`vwap_field` 设置；
    - **策略列表与版本树**：支持多策略切换；提供“➕ 克隆为新版本”按钮（自动将 version + 1，防篡改历史版本）；
    - **基础属性**：策略 ID、模板选择 (`channel_stepup`)、是否启用；
    - **股票池范围 (Universe)**：包含/排除代码前缀配置（支持 60, 00, 300, 688 等多选勾选）；
    - **必需字段多选器 (Required Fields)**：可视化 23 个内置基础指标多选框（修复 P1-1 缺失字段校验不生效的治理）；
    - **分层与权重配置 (Tiers & Rank Weights)**：A/B/C 规则映射与权重值；
    - **核心门槛参数 (Thresholds)**：通道斜率 (`slope_min`)、通道位置区间 (`ch_pos_min/max`)、下轨支撑容差 (`support_tolerance`)、TD 卖点上限 (`td_sell_max`)、成交量温和放大参数等，带数值范围约束与 Tooltip 解释；
    - **容量配额 (Capacity)**：A/B/C 各自分配的最大候选数量；
    - **后验观察规则 (Followup)**：观察交易日天数 (`trading_days`)、后验有效判定条件 (`proof_any` 勾选 `daily_high_break`, `verified_vwap_rise`)。
  - **右侧：标准 JSON 源码编辑器 (JSON Source View)**
    - 实时以 JSON 语法高亮展示当前配置；
    - 支持手动编辑 JSON，提供“格式化 JSON”、“验证语法”按钮；
    - 表单与源码双向实时响应更新。
- **配置保存安全控制机制**：
  - **保存前拦截**：执行 `_valid_config()` 严格校验，若有非法类型、非法阈值或格式错误，直接标红并阻止保存；
  - **原子写入**：使用原子安全替换写盘，绝不损坏现有配置文件；
  - **变更生效边界透明提示**：弹窗明确提醒“保存成功！新生成的配置哈希为 `xxx`。依据工程约定，已冻结的当日清单保持不变，修改将于下一交易日 08:30 盘前自动生效”。

### 四、技术方案与关键代码设计

#### 1. 配置管理引擎 (`ats/strategy/next_day_watch_config_manager.py`)
```python
class NextDayWatchConfigManager:
    """次日异动候选池策略配置管理与双向校验引擎 (SSOT)"""
    @classmethod
    def get_config_path(cls) -> str: ...
    @classmethod
    def load_config(cls) -> Tuple[bool, dict, str]: ...
    @classmethod
    def validate_config(cls, config: dict) -> Tuple[bool, str]: ...
    @classmethod
    def save_config(cls, config: dict) -> Tuple[bool, str]: ...
    @classmethod
    def clone_strategy_new_version(cls, config: dict, strategy_id: str) -> Tuple[bool, dict, str]: ...
```

#### 2. 底层逻辑加固与缺陷协同修复
- **P1-1 配置真实兑现**：
  - 在 `next_day_anomaly_watch.py:260` 彻底消除硬编码的 `required` 元组，改用读取策略配置中真实的 `strategy.get("required_fields", [])`；
  - 在后验判定处读取 `strategy.get("followup", {}).get("proof_any", [])` 决定触发条件，彻底杜绝配置失效。
- **P0-1 报价证据加固**：
  - 在 TDX 实时数据适配中，量额无效时严禁填充现价作为 VWAP（改为 None 或 `verified=False`）；
  - 两帧确认增加 `prior_quote_volume < current_quote_volume` 或源行情时间递增校验，消灭相同报价重放误确认。
- **P0-3 冻结门禁加固**：
  - 仅在宽表计算成功且落盘完毕后才将当日记入 `_frozen_targets`，失败时允许在 09:15 前自动重试。

#### 3. 异步后台加载与防界面卡顿
- 读取磁盘历史日期的 `watch_*.json`、`eval_*.json` 与 `stats_*.json` 全部由独立的 `QThread`（如 `NextDayWatchDataLoaderWorker`）在后台执行，主线程仅通过 Qt Signal 接收纯字典数据，彻底消除文件 I/O 阻塞 UI 渲染。

### 六、验收样例与风险控制

1. **配置校验验收**：
   - 输入非法参数（如 `slope_min: -10`, `ch_pos_min: 80, ch_pos_max: 20`），表单与源码编辑器均高亮警告并禁用保存；
   - 移除 `lastp1d` 等关键字段，保存时触发 `schema` 拦截。
2. **候选池展示验收**：
   - 构造包含 30 只股票的模拟 `watch` 和 `eval` 文件，检查 A/B/C 分层徽章、检查点序列渲染、两帧确认证据钻取无任何错漏。
3. **版本隔离与回溯验收**：
   - 点击“克隆为新版本”，策略自动由 v1 升为 v2，保存后不影响已生成的 v1 历史考核文件，满足可追溯性契约。
