# 任务清单：集中交易指挥室列宽持久化与全系统流式增量同步通道 (2026-09-18 21:05)

## 任务背景与核心目标
1. **解决操盘手反馈排版痛点**：指挥室表格（天梯表、持仓表、指令表）列宽被压缩，动能分（55px）与启动时点（65px）文字被截断为“动能.../启动...”，且操盘手手动拖拽调整后重启无法记忆；
2. **构建全系统同步使用全量与增量更新能力 (性能加速)**：
   - 升级服务端 `instock_MonitorTK.py`：支持 `SUBSCRIBE_STREAM` 常态流订阅，打通 26670 (ATS), 26671 (多周期), 26675 (新股次新) 及动态端口，支持冷启动发全量包 (`UPDATE_DF_ALL`)，日常高频推送发增量包 (`UPDATE_DF_DIFF`)；
   - 完善客户端 `ats/network/tk_ipc_subscriber.py`：提供开箱即用的通用订阅器与增量合并逻辑；
   - 升级 `ats/ipc_bridge.py`：老客户端支持 dict 协议与增量合并；
   - 接入新股次新检测工具与集中交易指挥室：直通 26675 端口流式订阅，0ms 本地内存刷新。

## 交付成果清单

### 1. 指挥室列宽自适应、自由拖拽与跨会话自动持久化
- **文件**：`ats/ui/ipo_command_room_dialog.py`
- **改进点**：
  - `tbl_rank`、`tbl_pos`、`tbl_orders` 三大表格表头全部设为 `Interactive` 交互模式；
  - 默认紧凑列宽深度优化：天梯表动能分 62px、启动时点 72px、名称 78px、现价 58px、角色 80px，彻底消灭文字截断与省略号；
  - 接入全系统统一标准的 `setup_persistence` 体系，支持拖拽列宽后 500ms 防抖自动落盘，窗口关闭与下次启动 100% 精确恢复；
  - 提供 `reset_default_widths()`（重置默认列宽）与 `auto_fit_columns()`（一键自适应列宽）接口。

### 2. TK 主进程流式常态订阅与全量/增量智能加速分发
- **文件**：`instock_MonitorTK.py`
- **改进点**：
  - 引入 `_stream_subscribers` 常态推送注册表，统一纳管静态端口（26670, 26671, 26675）与动态握手端口；
  - 监听命名管道 `SUBSCRIBE_STREAM`、`REQ_FULL_SYNC`、`REQ_REGISTER_SUBSCRIBER` 指令；
  - `send_df` 循环智能准备 `payload_daily_full`（全量包）与 `payload_daily`（包含 `UPDATE_DF_DIFF` 增量包）；
  - 冷启动或强刷请求推送全量，日常变动推送增量，极大降低带宽开销与主线程 GIL 锁竞争；
  - 具备动态端口连续失败自愈清理机制，防止僵尸端口轮询。

### 3. 通用流式客户端组件与老客户端增量兼容
- **文件**：`ats/network/tk_ipc_subscriber.py`、`ats/tk_ipc_subscriber.py`、`ats/ipc_bridge.py`
- **改进点**：
  - 新增 `TKIPCSubscriber` 与全局单例 `get_ipo_ipc_subscriber(port=26675)`，集成命名管道握手、心跳维护与 `UPDATE_DF_DIFF` MultiIndex 原地合入算法；
  - `ats/ipc_bridge.py` 内部 `_handle_client` 同步支持 dict 封装的 `UPDATE_DF_ALL` 和 `UPDATE_DF_DIFF`，老终端不再丢失增量数据。

### 4. 新股检测工具直连流式推流与 0ms 刷新
