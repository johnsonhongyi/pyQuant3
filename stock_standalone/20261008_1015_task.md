# 任务清单：修复 ATS 新股次新股自动刷新排序跳变底层逻辑 BUG

**创建时间**：2026-10-08 10:15  
**对应需求**：修复 ats 的新股次新股自动刷新没有根据选择的排序总是在跳变，然后又刷新变回来的底层逻辑 BUG。

---

## 1. 根因剖析与机制确权

### 1.1 现象复现机制
- **图 1 & 图 3 状态**：用户当前选中的排序列为【涨跌%】（升序/降序），前 8 只为重点关注股票（黄色星号），后接普通次新股，均按涨跌%严格排序。
- **图 2 状态**：界面突然跳变！前 8 只是自选股按上市日升序（2026-04-24 ~ 2026-08-18），中间硬生生插入了待上市股票（莫森泰克、通则康威等），后面再接普通次新股（托伦斯、龙森智能等）。
- **跳变死循环**：每当自动刷新（定时器 5 秒轮询或 IPC 500ms 推送）到来时，界面先跳变回图 2，然后又刷新变回图 1/图 3，周而复始。

### 1.2 根因定位
1. **后台准备函数硬编码排序覆盖了用户选择**：
   - 在 `ats/ui/new_stock_panel.py` 的 `_prepare_stock_table`（第 347-360 行）中：
     函数入参虽然接收了 `sort_col` 和 `sort_order`，但内部完全弃之不用！
     反而硬编码使用了 `df_filtered.sort_values(by=["_sort_w", "_sort_date", "pct"], ascending=[True, True, False])`。
     其中 `_sort_w` 把待上市标为 4.0，次新标为 5.0，`_sort_date` 将上市日 `-` 替换为 `1970-01-01` 进行升序排序。
     **这正是图 2 所呈现的完全一致的异常排序！**
2. **前台分片写入与排序开关的时间差暴露了未完成中间态**：
   - 在 `_render_table_impl` 开始时，调用了 `self.table.setSortingEnabled(False)`；
   - 随后通过生成器分片（每次 16 行）将后台准备好的硬编码错误顺序（图 2）写入表格；
   - 在分片写入期间，界面暴露给用户，用户看到的就是图 2；
   - 直到所有分片全部写入完毕（`StopIteration`），才执行 `self.table.setSortingEnabled(True)`，Qt 的 `QTableWidget` 重新对表格排序，表格又跳回图 1/图 3！
3. **用户点击表头时的事件分支缺陷**：
   - 在 `_on_header_sort_changed` 中：
     `if changed and (getattr(self, '_table_painter', None) is not None or getattr(self, '_table_prepare_running', False)):`
     在系统空闲时，该条件为 False，导致用户点击排序列后，根本没有请求后台重新 prepare 数据！
     前台与后台数据状态脱节，下一次自动刷新到来时，后台继续送入错误的旧排序数据。
4. **默认排序列索引偏移**：
   - 表头插入了“竞价信号”列后，第 3 列变成了“竞价信号”，而默认注释期望的“上市日”偏移到了第 4 列。

---

## 2. 详细改造方案

### 2.1 后台多梯队动态排序引擎设计（`_prepare_stock_table` 重构）
- 建立动态表头字段与类型提取函数 `_extract_sort_series(df, header_name, sh_pct)`：
  - 数值型列（现价、涨跌%、涨速%、VWAP、换手%、市值、成交额、DFF系列、Rank、大盘偏离等）：准确转为数值，针对非有效值（无现价、<=0 或 NaN）打上空值标记。
  - 日期型列（上市日、申购日、解禁日）：规范格式，对 `-` / `--` / 空值打上空值标记。
  - 文本型列（代码、名称、状态、竞价信号、共振等）：去除前缀符号，对空值打上标记。
- 构建严格的三层排序机制：
  1. **第 1 键：置顶梯队 `_pin_rank`（永远升序）**：
     - Rank 0：今日大事件（今日上市 `listing_date == today` 或 今日申购 `apply_date == today`）；
     - Rank 1：⭐ 重点关注标的（`code in fav_stocks`）；
     - Rank 999：普通标的。
  2. **第 2 键：空值沉底 `_empty_rank`（永远升序）**：
     - 0：有真实有效数据的行；
     - 1：空值/占位符行。确保在任何梯队内部，空值行永远排在最后，无论升序还是降序！
  3. **第 3 键：用户选定列 `_sort_val`**：
     - 根据用户选定的 `sort_order`（升序/降序）进行排序。
  4. **第 4 键：次级保序键（Tie-breaker）**：
     - 上市日降序 + 证券代码升序，确保排序确定性。
- 排序完成后再计算行级签名 `signature` 与 `row_hashes`，确保能够精准捕捉物理行序变更。

### 2.2 前台交互与渲染状态机加固（`NewStockPanel` 重构）
- **`_on_header_sort_changed`**：
  - 无论当前系统是否空闲，只要排序列或方向发生改变（`changed == True`），立即中止旧 painter 并调用 `self._request_table_prepare()`，驱动后台重新以新顺序准备数据。
- **默认排序列与指示器初始化**：
  - 动态根据表头匹配“上市日”列号作为默认排序列；
  - 在 `_init_ui` 创建表头后立即调用 `setSortIndicator(self.sort_col, self.sort_order)`，保证表头指示器与配置时刻同步。
- **平滑原子渲染**：
  - 由于后台下发的数据本身已经精确对齐用户排序，写入表格的行从第 0 行起就是正确顺序；
  - 消除错误顺序暴露给用户的任何窗口期，彻底根治“跳变又变回来”的视觉抖动。
